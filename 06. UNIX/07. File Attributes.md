#### Viewing file's attributes

###### Using `ls -l`

`-l` flag in `ls` prints the contents in a 'long' format and shows several attributes of every file.

```
sou543$ ls -l
total 24
-rw-r--r--@  1 sou543  staff   175 Jul 27 04:47 Configurations.txt
-rw-rw-r--@  1 sou543  staff  1958 Aug  1 11:49 Links.txt
drwxr-xr-x@  5 sou543  staff   160 Aug 19 16:36 Notes
-rw-r--r--@  1 sou543  staff   118 Aug 13 19:19 Scratchpad.txt
drwxr-xr-x   7 sou543  staff   224 Aug  8 21:54 TestApp
drwxr-xr-x@  5 sou543  staff   160 Aug  8 21:53 TestPlayground.playground
-rw-r--r--@  1 sou543  staff     0 Aug 24 13:08 Unix scratchpad.txt
drwxr-xr-x  56 sou543  staff  1792 Aug 22 17:18 enterprise
drwxr-xr-x   4 sou543  staff   128 Aug  1 11:55 enterprise-test
```

The 'total' in first line indicates the total number of blocks occupied by all these files on the disk.

1st column (`-rw-r--r--@`) - Type and permissions associated with the file. <br>
2nd column (`1`) - Total no. of links associated with the file (might refer to aliases, and symbolic links). <br>
3rd column (`sou543 `) - Owner of the file. Has access to edit the file's contents and permissions. (root user too has that access.) <br>
4th column (`staff `) - Group owner of the file (can there be only one group owner?) <br>
5th column (`175 `) - Number of bytes (based on word count) taken by the file. The actual storage space taken is higher. <br>
6th column (`Jul 27 04:47`) - Last modification time of the file <br>
7th column - Filename

###### Understanding permissions' attribute

In the fist column, <br>
First character indicates file type. For example, `-` indicates an ordinary file. `d` indicates a directory.

Then there are 3 groups of 3 characters, each of these groups are known as `categories`.
```
rwx r-x r-x
```

The 3 slots in a category indicate read (`r`), write (`w`) and execute (`x`) permissions of the file. An absence of any of these permissions is indicated by `-`.

The first category is for the owner. The second category is for the group owner. The third group is for all other users. Note that if the owner is also a member of the group owner, then of course owner access rights takes precedence over group owner access rights.

> The access level on a file for a group are set by the file's owner. not by the group members.

###### Viewing permissions of a specific file

To view the permissions of a single file, give the file name as an argument. If however the argument is a directory, it gives the contents of the directory instead.
```
ls -l There.txt
-rw-r--r--@ 1 sou543  staff  175 Jul 27 04:47 There.txt
```

`-d` flag when used along with `-l` flag on a directory argument prints the directory's attributes instead of its contents.
```
ls -ld enterprise
drwxr-xr-x  56 sou543  staff  1792 Aug 22 17:18 enterprise
```

###### `user-ID (UID)` and `group-ID (GID)`

Every time an admin creates a user account, they need to assign two things to the user. A `user-ID (UID)` and a `group-ID (GID)`. These can be determined by `id` command.

```
sou543$ id
uid=503(sou543) gid=20(staff) groups=20(staff),12(everyone),61(localaccounts),702(com.apple.sharepoint.group.2),98(_lpadmin),100(_lpoperator),701(com.apple.sharepoint.group.1)
```

###### Default permissions of a file

By default following are the default file and directory permissions.
`rw-rw-rw` (Octal 666) for regular files <br>
`rwxrwxrwx` (Octal 777) for directories <br>

The system the subtracts certain permissions (known as `umask` permissions) from above and that is what gets typically applied. The `umask` permission is stored in one of the startup scripts and is by default octal 022. It can also be changed.
```
sou543$ umask
0022
sou543$ umask 000 <---- Would change the umask, though this in paryicular will not make sense
```

`umask` thankfully cannot increase access from what is the system default. However, this can still be done for files individually using `chmod`.


The default attributes of a file are`-rw-r--r--`, which means that only the owner can edit the file. The thing to note though is that even if permissions for it are set as `000` (i.e. `-----------`), the owner would still be able to delete the file as the directory permission may well allow that to happen.

`-R` flag allows to apply the permissions recursively in a directory.

`*` can be used to apply the permissions to all non-hidden files in a directory, `.` whereas includes hidden files as well.
```
sou543$ ls -l
total 16
-rw-r--r--  1 sou543  staff  2 Aug 24 16:16 File1
-rw-r--r--  1 sou543  staff  5 Aug 24 16:16 file2
sou543$ chmod u+x *
sou543$ ls -l
total 16
-rwxr--r--  1 sou543  staff  2 Aug 24 16:16 File1
-rwxr--r--  1 sou543  staff  5 Aug 24 16:16 file2
```


#### Changing permissions

###### Changing file permissions (`chmod`)

`chmod` is the command used to change the permission for any category.

The first argument specifies for what category, how the permissions should be changed. <br>
For example `u+x` means that owner (`u`) should be given (`+`) access to execute (`x`) the file. <br>
`ugo+x` whereas would mean its meant for all 3 categories, owner (`u`), user group (`g`) and other users (`o`). <br>
`-` means access getting removed.

```
sou543$ ls -l There.txt
-rw-r--r--@ 1 sou543  staff  175 Jul 27 04:47 There.txt
38f9d3e3f3f5:Desktop sou543$ chmod u+x There.txt
38f9d3e3f3f5:Desktop sou543$ ls -l There.txt
-rwxr--r--@ 1 sou543  staff  175 Jul 27 04:47 There.txt
```

The command also accepts multiple expressions delimited by commas.
```
chmod a-x;go+r filename
```
This means execute (`x`) permission is beiung removed (`-`) from all (`a`) users, and then read (`r`) permission is being added (`+`) for group (`g`) and other users (`o`).

Absolute permissions allow to set the permissions for each of the 3 categories of users using a very concise syntax.

For any catgeory, there are only 8 possibilities (2*2*2) for any combination of permissions. So they can be represented in a single octal number (i.e. 0 to 7).
```
0 --- No permissions
1 --x Executable only
2 -w- Writeable only
3 -wx Writeable and executable
4 r-- Readable only
5 r-x Readable and executable
6 rw- Readable and writeable
7 rwx Readable, writeable, and executable
```

So one number can be specified for each of the categories.
```
chmod 777 filename
```
The above command would mean that each of the three categories should have read, write and executable permissions.

> Directories have their own permissions and these can override the file permissions of the files it contains. By default any directory that gets created has the permissions of `rwxr-xr-x` which is quite safe as it implies that a different user will not be writeable by group or other users.

######  Changing file's owner and group owner (`chown` and `chgrp`)

`chown` is the command that can change a file's owner, and . It requires superuser (`su`) permissions. <br>
`chgrp` is the command to change a file's group owner.
Both these commands also have a `-R` flag to apply the changes recursively.

Only kernel has write permissions on a directory file. It's not possible to have the write permissions from the shell. If it were possible and the directory file's contents altered then the file system's integrity can be compromised by messing up the contents of a directory file so that it does not match with what is actually supposed to be in the directory.

While it's possible to remove read permission on a directory, doing it will be weird as then even a `ls` on it will not work.

Executing a directory does not make any sense and yet users need to have execute permission on a directory. That is because for any ordinary file to be actually passed through when used as an argument in a command, each of the directories in its path need to have execute access for the user. In fact this is so basic a need, that even something trivial like `cd` will not work without it.
> For above reason, execute permission when spoken in context of directories is also known as search permission.

#### File systems and inodes

###### Hard disk Partitions

Hard disk is actually split into multiple partitions (or slices) with a separate file system for each of them. Each of these file systems have their own `root` directory, however when the system is up only a single file system shows up. That is because one of them is considered to be the main one. At the time of booting, all the other file systems mount (attach) themselves to the mail file system to create the illusion of a single file system.
> But is this the case in macOS as well. I still see the distinct partitions of a hard disk in Finder.

###### `inode` and `inode_number`

Every file has its metadata stored in a separate table known as `inode`. It has everything other than the file's `name` and `inode number`, which are instead stored in the directory that has the file. The `inode number` is like an address of the file's `inode`.
Every file system has a separate portion set aside for storing inodes, which is accessible only to the kernel.

`-i` flag of `ls` command prints the inode number of a file.
```
sou543$ ls -i Configurations.txt
3847263 Configurations.txt
```

When a file is deleted, only then may the system allocate that `inode` number to another file.

###### Hard Links

A file can have multiple filenames. When that happens the file has more than one `link.` As all these links actually point to the same file, they all have the same `inode number`.
> This is not the same as creating a file's alias. The alias is still treated like a different file and gets its own inode number.

`ln` command creates a link between two files.
When used without any flags it creates a `hard link`.

```
sou543$ ls -il
total 8
10838597 -rw-rw-r--@ 1 sou543  staff  1958 Aug  1 11:49 Links

sou543$ ln Links Links1; ls -il
total 16
10838597 -rw-rw-r--@ 3 sou543  staff  1958 Aug  1 11:49 Links
10838597 -rw-rw-r--@ 3 sou543  staff  1958 Aug  1 11:49 Links1
```

A hard link literally uses the same file as the original. Even their `inode number`s are same. In fact, even when a file gets copied the `inode number` of the new file is different, but not here. The only way to differentiate a hard link from a copy is to look at their link count in attributes listing. A hard link increments the count for both the files.

It's possible to pass multiple ordinary files as arguments to the `ln` command, however the last argument should be an already existing directory. The command then creates one hard link each for each of the files and puts all of them in the specified directory.

Hard links provide some protection against accidental deletion of the original file. Even if a file gets deleted, the hard link that was created from it still exists.
> A file is considered completely removed from the system once its link count becomes 0. Keep in mind though that moving just to trash does not decrement a file's link count.

Shell allows the same eventual file to behave differently depending upon which hard link it got invoked from. That is how both `gzip` and `gunzip` files/commands get to behave differently in spite of both them eventually being the same file (i.e. having the same `inode number`).
> A file's name is available to a shell script as `$0` and to a C program as `argv[0]`.

###### Symbolic Links or Soft Links

`-s` flag on `ln` command creates a symbolic link.
```
sou543$ ln -s Links LinksAlias ; ls -il
total 16
10838597 -rw-rw-r--@ 3 sou543  staff  1958 Aug  1 11:49 Links
10839759 lrwxr-xr-x  1 sou543  staff     5 Aug 26 22:23 LinksAlias -> Links
```
These are like aliases. The symbolic link file is a new file (with its own `inode number`) that just points to the actual file. In its attributes listing its name is suffixed with a `->` symbol to the actual file, and its size too is of course lot lesser. If the actual file is deleted, it becomes a dangling symbolic link and is practically useless.

There are some more differences between hard links and soft links. Hard links cannot be created across file systems, but soft links can be. Hard link cannot be created for a directory as a whole, but soft link can be.

###### Time related attributes (`touch command`)

A unix file has 3 timestamps.

Time of last modification (Shown in `ls -l`) <br>
Time of last access (Shown in `ls -lu`) <br>
Time of last inode modification (Shown in `ls -lc`) <br>

Time of last modification - Updated for an ordinary file when the file is updated. Updated for a directory file when a file is created, deleted or removed. Updating the contents of one its files does not change the directory's last modification time.

Time of last access - Updated for an ordinary file when its read, wrote or executed. Updated for a directory file, when it is read (what is that?). Accessing one of its files, or cd-in to it, or creating a file in it does not change its time of last access.

`-t` flag in `ls` also sorts the listing as per the other flag which indicates the time field.

`touch` command can change the time of last modification or time of last access of a file.
```
touch filename ---- Changes both to be current time
touch filename MMDDhhmm ---- Changes both to be specified time
```

`-m` and `-a` flags of `touch` change only the time of last modification or time of last access.

#### `find` command

`find` command recursively examines a set of directories to look for files matching a set of criteria, and then even take actions on them.
```
find ListOfSearchPaths SelectionCriteria Actions
```

```
sou543$ find /Users/sou543/Desktop/enterprise -name "*PayPal*" -path "*C1API*" -print 2>/dev/null
/Users/sou543/Desktop/enterprise/Pods/C1API/C1API/API/PayPal
/Users/sou543/Desktop/enterprise/Pods/C1API/C1API/API/PayPal/PayPalAddTokenGetStatusRequest.swift
/Users/sou543/Desktop/enterprise/Pods/C1API/C1API/API/PayPal/InitiatePayPalLinkingRequest.swift
/Users/sou543/Desktop/enterprise/Pods/C1API/C1API/API/PayPal/PayPalEligibleCardsRequest.swift
```
###### Search Paths

`ListOfSearchPaths` is delimited by whitespace (` `).

`.` causes the search to be done on present working directory. <br>
`/` causes the search to be done on root directory.

###### Selection criteria flags

`-name` flag indicates file name in selection criteria. <br>
`-path` flag indicates file path in selection criteria. <br>
`-type` flag indicates file type, with a value `f` meaning ordinary file. <br>
`-inum` flag indicates inode number. <br>
`-perm` flag matched permissions in octal base. (`-perm 777` for example). <br>
`-mtime -x` flag matches files with modification time newer than x days back. <br>
`-maxdepth n` flag specifies how deep a search should be done. If 1 is specified any sub directories will not be searched.

###### Selection criteria operators

`!` operator in selection criteria negates the condition. <br>
```
find . ! -name "*.c" -print
```

`-o` operator in selection criteria causes the conditions to be OR-ed instead of AND-ed. The conditions should be wrapped in ` \( ` and ` \) ` though.
```
sou543$ find /Users/sou543/Desktop/enterprise  -name "*PayPalActivity*xib" -path "*DigitalCardDetails*xib" -print 2>/dev/null

sou543$ find /Users/sou543/Desktop/enterprise  \( -name "*PayPalActivity*xib" -o -path "*DigitalCardDetails*xib" \) -print 2>/dev/null
/Users/sou543/Desktop/enterprise/Enterprise/MobileUI/Features/PayPal/Shared/PayPalActivityIndicatorView.xib
/Users/sou543/Desktop/enterprise/Enterprise/MobileUI/Features/Digital Card/ViewControllers/SpendToggle/DigitalCardDetailsCardView.xib
/Users/sou543/Desktop/enterprise/Enterprise/MobileUI/Features/Digital Card/ViewControllers/SpendToggle/DigitalCardDetailsToggleViewController.xib
```

`-a` operator in in selection criteria causes the conditions to be AND-ed, it is the default.

###### Actions

`-ls` runs `ls -ilds` on the matches. <br>
```
find . -name "IMG*" -ls
10962850     4016 -rw-------    1 sou543           staff             2054479 Aug 28 10:13 ./IMG_7669.JPG
10962858     4176 -rw-------    1 sou543           staff             2134066 Aug 28 10:13 ./IMG_7668.JPG
```

`-exec cmd` executes the specified command. `{}` causes the found files to be replaced in the command. `\;` means the replacement of files will be done one by one and the command executed every time, whereas `+` means the found files will be inserted all at once and the command run just one time <br>
```
find . -name "IMG*" -maxdepth 1 -exec mv {} Simple\ Filters \;
```
In above example, all the matching files are moved to the directory 'Simple Filters' one by one using the `mv` command.

Specifying `-ok` instead of `exec` causes the command to seek confirmation for each file before performing the action.
```
find . -name "IMG*" -maxdepth 1 -ok mv {} Simple\ Filters \;
"mv ./IMG_7669.JPG Simple Filters"? y
"mv ./IMG_7668.JPG Simple Filters"? y
```

Specifying `2>/dev/null` (in the action part) redirects error messages to `/dev/null` and not be shown in the shell session instead. It should certainly be used when searching root directory, where it is likely that several nested directories will not be accessible and show error messages.
