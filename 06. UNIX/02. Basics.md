> The shell acts both as interpreter and a scripting language. Everything used in a shell script can also be used in an interactive shell, but the reverse is not true.

When you just open the terminal and even if do not do anything after that, a command is already running. This command is the `shell`.

##### Basic operations

`Ctrl C` - Interrupts a running program

`Ctrl D` or `exit` or `logout` - Logs out the current user

```
38f9d3e3f3f5:~ sou543$ exit
logout
Saving session...
...copying shared history...
...saving history...truncating history files...
...completed.
Deleting expired sessions...69 completed.

[Process completed]
```

> What is the difference between `exit` and `logout`? Well, `logout` is an internal command so its exact implementation depends upon the shell used (bash, zsh, etc.)

A command can be typed even when the previous one has not finished running, it is registered but just not shown on shell just yet.

Commands can be combined using `;`
```
ls > list.txt ; cat list.txt
```

Commands that can be connected together using pipe are called filters.
> Check examples for filters

A command can also be run by directly specifying its path (absolute or relative).
```
$ /bin/date
```

#### Basics of commands

###### Anatomy of a command

```
command
argument ~ operand
option ~ flag
```

Certain special arguments are called `option`s. They are prefixed with `-` sign.

```
ls -l ~/Documents/myProject/
```

Here `l` is the flag and `~/Documents/myProject/` is the argument.

> If a command takes a filename as an argument, it is usually the last set of arguments.

Arguments can take the form of an expression (in `grep`), a set of instructions (in `sed`), or a program (in `perl` and `awk`).

###### Location of any command

`type` can be used to find the location of a command. It however searches only the directories specified in `PATH` variable.

```
sou543$ type ls
ls is /bin/ls

sou543$ type type
type is a shell builtin
```

`which` too can do the same thing. Although it's supposedly obsolete now, and shouldn't be used.
```
Desktop (06:25 PM) $ which swiftlint
/usr/local/bin/swiftlint
```
(History of [`which`](https://unix.stackexchange.com/a/85250))

###### Internal and External commands

An internal command is built into the shell, like `cd`. An external command whereas is present in a separate file that can be seen, like `cat` (usually at `/usr/bin`). For internal commands, the shell does not even look at `PATH` before execution.

`help` gives a list of all internal commands in bash. The number of command that are internal commands is rather less.

If a command is listed as both internal and external, shell gives precedence to the internal command.

> Commands are files containing programs, mainly written in C.

#### Getting help or documentation

`help` seems to be working only for internal commands. <br>
`man` works for both internal and external commands. <br>
`apropos` gives a one line description of all the matching commands. <br>
`whatis` too gives a one line description of all the matching commands, but does a narrower search. <br>

###### Navigation in `man`
`q` exit <br>
`f` forward one page <br>
`b` back one page <br>
`/searchstring` (`n` for next matching page) <br>

###### Understanding `man` documentation

If an argument is enclosed in `[]`, its optional.<br>
`...` implies the preceding word (i.e. argument) is repeatable.<br>
`|` indicates only one of the shown options can be shown on either side of the pipe.

```
NAME
     wc -- word, line, character, and byte count

SYNOPSIS
     wc [-clmw] [file ...]
```

So in ☝️example, the flags `c, l, m, w` are optional and the file mentioned in the argument can be specified multiple times.
```
sou543$ wc -lw Scratchpad.txt Scratchpad.txt
       4      21 Scratchpad.txt
       4      21 Scratchpad.txt
       8      42 total
```

###### More tidbits about `man`

`k` flag causes the command to be an equivalent of `apropos` command.<br>
`f` flag causes the command to be an equivalent of `whatis` command.

The `(1)` that typically follows a command in its `man` documentation is basically a number that indicates that is a command available to the user. The number essentially gives the 'section' of the manual the page is from.
```
1      User Commands
2      System Calls
3      C Library Functions
4      Devices and Special Files
5      File Formats and Conventions
6      Games et. al.
7      Miscellanea
8      System Administration tools and Daemons
```

###### `apropos` command

`apropos` searches the entire `whatis` db for the mentioned string and gives the back the qualifying results. This database seems to be a set of short descriptions of all commands. It is hence an efficient way to get a short description of a command.

```
sou543$ man -k uname
guname(1), uname(1)      - print system information
uname(1)                 - Print operating system name
uuname(1)                - list remote UUCP sites
```

###### `whatis` command

Pretty much the same thing as `apropos`, searches the `whatis` database and but seems to be more limited. Probably does not search all sections or search substrings.

```
sou543$ whatis wc
gwc(1), wc(1)            - print newline, word, and byte counts for each file
wc(1)                    - word, line, character, and byte count
```

#### Variables

Variable assignment is done using `variable=value`. Its evaluation though requires `$` prefix to the variable name.
```
k=5
echo $k
```

All shell variables are of string type, and are initialized to null string by default.

To assign a multiword string to a variable, spaces can be escaped but the preferred way is to use quoting.
```
str="Multi word"
```
Both `$` and back-ticks are evaluated by shell even when they are double-quoted.


###### Removing a variable (`unset`), Making it `readonly`

A variable can be removed with `unset`, and protected from reassignment with `readonly`.
```
Desktop (10:14 PM) unset k

Desktop (10:14 PM) $ z=5
Desktop (10:14 PM) $ readonly z
Desktop (10:14 PM) $ z=
-bash: z: readonly variable
```

###### Local and Environment variables

Shell variables are of two types, local and environment. Environment variables are available everywhere, across all shell sessions. Conventionally, environment variables are written in upper case.

`set` displays all variables in current shell. <br>
`env` displays only the environment variables. <br>
> `env` is an external command, but `set` is not.

`export` can convert a local variable to environment variable.

```
sou543$ env
rvm_bin_path=/Users/sou543/.rvm/bin
TERM_PROGRAM=Apple_Terminal
GEM_HOME=/Users/sou543/.rvm/gems/ruby-2.6.3
SHELL=/bin/bash
.. and lot more
```

In fact the shell adds it recursively to all the child shells it spawns after that. Without doing an `export`, the child shells cannot access the variables declared in the parent shell.
```
$ cat script1.sh
echo "x is :" $x
x=20
echo "x is :" $x

Desktop (05:49 PM) $ x=5; export x; ( /Users/sou543/Desktop/script1.sh );
x is : 5
x is : 20
```

#### Meta-characters and Wildcards

The shell first scans the command line for `meta-characters`. These are special characters that do not mean anything to the command but mean something special to the shell.

Some of the meta-characters - `> * | [ ]`

The shell expands the meta-characters to recreate a simplified command line, and then passes on the command line to kernel for execution.

Bourne shells - Bourne shell (`/bin/sh`) and its derivatives - Korn shell (`/bin/ksh`) and Bash (`/bin/bash`). <br>
C shell (`/bin/csh`) and its derivative, Tcsh (`/bin/tcsh`)

`Wild-cards` are the meta-characters that are used to construct a general pattern of matching filenames. They do not mean anything to the command, but only to the shell.

`*` - Any no. of characters including none <br>
`?` - A single character <br>
`[ijk]` - A single character, one of i, j or k <br>
`[!ijk]` - A single character, that is not i, j or k <br>
`[x-z]` - A single characters within the ASCII range of x and z <br>
`[!x-z]` - A single characters that is not within the ASCII range of x and z <br>
`{str1,str2}` - One of 'str1', 'str2', etc. (Does not work in `sh`, but works in `bash`, `csh`, etc.) <br>

> `*` and `?` cannot match a filename beginning with `.`. They also do not match `/` in the filename.

A `character class` comprises a set of characters enclose by rectangular brackets (`[]`).

When a backslash (`\`) is provided before a wild-card to remove (escape) its special meaning, it is called `escaping`.
When a wildcard or even the entire expression is enclosed within quotes (`''` or `""`), it is not interpreted by shell. This is called `quoting`.

In command line, even enter (newline) must be escaped if the command needs to be written across multiple lines.

Single quotes protect all special characters other than single quote itself. <br>
Double quotes protect all special characters other than double quote itself, `$` and back-tick . That is, it lets `$` to be interpreted as a variable prefix and lets back-tick be interpreted as command-substitution characters.

```
Book (02:15 PM) $ echo 'Note ** The current shell is: $SHELL'
Note ** The current shell is: $SHELL

Book (02:17 PM) $ echo "Note ** The current shell is: $SHELL"
Note ** The current shell is: /bin/bash
```

#### Standard input, Standard output, Standard error

The shell associates 3 files with the terminal - two for display, and one for keyboard. Even though a terminal is typically represented by a device name such as 'ttys001', commands do not usually read or write to this file. They perform all terminal related activity to one of these files that the shell makes available to every command.

These special files are actually streams of characters which many commands see as input and output. When a user logs in, the shell makes available 3 files representing 3 streams. Each stream is associated with a default device, and usually the device is the terminal.

`Standard input` - Represents input and is connected to the keyboard. <br>
`Standard output` - Represents output and is connected to the display. <br>
`Standard error` - Represents error message that emanate from the command or shell. This too is connected to the display. <br>

###### Standard input

When `cat` and `wc` are used without arguments, they read the file representing the standard input. This file represents 3 input sources. <br>
Keyboard, the default source <br>
A file using redirection with `<` <br>
Another program using pipeline <br>

For example, if just `wc` is typed then any text that is entered in terminal and the quit using 'Ctrl D', `wc` works on  that.

Here `wc` works on specified file. (of course it was also possible to just write `wc Configurations.txt`)
```
Desktop (02:37 PM) $ wc < Configurations.txt
      11      26     175
```

On seeing `<`, the shell opens the disk file and unplugs the standard input source from its default source (i.e. keyboard) to the specified file, and then `wc` reads from the standard input.
`wc` does not know the source of standard input, it does not even know that shell had to open a file.

When command takes input from multiple sources, `-` can be used to indicate the sequence.
Here, a `cat` is first done from the file and then from the standard input (i.e. keyboard).
```
Desktop (02:42 PM) $ cat Configurations.txt -
```

The third source of standard input is the pipe. And there is a fourth source too, the `HERE document.`

###### Standard output

All commands displaying output on terminal actually write to the standard output file as a stream of characters and not directly to the terminal as such.

There are 3 possible outputs for the standard output. <br>
Terminal, which is the default destination. <br>
File specified using `>` and `>>`. <br>
Input to another program using pipe. <br>
```
wc Configurations.txt > NewFile.txt
```

###### File descriptors

Each of the 3 standard files is represented by a number called `file descriptor`. The kernel maintains a table of file descriptors for every process running in the system.

The first 3 slots are generally allocated to the three standard streams. <br>
0 - Standard input <br>
1 - Standard output <br>
2 - Standard error <br>

###### Standard error

These descriptors are implicitly prefixed to the redirection symbols. For example, `>` and `1>` mean the same thing to the shell. `<` and `0<` are also identical. If a program opens a new file, it usually gets allocated the descriptor 3.

The descriptor is needed when handling standard error stream.
```
Desktop (05:21 PM) $ cat XYZFile > Result
cat: XYZFile: No such file or directory

Desktop (05:22 PM) $ cat XYZFile 2>Result
```

#### Merging streams (standard input and standard error)

Though standard input and standard error  are two separate streams, there is a way to merge the two. This is done with `&` operator.
```
echo "Message" 1>&2
```
> Try this. Page 455.

###### What are `filter` commands?

Not every command uses standard input or standard output. For example, `ls` does not ready from standard input. `lp` does not write to standard output.

Commands that use both standard input and standard output are called `filters`. Some examples are `cat`, `wc`, `gzip`, `cmp`.

#### Two special files - `/dev/null` and `/dev/tty`

`/dev/null` is a special file that simply accepts any stream without growing in size. It simply destroys all output written to it, and its size always remains zero. it is particularly useful when you want to have some destination for the standard output but do not care about what is getting written to it.
> It is actually a pseudo-device because unlike other device files, it is not associated with any physical device.

`/dev/tty` is another special file, and it indicates the terminal. Commands generally do not write to this file, but sometimes it is needed to redirect some statements in shell scripts to this file.
> Is there a physical location of these files that I can view in file system?

Here the output of `who` is directly passed to `wc`. This is an example of pipes. There is no restriction to the number of commands that can be chained together using pipes.
```
Desktop (05:54 PM) $ who | wc -l
       2
```

In the below example, as `tee` has `/dev/tty` as its standard output the results got printed to terminal, as they wouldn't have been and just the count would have been.
```
Desktop (09:21 PM) $ awk '$1 ~ /\*/' File.txt | tee | wc -l
       3

Desktop (09:21 PM) $ awk '$1 ~ /\*/' File.txt | tee /dev/tty | wc -l
8*	shell	28
17*	networking tools	30
21*	advanced shell programming	20
       3
```

> In a pipeline all programs run simultaneously, and the appropriate driver ensures they are kept in sync.

#### Command substitution

There is yet another way in which the standard output of one command can be used by a subsequent command. This is known as `command substitution`. The command to be substituted is enclosed in back-ticks.
```
Desktop (09:37 PM) $ echo "There are `ls -l | wc -l` files in `pwd`"
There are       12 files in /Users/sou543/Desktop
```
> Command substitution is enabled only when back-ticks are used within double quotes (not in single quotes).

However both bash and ksh recommend `$()` to be used instead of the back-ticks for command substitution.
```
Desktop (09:40 PM) $ echo "There are $(ls -l | wc -l) files in $(pwd)"
There are       12 files in /Users/sou543/Desktop
```
