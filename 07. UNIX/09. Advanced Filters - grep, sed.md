#### Wildcards and Regular expressions

Following are the wildcards in UNIX. <br>
`?` - Any single character except a single dot <br>
`*` - Zero or more characters, except a leading dot <br>
`[]` - Class of characters

POSIX identifies regular expressions as belonging to two categories - Basic and Extended.

Some regular expression meta-characters like `+` and `?` are actually a part of ERE, so `-E` flag must be used when using a regex containing those meta-characters.

> Regular expressions are interpreted by the command and not the shell. Hence wrapping them in `""` in `grep`, etc. ensures that Shell does not start interpreting them in their own way.

Some commands (like `grep`) use regular expressions, not wildcards. Hence `grep -x ".*[12].*" Sample.txt` will work for a line like `Word1new`, whereas `grep -x "*[12]*" Sample.txt` will not. <br>

Whereas some other commands (like `find`) use wildcards and not regular expressions. Hence `find . -maxdepth 1 -name "*txt" -print` works but `find . -maxdepth 1 -name ".*txt" -print` does not.

#### `grep` command

`grep` searches for patterns in one or more files, or the standard input if no filenames are provided.
```
grep options pattern filenames
```

```
$ grep -n "file" Sample.txt
1:a new file has been created
2:second line in a new file
```

It can output its comment to standard output with `>`.
```
grep -n "file" Sample.txt > Results.txt
```

`grep` supports basic regular expressions (BRE) by default and extended regular expressions (ERE) when `-E` flag is used. `grep` in fact stands for Global Regular Expression Print.

`-n` gives the line number as well in the output. <br>
`-x` looks for the pattern to match the entire line. <br>
`-v` matches all the lines not matching the pattern. <br>
`-i` ignores the case while doing the search. <br>
`-f` allows to pick up the pattern itself from a different file (one per line). <br>
`-h` hides the filenames from the result when searching in multiple files <br>
`-o` returns just the part matching the pattern and not the entire line. <br>
`-c` just returns the total number of lines matching the pattern. <br>
`-l` just returns all the files among the specified input files which have any line matching the pattern. <br>
`-E` uses extended regular expressions. <br>
`-e` allows to specify multiple conditions which are OR-ed together. <br>
`-A NUM` prints NUM number of lines after matching lines. <br>`-h` strips out filenames from the output <br>`-l` returns only filenames in the output <br>

```
Desktop (03:16 PM) $ grep -e "file" -e "21" Sample.txt
a new file has been created
second line in a new file
kdsc 21 ldsk
```

> `grep` it seems cannot be used for multi-line regex search. For doing that things such as `prcgrep` need to be installed (`brew install prcgrep`) and used.

`-r` searches recursively across all the files in the current directory. <br>`--include="pattern"` searches only across file names matching the mentioned pattern. <br>

```
grep -r --include="*.yml" -E ".*SOME_TEXT.*"
```

#### `sed` command

`sed` performs non-interactive operations on a data stream (hence its name, i.e. 'stream editor').

```
sed options 'address action' file(s)
```
'Address' can be line numbers or a regex pattern (enclosed in a delimiter) in a line. The latter is also known as context addressing.

###### Actions

`q` denotes the quit action. This prints the first 3 lines and then quits (in effect, being same as `head -n 3`).
```
sed '3q' Sample.txt
```
`p` denotes print action. If `p` is used for printing, `-n` flag must be used as well or else weird things happen.
```
sed -n '3,5p' Sample.txt  // This prints line numbers 3 to 5
sed -n '$p' Sample.txt    // This prints last line (denoted by `$`)
```

This prints line from both groups in a single command. This is a different way of giving commands (where the command itself needs to span multiple lines).
```
Desktop (10:49 PM) $ sed -n '3,5p
> 7,8p' Sample.txt
```

`w` denotes write action. Selections get written to a new file.
```
Desktop (11:11 PM) $ sed '3w output.txt' Sample.txt
```

`i` denotes insertion (`i`). Here, in line no. 1 insertion is made of text 'one' (the `\` after that is necessary), and the output is written in a new temporary file (`$$`).
```
Desktop (11:15 PM) $ sed '1i\
> one\
> ' Sample.txt >> $$
```

`s` denotes substitution action (explained more later)

There are some more editing actions available in `sed`. Many of these commands are same as what `vim` has - `i` (insert), `a` (append), `c` (change), `d` (delete).

`!` sign negates the specified action.
```
sed -n '3,5!p' Sample.txt  // This prints all lines other than lines 3 to 5
```

Multiple actions can be specified in successive lines. It needs to be kept in mind that being something that works on data streams, `sed` does the 1st action on entire file, then the 2nd action on the entire file, and so on.

> `sed` has something called 'remembered pattern' (`//`) as well, study that

Repeated pattern (`&`) - `&` denotes a source pattern being reused in substitution.
> Interval regular expression (IRE) and Tagged regular expression (TRE). Understand these. Are these basic regex things too?


###### Options

`-e` - Can enter multiple instructions, each preceded by `-e`. <br>
```
sed -e '2,3w Result.txt' -e '6,7w Result.txt' Sample.txt
```

`-f` - Take actions from another file. <br>

###### Substitution with `s` action

`sed` command (with `s` action) is commonly used to search and replace substrings with other strings, in a given string.

Here is the usual syntax for searching and replacing strings.
```
sed -i '' -E 's#Substring#ReplacementString#g' InputFile
```

`-i` implies the file should be edited in-place instead of outputting the result to the console.

`''` ensures that the existing file does not get backed up in a new file before the contents are modified.

`-E` implies a (extended?) regex search and replacement should be done.

`s` implies substitution

`g` implies a global search and replace (instead that of just the first occurrence)

Even though the above example uses `#` as the delimited. any character can actually be used as the delimiter. In fact, typically `/` is used as the delimiter.

###### Misc.

One big limitation with `sed` is that it does not scan multiple lines and hence cannot be made to work for multi line regex out of box.

Another limitation is that it sometimes does not recognize tabs (`\t`) in a regex pattern (I did verify this to be true). [link](https://stackoverflow.com/questions/2610115/why-is-sed-not-recognizing-t-as-a-tab)

Also things like `\d` and `\w` which are pretty common regular expression patterns have a different meaning in `sed` and cannot be used like a regex pattern. [link](https://stackoverflow.com/a/14671365)

To use variables in the pattern itself, quotes need to be used ([link](https://askubuntu.com/a/76842)).<br>
Here is an example. Single-quote is better suited as a delimiter is the string itself has `/`, etc.
```
sed -i '' -E 's#'"$searchedString"'#'"$replacementString"'#g' "$fileBeingScanned"
```

Reversing the order of all the lines in a file with `sed`. This works, but not clear about the internals. It uses new options like `G` and refers to things like `pattern space` and `hold space`. ([link1](https://stackoverflow.com/a/29435696/1135417), [link2](https://www.baeldung.com/linux/reverse-order-of-file-lines))
```
sed '1!G;h;$!d' File.text
```
