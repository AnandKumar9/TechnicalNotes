#### Evaluating expressions (`expr`)

`expr` evaluates expressions.

It can perform computations. The operator (`+`, etc.) must have whitespace on both of its sides
```
Desktop (10:53 PM) $ x=2; y=1
Desktop (10:53 PM) $ expr $x + $y
3
Desktop (10:53 PM) $ expr $x+$y
2+1
```

However for doing multiplication, the `*` must be preceded by a ` `.
```
answer=3
x=6
echo `expr $answer \* $x`
```

The regex `.*` is used to calculate the no. of characters in a string.
```
Desktop (11:08 PM) $ expr "SomeName" : '.*'
8
```

Using `expr` To update variables.
```
x=6
x=`expr $x \* 2`

y=3
y=`expr $y + 8`
```

#### Manipulating positional parameters

###### Extraction with `set`

`set` assigns to its positional parameters the output of the input passed to it.
```
Desktop (02:54 PM) $ set `date`
Desktop (02:57 PM) $ echo $1
Sat
```

```
Desktop (02:57 PM) $ set 20 50
Desktop (02:58 PM) $ echo $2
50
```

Sometimes the output starts with `-` or has `null`, in which case `set` may get confused and treat them as options. Using `--` causes `set` to not consider these things as options for it to interpret.
```
Desktop (04:21 PM) $ set `ls -l Scratchpad.txt`
-bash: set: -w: invalid option
set: usage: set [--abefhkmnptuvxBCHP] [-o option] [arg ...]

Desktop (04:22 PM) $ set -- `ls -l Scratchpad.txt`
Desktop (04:22 PM) $ echo $1
-rw-r--r--@
```

###### Shifting the order during extraction with `shift`

`shift` shifts the positional parameters by 1. Previous `$2` becomes new `$1`, and so on.
```
Desktop (03:02 PM) $ grep "USA" Sample.txt
WashingtonDC USA NorthAmerica WashingtonDC
NewYorkCity USA NorthAmerica WashingtonDC
Desktop (03:03 PM) $ set `grep "USA" Sample.txt` ; echo $1
WashingtonDC

Desktop (03:03 PM) $ shift
Desktop (03:03 PM) $ echo $1
USA
```

#### Debugging scripts

`-x` flag of `set` is used for debugging as if included, it prints every line of code before executing it.

```
set -x
for file in *.txt; do
	echo "$file"
done
```

```
Notes (09:30 PM) $ /Users/sou543/Desktop/script.sh
++ for file in '*.txt'
++ echo 'Unix commands.txt'
Unix commands.txt
++ for file in '*.txt'
++ echo 'Unix scratchpad.txt'
Unix scratchpad.txt
```

It can be turned off with `set +x`.

#### HERE DOCUMENT (`<<`)

`<<` (also knowns as `HERE DOCUMENT`) is used to indicate that the data for a command is provided in the same line. This apparently can also be used in scripts.
```
Desktop (04:29 PM) $ wc -w << MARK
> One word
> Two Line
> MARK
       4
```
Any word (`MARK` here) can be used as the indicator for beginning and end.

#### `trap` command

Its like a notification observer (and is typically used like teardown/dealloc function in other languages). It gets called whenever the script receives a signal. The script first tells what signals it wants to listen to, and then specifies the code that needs to be run when these signals are received.

```
trap 'command_list' signal_list
```

The signal list can contain integer values or names (without the 'SIG' prefix) of one or more signals (the same thing as what is used with 'KILL' command).

Here, all the files expanded from `$$*` are removed, a message shown, and script stopped whenever the 3 specified signals are sent to the shell process running the script.
```
trap 'rm $$* ;  echo "Program interrupted" ;  exit' HUP INT TERM
```

> When the interrupt key (i.e. Ctrl + C) is pressed, it sends the signL SIGINT (2).

The signals can also be ignored by not specifying any command.
```
trap '' HUP
```
