#### Shell and Sub-shell

Anytime shell executes a shell script, it first creates a sub-shell and then that sub-shell executes the commands written in that script.

So this automatically creates a new sub-shell for the script to run. Note though that the script must have executable permission for this to run.
```
$ /Users/sou543/Desktop/script.sh   
```

Its however also possible to explicitly ask the shell to create a sub-shell for executing the script. This is done by explicitly typing the command for the shell to used (`sh`, `ksh`, etc.). This way the script even need not be an executable.
```
$ ls -l script.sh
-rw-r--r--  1 sou543  staff  14 Sep 21 22:32 script.sh

$ sh script.sh
$ sh < script.sh    # This works too, likely the same thing as previous command. < is just saying the specified file is the standard input for the sh command.
```

###### `()` and `{}`

Statements enclosed within `()` are executed in sub-shell. Statements enclosed within `{}` are executed in the current shell only.
```
Desktop (05:10 PM) $ (script1.sh ; script2.sh ) > result.txt
```

> There are some applications that require a set of commands to be run without spawning a child shell, that is when `{}` comes handy.

Here since the `cd` and subsequent `pwd` is run in a new sub-shell, `pwd` after that prints the actual working directory. So it's as if `()` created a new separate shell and run all the enclosed commands in that shell.
```
Desktop (05:10 PM) $ pwd
/Users/sou543/Desktop

Desktop (05:18 PM) $ (cd Notes/ ; pwd)
/Users/sou543/Desktop/Notes
Saving session...
...copying shared history...
...saving history...truncating history files...
...completed.
Deleting expired sessions...203 completed.

Desktop (05:18 PM) $ pwd
/Users/sou543/Desktop
```

###### Dot command (`.`)

The dot command `.` too can be used to execute a shell script without creating a sub-shell. This is also how any variables created in `.profile` become available in all shells. #### Arrays, Functions, etc.

###### Integer computation with `let` (Korn and Bash)

Korn and Bash come with an integer handling facility that makes `expr` quite redundant. And it's also quite fast.
```
Desktop (06:12 PM) $ let a=2+2
Desktop (06:12 PM) $ echo $a
4
Desktop (06:12 PM) $ let b="2 + 2" # " is needed if whitespace is used
Desktop (06:12 PM) $ echo $b
4
```

With `let`, using `$` is not mandatory while doing assignments.
```
let c=a+$b
```

`(( ))` can replace `let` itself. Note that just using `()` will not work.
```
Desktop (06:38 PM) $ x=5;y=2
Desktop (06:39 PM) $ let z=x+y

Desktop (06:39 PM) $ let n=$(x+y)
-bash: x+y: command not found
```

> POSIX in fact recommends the usr of `(( ))` over `let`.

###### Arrays (Korn and Bash)

One dimensional arrays are supported and they begin with index '0'.

```
$ arr[2]="Hi" - Declare array, and assign value to one of the indexes

$ arr1=(2 4 5) - Fully initialize array

$ echo ${arr1[1]} - Get an element, see how it needs to be done using `${}`

$ echo ${arr1[@]} - Get all elements
$ echo ${arr1[*]} - Too too gets all elements
$ echo ${#arr1[@]} - Get length of array
```

An array need not have elements in all indexes.
```
$ arr[2]="Hi"
$ echo ${#arr[@]}
1
```

###### String handling (Bash)

Get length of a string - `${#varName}`
```
Desktop (08:38 PM) $ name="Anand"
Desktop (08:40 PM) $ echo ${#name}
5
```

There are two special ways for extracting substrings. <br>
`${var#pat}` Shortest substring that matches 'pat' at the beginning of '$var'<br>
`${var##pat}` Longest substring that matches 'pat' at the beginning of '$var'<br>
`${var%pat}` Shortest substring that matches 'pat' at the end of '$var'<br>
`${var%%pat}` Longest substring that matches 'pat' at the end of '$var'<br>
```
Desktop (08:53 PM) $ var3="apple.com"
Desktop (08:55 PM) $ echo ${var3#apple}
.com

Desktop (08:52 PM) $ var1="SomeRandomName.txt"
Desktop (08:52 PM) $ echo ${var1%.txt}
SomeRandomName

Desktop (08:52 PM) $ var2="com.apple.www"
Desktop (08:53 PM) $ echo ${var2%%.*}
com
```

###### Functions

Defining a function
```
funcname() {
  Statements
  return value    # Returning is optional
}
```

Calling a function. `()` is not needed.
```
funcname
```

Shell functions take command line arguments just like shell scripts (`$1`, `$2`, `$#`, etc.), however it seems that these arguments must be specifically passed to the function.
```
removeSpacesFromFilenames() {
  .. Access passed variables using $1, $2, etc.
}

removeSpacesFromFilenames "$1"  # Actually pass the command line arguments
```

They are typically even placed in separate files known as 'library' files so that the other applications cans also use them.

#### Conditional Parameter Substitution

```
${Var:OptionString}
```

`+` option returns 'string' only if 'var' is defined and is assigned a non-null string.

`-` option returns 'string' only if 'var' is undefined or if it is a null string.

`=` option even assigns 'string' to 'var' if 'var' is undefined or if it is a null string.

`?` option evaluates 'var' if 'var' is assigned and non-null. Else, it prints 'string' and then automatically stops the script.

#### Evaluating twice with `eval`

If `eval` is prefixed, then the command line is evaluated twice. In first pass, some of the evaluation is held off and only done in second pass instead.

```
$ prompt1="ID:" ; prompt2="Age:";x=1
$ echo $prompt$x
1                 # THIS IS WHAT WILL HAPPEN WITHOUT eval

$ eval echo \$prompt$x
ID:               # THIS IS WHAT eval DOES
```

`$ eval echo \$prompt$x` - Here first `$` is not evaluated (may be because it's prefixed with `\`?)
