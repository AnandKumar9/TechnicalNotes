#### Viewing files

###### `cat`: Viewing and creating files

> `cat` can be used to view as well as create files.

`cat` shows the contents of specified files one after another. However, it does not even have a header to demarcate the files. After all it 'concatenates' the specified files.
> `cat` is well suited for showing the contents of small files, not for big files.

`-n` flag prints the line numbers.
```
sou543$ cat -n Configurations.txt
     1	Xcode and command line tools
     2
     3	Add proxify scripts to bash_profile
     4	Add eval "$(rbenv init -)" to bash_profile
     5	Install homebrew
     6	Install bundler
     7	Install RVM
     8
     9	Atom
    10	Charles
    11	Reveal

```
`-b` flag prints the line numbers of only non-blank lines.

`-v` flag prints non printable characters as well using some notation. This is especially useful for executable files, which otherwise when printed using simple cat without any option would just print junk characters.

`cat > Filename` creates a file named 'filename' and the content then entered in the shell session editor gets saved over there. The editor can be quit and the content saved using `Ctl D`.

###### Pager commands like `more`

`more` is a very useful command for viewing large files in a shell session. It's like `man` and shows one page at a time. <br> <br>
Navigation is done using these keys - <br>
`f` or space bar for moving forward <br>
`b` for moving back <br>
`q` for quitting <br>
Numbers can be prefixed to `f` or `b` (like in vim) to move that many specified pages straight away <br>
Search too can be done by prefixing `/` to the search string (just as in `man`).

> Its pretty common to pipe the long result of another command (like `ls` on a directory with many files) to `more` so that it can be viewed properly. `ls | more`
> Such commands like `more` are called pager commands. `more` is the default pager in bash, whereas `less` is the default pager command in linux.


#### Moving, copying files, etc.

###### Deleting files with `rm`

<br>

`rm` command deletes specified files. It does not however delete directories.

```
sou543$ rm Test.txt Test1.txt

sou543$ rm Test2
rm: Test2: is a directory
```

> It can delete all the files in a directory though if just `*` is specified as an argument.

`-f` flag causes a force deletion, i.e. permission is not sought from user before deleting a write-protected file.

`-r` flag applies the `d` flag recursively. So it can be used to delete an entire folder recursively. `-R` too is the same thing.

`-i` flag causes the deletion to be interactive, i.e. a confirmation is asked before deleting each file.

`-d` flag attempts to remove folders as well


###### Copying files with `cp`

```
cp file1 file2 destination
```

`-i` flag does an interactive copy where a confirmation is seeked before copying every file.

`-R` flag does a recursive copy where the entire structure of includes files and sub-directories get copied.

###### Moving or renaming files with `mv`

`mv` command can rename a file (or directory) or even move a file to another directory. By default, it does not seek confirmation before overwriting an existing file.


Here if 'arg2' is already an existing folder, arg1 gets moved to it. If 'arg2' is not already an existing folder, then 'arg1' gets renamed to 'arg2'.
```
mv arg1 arg2
```

Here, files 'arg1' 'arg2' 'arg3' get moved to 'arg4' folder.
```
mv arg1 arg2 arg3 arg4
```

#### Print operations

###### Add job to printer

`lp` command puts the specified file in print queue of the system's default printer.
```
lp File1.txt
```

`-dPrinterName` flag allows the print to be submitted to the printer named 'PrinterName'.

`-t"TitleName"` prints the `TitleName` in the first page.

`-n5` flag prints 5 copies (of course any number can be specifed there).

> Output of one command can be piped to `lp` and printed. For example, `ls | lp`.

> Most UNIX printers are of something called `postscript` variety. What it means is that it can properly print files formatted in PostScript (what is that?). Any GUI printer application or program actually first converts the data to PostScript which then becomes the input to printer. `lp` command does not do this conversion.

###### View print queue

`lpstat` command gives the print queue.
```
sou543$ lpstat
SecurePrint-Cloud-21    sou543            2048   Wed Aug 21 23:35:58 2019
SecurePrint-Cloud-22    sou543           32768   Wed Aug 21 23:36:17 2019
```

###### Cancel print job

`cancel printID` can be used to cancel the specified print job.
`cancel printerName` cancels the current job (i.e. the earliest job yet to start printing) on the specified printer. Once a job is being printed, it cannot be cancelled.

#### Inspecting file types

`file` command can be used to identify basic file type, i.e. ordinary file, directory or device file. For ordinary file, it can even give further classifications. It's not very precise or exhaustive but is usually sufficiently indicative.
```
sou543$ file Configurations.txt
Configurations.txt: ASCII text
```

`file *` gets the type for all the files in the working directory.
```
Configurations.txt:           ASCII text
DigitalCardFlowManager.swift: C++ source text, UTF-8 Unicode text
Links.txt:                    UTF-8 Unicode text
Notes:                        directory
Scratchpad.txt:               ASCII text
TestApp:                      directory
TestPlayground.playground:    directory
Unix scratchpad.txt:          ASCII text, with very long lines
enterprise:                   directory
enterprise-test:              directory
```
> A file has something called `magic number` embedded in its first few bytes, every file type has a unique magic number. That is what is used by `file` to identify the file's type.

###### Length with `wc` command

`wc` gives the number of lines, words and characters in a file. It has arguments `-l`, `-w`, and `-c` which can give just the number of lines, words, or characters. Multiple arguments can be provided as well.

```
sou543$ wc Configurations.txt
      11      26     175 Configurations.txt
sou543$ wc -l Configurations.txt Links.txt
      11 Configurations.txt
      54 Links.txt
      65 total
```

> `wc -c` hence also serves as a rudimentary way to determine how big a file is.

#### Comparing files

###### Checking if files are identical with `cmp`

`cmp` does elementary comparison of two files and gives the line no. of the first mismatch. If they are identical it does not echo anything back.
```
sou543$ cmp Configurations.txt Configurations1.txt
Configurations.txt Configurations1.txt differ: char 109, line 4
```

###### Checking how much is common with `comm`

`comm` finds what is common between two files. The first column shows the lines unique to the first file, the second column shows the lines unique to the second file, and the third column shows the lines common to both files.
```
sou543$ comm Configurations.txt Configurations1.txt
		Xcode and command line tools

		Add proxify scripts to bash_profile
Add eval "$(rbenv init -)" to bash_profile
	Add eval "$(rbenv init -)" to bash_profile hi
		Install homebrew
Install bundler
Install RVM

Atom
Charles
Reveal
	now Install bundler
	Install RVM

	Atom
	Charles
	Reveal
```

> Be careful with `comm`. While it does give the correct output, it can get confusing as long lines do not automatically cause output to expand in width. Not sure, but it also seems a little tricky on how it compares newlines.

To drop a particular column from the output, that column no. can be used as an option. For example here 2nd and 3rd columns are dropped from the output.
```
sou543$ comm -23 Configurations.txt Configurations1.txt
Add eval "$(rbenv init -)" to bash_profile
Install bundler
Install RVM

Atom
Charles
Reveal
```

###### Finding how to make files identical with `diff`

`diff` command tells which lines need in first file should be changed for two files to become identical.

```
4c4
< Add eval "$(rbenv init -)" to bash_profile
---
> Add eval "$(rbenv init -)" to bash_profile hi
6c6
< Install bundler
---
> now Install bundler
```

It goes something like this. '4c4' means line 4 should be changed as shown. Line 6 should be changed as shown. Similarly there can be codes such as '0A1,2' which would mean at line 0 of fist file, lines 1 and 2 of second file should be appended. Or '4d5' which means that line 4 of first file should be deleted.

#### Compressing and Archiving files

#### `gzip` and `gunzip`: Compression and decompression

`gzip` and `gunzip` do basic compression and decompression.

```
gzip libc.html

wc -c libc.html
6791483 libc.html

wc -c libc.html.gz
1017791 libc.html.gz
```

`-l` flag gives the stat during compression/decompression.
```
gzip -l libc.html.gz
compressed uncompressed  ratio uncompressed_name
1017791      6791483     85.0% libc.html
```

`-d` flag on `gzip` is another way to do decompression (other than using `gunzip`)
```
gzip -d libc.html.gz
gunzip
```

`-r` flag is used for doing recursive compression and `-dr` flag is used for recursive decompression. The compression argument must be a directory.

`-c` flag on `gunzip` can b used to view the contents of a compressed file without having to decompress it. The commands `zcat` or `zmore` can be used for the same thing.

#### `tar`: Archiving and Unarchiving

Archive is a collection of files shown as one file which can then be ftp-ed, mailed, etc. as a single attachment.

`tar` creates an archive.

```
sou543$ tar -cvf Sample.tar libc.html IMG_7630.PNG DigitalCardFlowManager\ flow\ diagram.png
a libc.html
a IMG_7630.PNG
a DigitalCardFlowManager flow diagram.png

sou543$ wc -c Sample.tar libc.html IMG_7630.PNG DigitalCardFlowManager\ flow\ diagram.png
 1023488 Sample.tar
  511488 libc.html
  200103 IMG_7630.PNG
  306620 DigitalCardFlowManager flow diagram.png
 2041699 total
```

> Using the extension `tar` for a tar file is just a convention, and not a requirement.

The command can even work recursively on directories.
The tar file can then also be compressed using gzip, etc. to reduce it size.

`-x` flag can be used to extract files from an archive. Again `-f` flag is necessary to provide the name of the archive that needs to be extracted from.
```
sou543$ tar -xf Sample.tar
```

It's also possible to extract selected files from an archive by specifying the selected files to be extracted as succeeding arguments.
```
sou543$ tar -xvf Sample.tar libc.html
x libc.html
```

Sometimes though it can throw errors such as 'Not found in archive', so its failure should not conclusively mean that the file really does not exist in the archive.

`-tvf` flags used together show the contents of an archive without extracting them.
```
sou543$ tar -tvf Sample.tar
-rw-------  0 sou543 staff  822784 Aug 24 07:21 IMG_7630.PNG
-rw-r--r--  0 sou543 staff    1937 Aug 23 17:37 ./._DigitalCardFlowManagerflowdiagram.png
-rw-r--r--  0 sou543 staff  306620 Aug 23 17:37 DigitalCardFlowManager flow diagram.png
-rw-r--r--  0 sou543 staff  511488 Aug 24 07:03 libc.html
```

###### `zip` and `unzip`: Compression and Archival together

`zip` does compression and archival together. Hence even if it does not compress as much as another command `bzip2`, it provides convenience.

```
zip Sample.zip IMG_7630.PNG DigitalCardFlowManager\ flow\ diagram.png
  adding: IMG_7630.PNG (deflated 21%)
  adding: DigitalCardFlowManager flow diagram.png (deflated 22%)
```

One great thing about `zip` is that it does not overwrite any existing zip file with same name, but instead updates (if same things are being decompressed) or appends (if something new is being decompressed) to it as needed.
```
zip Sample.zip libc.html
  adding: libc.html (deflated 20%)
```

`unzip` does the decompression. If any if the existing files already exist, it does an interactive restoration where the user is asked if the existing file should be overwritten or not.

```
sou543$ unzip Sample.zip
Archive:  Sample.zip
  inflating: IMG_7630.PNG            
  inflating: DigitalCardFlowManager flow diagram.png  
  inflating: libc.html      
```

`-v` flag shows the contents of the zip file without actually doing the decompression. It also shows the compressed and uncompressed size of each file in the archive.

```
sou543$ unzip -v Sample.zip
Archive:  Sample.zip
```
