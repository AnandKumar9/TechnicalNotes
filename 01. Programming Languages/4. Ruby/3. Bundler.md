###### The rationale behind Bundler

To put it very simply, the obvious benefit with `bundler` is that you do not install every gem yourself. You instead specify all the gems you need in a single file (called `gemfile`) and then run just one command (`bundle install`) which installs all the required gems for you. <br>

It also gives you the other option that there can be multiple versions of the same gem installed in the system and different projects can use different versions.

To be very precise though, such behaviors already existed in other mechanisms. The real benefit of using Bundler is that it does dependency resolution before runtime (unlike `RubyGems`, which did it at runtime).

> Without bundler, gems can be installed using `gem install gemName` command (i.e. using `RubyGems`).

Given that `rvm` is also being used, <br>
`bundle install` installs the gems in current gemset. <br>

`bundle info gemName` says where is the specified gem located for current gemset (of the Terminal session). And if its not there, I think it looks for that gem in system `Ruby.framework` folder.

> A sample gem location when checked using `bundle info` - <br>
`/Users/sou543/.rvm/gems/ruby-2.4.1/gems/mini_portile2-2.1.0` <br>
So here clearly the gemset being used is 2.4.1 default.

###### bundle install and bundle update

`bundle install` to put it very simple conservatively installs the gems in gemfile. To be more precise, if the `gemfile.lock` does not already exist the bundler does dependency resolution and on a successful resolution, installs the gems and generates a `gemfile.lock` which keeps a record of all the installed gems, their versions, etc. If however a `gemfile.lock` already exists and the gems mentioned in it already satify the `gemfile` it does not install any new version of the gem.

`bundle update` whereas updates every gem in gemfile to the latest possible version. It resolves dependencies from scratch, ignoring the Gemfile.lock. In other words, it is a way to update a gem without modifying the gemfile (if the gemfile permits it that is).

`bundle update GemName` is better as it updates the gem and its dependencies to the latest version allowed by `gemfile` without modifying any other dependencies.

> Its usually safer to do a `bundle install` than a blanket `bundle update`.

When you update a gem, bundler will not update a dependency of that gem if another gem still depends on it.
`bundle install` command always does a conservative update, refusing to update gems (or their dependencies) that you have not explicitly changed in the gemfile.

`gemfile.lock` is like a manifest file which keeps a record of all the gems that got installed. It also knows which version of bundler was used the last time you installed its gems.

> With source control, always check-in both `gemfile` and `gemfile.lock`.

###### bundle exec

`bundle exec something` runs the 'something' script in the context of the current bundle.

So `bundle exec pod install` will do the pod installation using the cocoapods version specified in the current directory's gemfile.
Whereas `pod install` will do the pod installation using the cocoapods version in the system Ruby directory.

I think every system should still do `bundle install` as a one-time activity. And after that they need to do it only if they are changing anything in the gemfile (not the podfile).

It doesn’t install gems if any are missing, it just prints out an error asking you to install the gems

###### Misc.

Installing bundler itself is as simple as doing a `gem install bundler`. After all its a gem itself too. `gem install bundler -v <VERSION_NO>` installs a specific version of Bundler.

`bundle` if typed alone defaults to `bundle install`.

`bundle init` creates an empty gemfile.

`bundle install --system` apparently installs the gems as system gems (i.e. installs them in the system folder), not for the folder corresponding to the current project.

`bundle pack` seems to be some command that can download gems mentioned in gemfile in such a way that internet is not needed to do bundle install anymore. However its not recommended. Apparently downloads them so something like a vendor/cache folder.
