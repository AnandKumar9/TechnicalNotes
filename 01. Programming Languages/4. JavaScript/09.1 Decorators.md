#### Decorators and forwarding, call/apply

`Decorator` is the term used for a wrapper function around a function that enhances it in some way.

In the below example, `slow()` gets wrapped in another `cachingDecorator()`  and then also reassigned to it such that when `slow()` is called with a parameter that it was already called with from before, the previously cached result gets used.

```
function slow(x) {
  // there can be a heavy CPU-intensive job here
  alert(`Called with ${x}`);
  return x;
}

function cachingDecorator(func) {
  let cache = new Map();

  return function(x) {
    if (cache.has(x)) {    // if there's such key in cache
      return cache.get(x); // read the result from it
    }

    let result = func(x);  // otherwise call func

    cache.set(x, result);  // and cache (remember) the result
    return result;
  };
}

slow = cachingDecorator(slow);

alert( slow(1) ); // slow(1) is cached and the result returned
alert( "Again: " + slow(1) ); // slow(1) result returned from cache
```

> There are several nuances and enhancements to this that can be done. `func.call`, `func.apply`. <br> <br>
There are also terms like `method borrowing`. Read JavaScript.info [link](https://javascript.info/call-apply-decorators#transparent-caching), its detailed.

#### Function binding

`func.bind(context, ...args)` returns a “bound variant” of function func that fixes the context `this` and first arguments if given. Usually we apply `bind` to fix this for an object method, so that we can pass it somewhere. For example, to setTimeout. When we fix some arguments of an existing function, the resulting (less universal) function is called partially applied or partial.
