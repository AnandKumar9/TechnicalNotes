There are some module management systems (i.e. managing multiple JavaScript files to get them to work together) before JavaScript started providing built-in support. These include `AMD`, `CommonJS` (module system created for Node.js server), `UMD`.

##### import, export

A module is just a file. Modules can load each other and use special directives `export` and `import` to interchange functionality, `export` specifies what variables and functions can be accessed by other files and `import` specifies what to access from other files.

```
// In sayHi.js
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}

// In main.js
import {sayHi} from './sayHi.js';

alert(sayHi);
sayHi('John');
```

Nuances regarding import/export syntax ([link](https://javascript.info/import-export#summary))

##### Dynamic imports

Dynamic imports allow which module to be imported at runtime, and can also allow conditional imports at runtime.

The `import(module)` expression loads the module and returns a promise that resolves into a module object that contains all its exports.
```
let modulePath = prompt("Which module to load?");

import(modulePath)
  .then(obj => <module object>)
  .catch(err => <loading error, e.g. if no such module>)
```

Dynamic imports work in regular scripts, they don’t require script `type="module"`.

Although `import()` looks like a function call, it’s a special syntax that just happens to use parentheses (similar to `super()`).

##### Using in a browser

When running in a browser, the browser needs to be informed that a script needs be treated as a module, by using the attribute `<script type="module">`.
```
<script type="module">
  import {sayHi} from './say.js';

  document.body.innerHTML = sayHi('John');
</script>
```

Modules work only via HTTP(s), not locally.

Module scripts are always deferred, i.e. same effect as `defer` attribute for both external and inline scripts.
> The above should become more clear after reading about browsers section.

While for non-module scripts the async attribute only works on external scripts, for module scripts, it works on inline scripts as well. (JavaScript.info [link](https://javascript.info/modules-intro#async-works-on-inline-scripts))

External scripts that have `type="module"` are different in two aspects - External scripts with the same src run only once, External scripts that are fetched from another origin (e.g. another site) require `CORS` headers.

No 'bare' modules are allowed.

##### Misc.

Modules always use strict mode. Each module has its own top-level scope. In other words, top-level variables and functions from a module are not seen in other scripts.

A module code is evaluated only the first time when imported. If the same module is imported into multiple other modules, its code is executed only once, upon the first import.

The object `import.meta` contains the information about the current module. Its content depends on the environment.
```
<script type="module">
  alert(import.meta.url); // script URL
  // for an inline script - the URL of the current HTML-page
</script>
```

In a module, `this` is undefined.
