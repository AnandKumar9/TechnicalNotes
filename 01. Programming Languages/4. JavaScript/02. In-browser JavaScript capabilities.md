In-browser JavaScript can do everything related to webpage manipulation, interaction with the user, and the webserver.

##### Modifying HTML

For instance, it can add new (or modify existing) HTML to the page, react to user actions, make requests over the network (using `AJAX`, `COMET`, etc.), work with cookies, work with local storage.

##### Can only access some files

What it can't do is read or write arbitrary files on the hard disk, run programs, or have direct access to OS functions (i.e. working with memory, processes, etc.).

##### Can access some camera, etc. only with user permission

Modern browsers do allow to work with files, but the access is limited and only provided if the user does certain actions, like “dropping” a file into a browser window or selecting it via an `<input>` tag. Its like any random file can be surreptitiously worked with. There are also ways to interact with camera/microphone and other devices, but they require a user’s explicit permission.

##### Restricted knowledge about other browser tabs

Different tabs/windows generally do not know about each other. Sometimes they do, for example when one window uses JavaScript to open the other one. 

Otherwise scripts can access data across windows only as allowed by  `Same Origin Policy`. With Same Origin Policy (i.e. SOP), a web browser permits scripts contained in a first web page to access data in a second web page, but only if both web pages have the same origin. An origin is defined as a combination of URI scheme, host name, and port number. 

##### Making network requests to other servers

JavaScript can easily communicate over the net to the server where the current page came from. But its ability to receive data from other sites/domains is limited. Its possible but requires explicit agreement expressed in HTTP headers (response headers?) from the remote side.
