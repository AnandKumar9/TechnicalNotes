`JavaScript` scripts can be written right in a web page's HTML and run automatically as the page loads. Unlike many other languages like Swift and Java, it is not a compiled language.

##### JavaScript engine (where can JavaScript be run)

JavaScript can in fact now run even outside a web broswer, it can basically run on any system or server that has the `JavaScript engine` installed. JavaScript engines are made by most major web browser vendors and as well as some more entities that heavily use JavaScript (such as Node.js).

The JavaScript engine provided by browsers is often referred to as `JavaScript virtual machine`.

`V8` - JavaScript engine used in Chrome, Opera, Edge. <br>
`SpiderMonkey` - JavaScript engine used in Firefox. <br>
`Chakra` - JavaScript engine used in Internet Explorer. <br>
`JavaScriptCore` - JavaScript engine used in Safari.

##### ECMAScript (a JavaScript standard)

`ECMAScript` is the common JavaScript standard across various web browsers, and anyone making a JavaScript engine.

##### JavaScript runtime (converting JavaScript to machine language)

A `JavaScript runtime` is a different thing than a `JavaScript engine`. JavaScript runtime provides APIs to develop scripts. For example, web browsers' runtime environments provide DOM API, Fetch API, Storage, etc. Something important called `Runloop` is implemented in runtime.

A JavaScript engine converts the JavaSript code into machine language code so that the system can execute it. It is what serves as the Interpreter.

##### Node.js (a runtime environment)

`Node.js` is a back-end JavaScript `runtime environment` for JavaScript code that is run outside a web browser. It allows use of  JavaScript to write command line tools and for server-side scripting, i.e. running scripts server-side to produce dynamic web page content before the page is sent to the user's web browser. It runs on (with?) `V8 engine` (a JavaScript engine developed by Google).

> But then again there seems to be references where it looks like the term `engine` actually means all of these things together, i.e. the custom JavaScript API + parsing and converting it to machine language code + actually running that machine language code.

##### JavaScript Transpilers

There are several other JavaScript 'based' languages that exist which provide their own syntax/capabilities and are transpiled (i.e. converted) to JavaScript before they are run in the brower. These languages typically aim to address certain limitations of JavaScript. Here are some of the examples.

`CoffeeScript` - Syntactic sugar with shorter sytnax. Liked by Ruby devs.

`TypeScript` - Concentrates on strict data typing. Developed by Microsoft.

`Dart` - Has its own engine that runs in non-browser environments (like mobile apps), but also can be transpiled to JavaScript. Developed by Google.

`Flow` - Supports data typing. Developed by Facebook.

`Kotlin` - Kotlin/JS provides the ability to transpile  Kotlin code to JavaScript. So may be useful to have Kotlin developers do web scripting. Works for Node.js environments too.
