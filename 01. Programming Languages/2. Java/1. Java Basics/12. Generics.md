###### Generic Types

A `Generic Type` is a generic class or interface that is parameterized over types.

A type variable can be any non-primitive type.

`Type parameter` is the term that refers to the generic parameter. `Type argument` whereas refers to the type argument that actually gets passed to the generic instance. <br>
For example, `T` in `Foo<T>` is a type parameter and the `String` in` Foo<String>` is a type argument.

###### Type Inference

The type arguments required to invoke the constructor of a generic class can be replaced with an empty set of type arguments (<>) as long as the compiler can determine, or infer, the type arguments from the context.

For example, here both box1 and box2 are initialized in valid ways.
```
public class Box<T> {

    private T t;

    public void set(T t) { this.t = t; }
    public T get() { return t; }
}

Box<String> box1 = new Box<String>();
Box<String> box2 = new Box<>();
```

###### Raw Types

Just the name of a generic class or interface alone without any type arguments, is called the `Raw type`.

The below code snippet is valid. Even if Box is actually a generic type, it creates a raw type of Box<T>. And apparently still makes it to work like a generic type.
```
Box box3 = new Box();
box3.set("Evening");
System.out.println(box3.get());
```

Raw types show up in legacy code because lots of API classes (such as the Collections classes) were not generic prior to JDK 5.0.

For backward compatibility, assigning a parameterized type to its raw type is allowed:

```
Box<String> stringBox = new Box<>();
Box rawBox = stringBox;               // OK
But if you assign a raw type to a parameterized type, you get a warning:

Box rawBox = new Box();           // rawBox is a raw type of Box<T>
Box<Integer> intBox = rawBox;     // warning: unchecked conversion
```

###### Generic Methods

`Generic methods` are methods that introduce their own type parameters.

```
public static <K, V> boolean compare(Pair<K, V> p1, Pair<K, V> p2) {
   return p1.getKey().equals(p2.getKey()) &&
          p1.getValue().equals(p2.getValue());
}
```

`Type inference` allows to invoke a generic method as an ordinary method. There is no need to specify type between the angle brackets.

###### Bounded Type Parameters

`Bounded Type Parameters` allows to restrict the types that can be used as type arguments in a parameterized type.

To declare a bounded type parameter, list the type parameter's name, followed by the extends keyword, followed by its upper bound (superclass?).

```
public <U extends Number> void inspect(U u) {
```

A type parameter can have multiple bounds. If one of the bounds is a class, it must be specified first. Here B1 can be a class (or interface too?) but B and C must be interfaces.

```
<T extends B1 & B2 & B3>
```

###### Generics and Inheritance

Given two concrete types `A` and `B` (for example, `Number` and `Integer`), `MyClass<A>` has no relationship to `MyClass<B>`, regardless of whether or not `A` and `B` are related. The common parent of `MyClass<A>` and `MyClass<B>` is `Object` and not something else.

A generic class or interface can be sub-typed by extending or implementing it. The relationship between the type parameters of one class or interface and the type parameters of another are determined by the extends and implements clauses.

For example, `ArrayList<E>` implements `List<E>`, and List<E> extends `Collection<E>`. So `ArrayList<String>` is a subtype of `List<String>`, which is a subtype of `Collection<String>`. So long as the type argument is not varied, the sub-typing relationship between the types is preserved.

###### Generic Constructors

Constructors can be generic (in other words, declare their own formal type parameters) in both generic and non-generic classes.

###### Target Types

The target type of an expression is the data type that the Java compiler expects depending on where the expression appears.
