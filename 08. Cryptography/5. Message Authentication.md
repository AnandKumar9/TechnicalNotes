Messages are typically authenticated by adding extra information to the message itself that only the sender could have computed. When used in symmetric key encryption, thet are called `Message Authentication Codes`. When used in publick key scheme, they are called `Signatures`.

#### Message Authentication Code (MAC)

Used to check the authenticity and integrity of a message in Symmettic key encryption schemes. Also known as `Tags`.

A `MAC algorithm` takes a message of arbitrary length and a secret key of fixeed length, and produces the tag. It typically also comes with a `verification algorithm` that takes a message, key and a tag, and tells if the tag is valid or not.


##### Possible attacks

`Chosen Forgery Attack` - Attacker sends a bunch of messages(m) and ghets their tags(t).

`Existential Forgery Attack` - Using the above attacker, devises a way to itself generate the tag for a given message.

A secure MAC should not allow the above to be possible.

##### Why does MAC take a secret key

Sometimes checksums (like CRC32 or Arlder32) or even hashes (SHA family) are used to get a checksum of the message and are attached to it. When the recipient gets it, they compute the checksum and match it with the received checksum to ensure its validity.

This however is a pretty unsecure thing as the attacker can itself modify the checksum too as these checksums are usually calculated using well known methods. To avoid that a signature is applied to the binaries directly using a secret key.

##### Combining MAC and message

There are 3 ways to combine a ciphertext with MAC.

1. `Authenticate and Encrypt` - The ciphertext creation and authentication code generation are done separately, and then both are sent. `SSH` does it this way.
```
C = E(k1, P), t = MAC(k2, P)
```

2. `Authenticate then Encrypt` - First the code is generated, and then the combination of plain text and code ais encrypted. And then just teh combination is sent. `TLS` does it this way.
```
t = MAC(k2, P), C = E(k1, P||t)
```

3. `Encrypt then Authenticate` - The ciphertext is generated first, and the tyhe coee is cpmputed. `IPSec` does it this way.
```
C = E(k1, P), t = MAC(k2, C)
```

Among all of these `Encrypt then Authenticate` is the most secure as it requires validation of MAC before the receiver decrypts the message, Every other method requires decryption before validation and that is not good. `Authenticate then Encrypt` is however not too bad either, and certainly a lot better than at least `Authenticate and Encrypt`.

##### Hash-based Message Authentication Code (HMAC)

A standard to produce a MAC using a cryptographic hash function as a parameter. It does of course take a secret key though. Its supposed to be very secure.

##### One-time MACs

`One-time MAC` is a MAC function that can be securely used only once, with a single key. It however is not practical.

`Carter-Wegman MAC` is a MAC function that turns any secure One-time MAC into a secure many-time MAC. This in fact is lot more practical.

##### Authenticated Encryption with Associated Data (AEAD)

Authenticated encrypted message have several `modes`. `AEAD` is a feature of certain modes of authenticated encryption, and such modes are called `AEAD modes`.

Typically messages consist of 2 parts - Actual content, Metadata about the content. Typically the actual content should be encrypted but the metadata shouldn't. The entire message should then ideally be authenticated, but very often systems leave the metadata unauthenticated.

`AEAD` is a way that somehow kincludes the metadata too in the encrypted portion.
> But then how does the meatadats stay unencrypted, it needs to be deciphered by amn interim server such as a mail server.

`OCB` and `GCM` are modes of `AEAD`.

#### Signature Algorithms

Used for authenyticating publick-key encrypted messages.

It has 3 parts. <br>

1. `Key-generation algorithm`. Generates a public and private key. <br>

2. `Signature Generation algorithm`. Given a message a d a key, produces a signature.

3. `Signature verification algorithm`. Given a message, public key and signature, accepts or rejects message's claim to authenticity.

##### Misc.

`Digital Signature Algorithm (DSA)` is a standard for digital signatures.

`Elliptic Curve DSA (ECDSA)` is another variant of DSA.

`Non-repudiation` is the fact that once the reciver verifies the source, the source cannot deny that it sent the message.

`Nonce` is a number that can be used just once in a cryptographic communication. They often also include a timestamp.

`Key-derivation function` is a function that derives one or more secret values (keys) from one secret value. They often also take in a salt parameter (i.e. random data).
