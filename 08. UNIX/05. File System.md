#### Different kinds of files

Everything in UNIX is a file.

There are mainly 3 kinds of files -
1. Ordinary file
2. Directory file
3. Device file

`Ordinary file` can be of two types. `Text file` only contains printable characters. `Binary file` contains both printable and unprintable characters.

`Directory file` keeps details of files and subdirectories it contains.
Each entry in a directory file has two components - filename, unique ID (known as `inode`)
for that file.

You can't write a directory file, but you can perform actions that make the kernel write a directory. When you create or update a file, kernel automatically updates the corresponding directory.

Even `device` (like a CD-ROM or tape) is a file. It's typically not a stream of characters, and actually does not contain anything at all. Device filenames are generally found in a single directory structure called `/dev`.
> Is it that the name of a device file is in a location called `/dev` in it. Or is it that the names of all connected device files are in some common location called `/dev`?

###### Filenames
Usually filenames can have any character other than `/` and the NULL character (i.e. ASCII value 0), and can have up to 255 characters. Though all other characters are typically allowed, the normal convention is to have only alphanumeric and `.-_` characters in file names.
The characters `&?*` (and back-tick) in particular should not be used, as they have special meaning in UNIX.

There is no mandatory requirement from UNIX that ordinary files have an extension. In fact even `.sh` is not needed for shell scripts, it's just a convention. Typically, it is an application that imposes requirements on what file extensions it can open. Hence, a C compiler requires files to have `.c` extension.

> Its not a good idea to have file names beginning with `-` as when used in shell commands providing these file names as arguments can cause them to be interpreted as the command's flag (option) instead.

#### `root` and `home` directories

`root` is the 'top' which serves as reference point for all files and is represented by `/`. Every file apart from `root` musty have a parent.
> System admin can use the user id `root` to login to a system. That is a different thing.

Home directory is where a user is placed on login. It's always stored in `$HOME` (i.e. `HOME` environment variable). It is typically something like this though it can be changed.
```
sou543$ echo $HOME
/Users/sou543
```

The first slash (`/`) is a synonym for root. <br>
`~` is same as home directory.

In fact it seems that the env variables can be substituted in commands. The below command is valid.
```
Desktop sou543$ cd $HOME/Pictures
Pictures sou543$

~ sou543$ cd ~/Documents
Documents sou543$
```

#### Commands for file operations

`pwd` prints the current working directory for the shell session.

`cd` changes the working directory.
When it is invoked with no arguments, it makes the home directory the working directory. Also, it can sometimes failto change the working directory when trying to access restricted directory (of if directory's permissions are incorrecrtly tampered with).

`cd  -` as well as `cd ~-` changes the working directory to the previous working directory. <br>
`cd ~` changes the working directory to home directory.

`mkdir` makes directories. If nested directories are to be created, first the parent should be created.
```
mkdir Directory1 Directory2
mkdir DirectoryCompletePath
```
> On macOS, it seems that any intermediate directory in the path must already be created.

`rmdir` removes directories. If nested directories are to be removed, first the children must be removed. A non-empty directory cannot be removed.
> `rm -r FolderName` can be used to attempt to delete a folder recursively.

All absolute paths begin with `/` (i.e. root directory). <br>
`.` represents current directory. <br>
`..` represents parent directory. <br>

Single dot can be used in commands where the current directory is an allowed argument. For example, the second argument here specifies current directory.
```
cp SomeFileAbsolutePath .
```

##### `ls` command

Providing file(s) as argument just prints the specified file (or its contents along with its name if its a directory) if it exists. And if it does not exist, prints a message.

Desktop		Downloads	Movies		Pictures

#### Typical UNIX file system structure

The root directory typically has some standard subdirectories. Here is how my root directory currently looks.
```
/ sou543$ ls
Applications/			cores/				private/
Library/			dev/				sbin/
Network/			etc@				tmp@
System/				home/				usr/
Users/				installer.failurerequests	var@
Volumes/			net/
bin/				opt/
```

`/bin` and `/usr/bin` - This is where the UNIX commands usually are. `$PATH` always has these two directories in it.

`/sbin` and `/usr/sbin` - This has commands which can be executed only by system administrator. They do not even show up in File system/Finder and are present in `$PATH` for a non-admin user.

`/etc` - Has configuration files. The login name and passwords are stored in `/etc/passwd` and `/etc/shadow`.

`/usr/share/man` - Has all the man pages. For example the man file for `ls` is at `/usr/share/man/man1/ls-F.1`.

`/usr/lib` - Contains various libraries (i.e. dylib files).

`/tmp` - The user is allowed to create temporary files here. These files are regularly wiped out by the system.

`/var` - Contains all the ephemeral things, i.e. print jobs and incoming or outgoing mails.
