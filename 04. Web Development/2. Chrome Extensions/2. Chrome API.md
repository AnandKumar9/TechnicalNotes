Chrome itself provides all the Javascript code in extensions with an [API](https://developer.chrome.com/extensions/api_index) to interact with various facets of Chrome in particular. This is distinct and in addition to the [Web API](https://developer.mozilla.org/en-US/docs/Web/API) that all browsers provide to JavaScript anyway.

Using some of the properties and methods in particular require entries to be made in the manifest.

`tabs` - Used to interact with Chrome's tabs system. ([link](https://developer.chrome.com/extensions/tabs))

`query` - A method that gets all tabs that have the specified properties, or all tabs if no properties are specified.

```
var queryInfo = {
    active: true,
    currentWindow: true
};

chrome.tabs.query(queryInfo, (tabs) => {
    var tab = tabs[0];
    var url = tab.url;
    console.log(url);
});
```

`executeScript` - Injects JavaScript code into a page.
> So it injects it only into the page for which the extension was invoked? Seems so.

```
var script = 'document.body.style.backgroundColor="' + color + '";';
chrome.tabs.executeScript({
    code: script
});
```

`extension` - To find pages in the extension, `chrome.extension` methods such as `getViews()` and `getBackgroundPage()` can be used.

`runtime` - Used to do plenty of things. Retrieve background page, get details about the manifest, work with events from extension's lifecycle, convert relative paths to fully qualified paths, etc. ([link](https://developer.chrome.com/extensions/runtime))

`lastError` - A property that gives the last error that has occurred during runtime. Typically defined in various callbacks.

```
chrome.storage.sync.get(url, (items) => {
   callback(chrome.runtime.lastError ? null : items[url]);
});
```

###### Storage API
<br>
`storage` provides API to work with user specific data storage. This data can also get automatically synced with Chrome.sync. Content scripts can access it directly without needing a background page. ([link](https://developer.chrome.com/extensions/storage))

It has 3 properties, each of which correspond to 3 different storage types - `sync`, `local`, `managed`. Items in the managed storage area are set by the domain administrator, and are read-only for the extension

`sync.get` and `sync.set` methods - Used to work with 'sync storage area'.

set is used to add a set of key-value pairs to the storage. An optional callback can also be provided as the second argument.

```
chrome.storage.sync.set(items);
```

get is used to get the value(s) for specified key or array of keys. The value are made available in the callback in second argument. In the below example just one key is requested.
```
chrome.storage.sync.get(url, (items) => {
    callback(chrome.runtime.lastError ? null : items[url]);
});
```

Keep in mind there are other storage APIs too that Chrome provides to extensions (and there are differences between their capabilities), this is not the only thing.

Also, this storage is not encrypted.
