##### Properties of XOR

There are some special behaviors of XOR (⨁) that make it particularly well suited for extensive use in cryprography.

1. It can be applied in any order
```
a ⨁ b = b ⨁ a
```

2. The operands can be flipped.
```
a ⨁ b = b ⨁ a
```

3. Any bit XOR-ed to itself becomes 0.
```
a ⨁ a = 0
```

4. Any bit XOR-ed to 0 remains unchanged.
```
a ⨁ 0 = a
```

Consequently, this is possible. In the second expression, `b` is the plain text bit and `a`is the secret key bit, the first `b ⨁ a` results in a ciper text bit. The first ⨁ is the encryption and the second ⨁ is the decruption.
```
a ⨁ b ⨁ a = b
b ⨁ a ⨁ a = b
```

##### One time pad

`One time pad` is a sequence of random bits that are used for XOR-ing as an encryption scheme. The pad is shared bdtween the sender and the receiver. It is a strong mechanism if bits were truly random and used only once. However that pratically does not happen.

And if the same pad gets used to encrypt two different plain texts, even thhos encrypted texts can be looked at together to get some clues about the underlying plain texts.
```
c1 ⨁ c2 = p1 ⨁ k ⨁ p2 ⨁ k = p1 ⨁ p2
```

One time pads are also impractical for the reason that the key needs to be as long as plain text. And generating truly random key is a time taking and hardware intensive process.

##### Summary

`Symmetric key encryption` - Same key used for encryption and decryption. <br>
`Public key encryption` - Different keys used for encryption and decryption. <br>

`One time pad` - Impractical. Key needs to be as long as plain text. Symmetric. <br>

`Block cipher` - Encrypts blocks of fixed length (block size). Symmetric. <br>
`AES` - A typeo pf block cipher. Block size of 128 bits. <br>
`DES` - An old block cipher, not safe and not used anymore. <br>
`3DES` - Some improvement on DES. <br>

`Stream cipher` - Can operate on a stream of any length. Symmetric. Quite secure. <br>
`ECB mode`, `CBC mode`, `CTR mode` - Different ways of doing stream cipher. <br>
`Native stream cipher` - Stream ciphers that do not use block cipher at all. <br>
`Synchronous stream cipher`, `Asynchronous stream cipher` - Different kinds of stream ciphers. <br>
`RC4` - Commonly used native stream cipher. <br>
`Salsa 20` - A new stream cipher. <br>

`Padding` - Process of padding extra bits when message length is not a multiple of block size. <br>

`Dieffe-Hellman algorithm` - A way to do exchange keys in a secure manner, it actually never exchanges the eventual key itself but facilitates a way for both ends to securely generate the key. <br>

`RSA` - Most commonly used public-key encryption algorithm. <br>
`OEAP` - A padding mechanism used in RSA. <br>

`Hash function` - Functions that can take an input of any length, but produce an output of fixed lenth which is known as digest. Digests are usually different for different inputs but sometimes can be same too.

`Message Authentication Code (MAC)` - Used for authenticating symmetric key encryption schemes. Also known as tags. <br>
`Signature` - Used for authenticating public key encryption schemes. <br>

`MAC algorithm` - Takes a message of arbitrary length and a secret key of fixeed length, and produces the tag. <br>
`Verification algorithm` - Takes a message, key and a tag, and tells if the tag is valid or not.

3 ways to combine a MAC and a message - Authenticate and Encrypt, Authenticate then Encrypt, Encrypt then Authenticate (most secure).

`Hash-based Message Authentication Code (HMAC)` - A standard to produce a MAC using a cryptographic hash function as a parameter. <br>
`One-time MAC` - A MAC function that can be securely used only once, with a single key. <br>
`Carter-Wegman MAC` - A MAC function that turns any secure One-time MAC into a secure many-time MAC. More pratical. <br>

`Authenticated Encryption with Associated Data (AEAD)` - A way that somehow includes the metadata too (not just the actual content) in the encrypted portion.

3 parts of Signature Algorithms - <br>
Key-generation algorithm, Signature Generation algorithm, Signature verification algorithm. <br>

`Digital Signature Algorithm (DSA)` - A standard for digital signatures. <br>
`ECDSA` - Another variant of DSA. <br>

`Nonce` - A number that can be used just once in a cryptographic communication. <br>

`SSL`, `TLS` - Cryptographic protocols for securing tarffic on the web. TLS has now superseded SSL. Even when people say SSL now, it usually means TLS..

`Handshake` - The initial step in a SSL/TLS connection in which client and server agree on various parameters used to establish the connection's security. This is when cipher suite, keys, etc. are exchanged and established.

`Certificate` - Contains plenty of things including public key and digital signature. <br>
`Certificate Authority (CA)` - Officially issues certificates. <br>
Client certificates - When clients produce their own certificates. <br>
Self signed certificate - A certificate that is not signed by a CA. <br>

`HTTP Strict Transport Security (HSTS)` - A way to communicate that the data transfer should only be done a secure transport. Done using a specific HTTP header.

`Certificate Pinning` - Client remembers the certificates (actualy a hash of the public key) itself and in subsequent connections, the older certificate is matched with the incoming certificate to ensure the server is authentic.

`OpenPGP` - A whole another cryptosystem that mainly focuses on securing data at rest. <br>
`GPG` - The most popular implementation of OpenPGP. <br>
`Off-the-record (OTR) messaging` - A protocol for securing instant messaging communications. <br>
