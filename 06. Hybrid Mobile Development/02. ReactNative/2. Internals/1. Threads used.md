RN uses 60 frames per second unlike webview based hybrid app development tools, which is what its UI to feel more native-like.  

iOS devices display 60 frames per second, which gives the UI system ~16.67ms to generate the static image (frame). If you are unable to do the work necessary to generate that frame within the ~16.67ms, then system will "drop a frame" and the UI will appear unresponsive.

##### JS frame rate (JS thread) and UI frame rate (Main thread)

There are two different frame rates.

Usually, the RN code's business logic runs on the `JavaScript thread` (i.e. not the main thread). This is where the React application lives, API calls are made, touch events are processed, etc.. Updates to native-backed views are batched and sent over to the native side at the end of each iteration of the event loop. f the JavaScript thread is unresponsive for a frame, it will be considered a dropped frame. This can happen if the root component of a complex app is reset, or with Navigator transitions when you push a new route as the JavaScript thread needs to render all of the components necessary, or even with processing touches if the JS thread is working with multiple frames at the same time.

`UI thread` is the main thread in iOS parlance. It is the most responsive thing. `NavigatorIOS` uses it (unlike `Navigator`), and many core components do too (like `ScrollView`).

> JavaScript thread performance suffers greatly when running in dev mode i.e. `dev=true`). `console.log` statements are expensive too and shouldn't be used in prod.
