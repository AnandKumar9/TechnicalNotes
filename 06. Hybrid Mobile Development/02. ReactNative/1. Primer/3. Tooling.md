`Expo` ([link](https://docs.expo.dev/get-started/introduction/)) it appears is a set of tools that help in several things in RN development. It has packages/command line tools to create new project, start a web server, live preview, etc.

`Ignite` ([link](https://github.com/infinitered/ignite)) seems to be a set of command line tools that can generate different kinds of boilerplate code.

`Metro` ([link](https://reactnative.dev/docs/metro)) seems to be what builds the JS code and assets. Its configured using the project's `metro.config.js` file.

`ESLink` ([link](https://eslint.org)) is the common tool used for linting checks.

##### Expo Go

`Expo Go` is an easy way to install and run the app on simulator as well as device. It can even be [installed directly](https://expo.dev/go) without having to do 'npx expo start'.

##### Snack

[Snack](https://snack.expo.dev) is a way to run ReactNative code in browser for testing.

##### Running on device

In case of iOS project, there is an xcodeproj/xcworkspace that is generated and can be used. Its usually in a folder named `ios`.

In case of Android projects it can usually be done using `npm run android`

([Link](https://reactnative.dev/docs/running-on-device?platform=android&os=macos))

##### Development Server

When running on device, the UI can refresh automatically whenever code is changed if the 'development server' on Mac is running and reachable. (Refer 'Connecting to the development server' at [this](https://reactnative.dev/docs/running-on-device?platform=ios) link.)

##### Continuous Native Generation (CNG)

`Continuous Native Generation (CNG)` is a process for building an Expo app where the native projects are generated on-demand from your app.json and package.json, similar to how your node_modules are generated from your package.json. ([Reference](https://docs.expo.dev/workflow/continuous-native-generation/))

In fact,  native project directories (android and ios) can even be added to the .gitignore. It supposedly makes project maintenance easier.
