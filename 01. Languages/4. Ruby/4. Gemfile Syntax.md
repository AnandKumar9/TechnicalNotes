###### Sample gemfile

```
#ruby=2.3.0
#ruby-gemset=ease-ios

source "https://artifactory.cloud.capitalone.com/artifactory/gems-internalfacing"

gem 'cocoapods', '1.5.0'
gem 'fastlane'
gem 'danger', :git => 'https://github.kdc.capitalone.com/Caffeine/danger-fork', :tag => 'v5.5.5'
gem 'unirest'

plugins_path = File.join(File.dirname(__FILE__), 'fastlane', 'Pluginfile')
eval_gemfile(plugins_path) if File.exist?(plugins_path)
```

###### Specifying gems' versions
```
'4.1.0.rc2' - Precise version
Nothing - Any version that works
'~> 1.6.1' - Any version >= 1.6.1 but < 1.7.0

">= 1.4.2" - Any version >=
">= 4.1.0", "< 4.2.0" - Any version between the specified ones
```

###### Specifying Ruby version and implementation
```
ruby "1.9.3" - Specify ruby version to be used
ruby "1.8.7", :engine => "jruby", :engine_version => "1.6.7" - If the engine (i.e. Ruby implementation is specified, then the engine version must also be specified)
```

###### Specifying source

If a gem is found in more than one global source, bundler prints a warning after installing the gem indicating which source was used. There is something called [source priority]((https://bundler.io/v1.17/man/gemfile.5.html#SOURCE-PRIORITY) which determines which gem to prefer if they are listed in multiple sources.

Some gem sources require a username and password. Use bundle config to set the username and password for any of the sources that need it.
`bundle config gems.example.com user:password`

`gem "some_internal_gem", :source => "https://gems.example.com"` - Specify an alternate Rubygems repository for a gem using the ':source' option.

###### Specifying groups

Each gem may specify membership in one or more groups. Any gem that does not specify membership in any group is placed in the default group.
```
gem "rspec", :group => :test
gem "wirble", :groups => [:development, :test]
```

###### Specifying git repository as source

If necessary, it can be specified that a gem is located at a particular git repository using the `:git` parameter.
```
gem "rails", :git => "https://github.com/rails/rails.git" (HTTPS)
gem "rails", :git => "git@github.com:rails/rails.git" (SSH)
gem "rails", :git => "git://github.com/rails/rails.git" (GIT)
```

`branch`, `tag`, and `ref` - Only one of these options must be specified. The default is `:branch => "master"`

```
git "https://github.com/rails/rails.git", :branch => "5-0-stable" do
```

The git repository should have at least one file, at the root of the directory containing the gem, with the extension `.gemspec`.

`:submodules => true` causes bundler to expand any submodules included in the git repository
> A git submodule lets you have another git repository within a subfolder of your repository.

###### Specifying local location as source

```
gem "rails", :path => "vendor/rails"
```

###### Semantic versioning in general

Following is the usual convention for deciding whether a version increment should be major, minor or patch.

`PATCH` 0.0.__x__ level changes for implementation level detail changes, such as small bug fixes <br>
`MINOR` 0.__x__.0 level changes for any backwards compatible API changes, such as new functionality/features <br>
`MAJOR` __x__.0.0 level changes for backwards incompatible API changes, such as changes that will break existing users code if they update. <br>

###### Misc.

The `:source`, `:git`, `:path`, `:group`, and `:platforms` options may be applied to a group of gems by using block form.

```
source "https://gems.example.com" do
  gem "some_internal_gem"
  gem "another_internal_gem"
end

git "https://github.com/rails/rails.git" do
  gem "activesupport"
  gem "actionpack"
end
```

The `install_if` method allows gems to be installed based on a proc or lambda. (So looks like the installations can be conditioned quite a lot.)
```
install_if -> { RUBY_PLATFORM =~ /darwin/ } do
  gem "pasteboard"
end
```
