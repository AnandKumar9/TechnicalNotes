##### Greedy quantifier, Lazy matching

Typically while finding a match, the largest possible match is made. This is called `greedy quantifier`.

In the below example the entire string got matched and there is only 1 match returned, not two.

Pattern - ".+" <br>
Test string - `"Ganymede," he continued, "is the largest moon in the Solar System."`

Pattern - ".*foo" <br>
Test string - `xfooxxxxxxfoo`

If however, just the bare minimum match (i.e. lazy matching) is needed, `+?` Or `*?` can be used. This is called `lazy matching` or also `reluctant matching`.

Now in the below example see how there are two matches now.

Pattern - ".+?" <br>
Test string - `"Ganymede,"` he continued, "is the largest moon in the Solar System."

Pattern - ".*?foo" <br>
Test string - `xfoo xxxxxxfoo`


`Possessive quantifiers`, i.e. `.*+` and `.?+` are something to do with how efficiently can the regex fail to find a match. (Need to understand it better, its something to do with the fact that it never backtracks after the initial attempt where the entire test string is matched.)
`Atomic groups` are something that let you do the same thing as possessive quantifiers.

##### POSIX class

POSIX classes (character classes) are a way to specify a set of characters. It works regardless of the underlying OS.
`[:upper:]` for instance denotes an uppercase character.

When used in a pattern, they must be put inside character class (i.e. sequence expressions).

Pattern - [[:upper:]]*
Test string - `GOOD` cap

##### Word boundary

`\b` ensures that the pattern occurs only at the boundary of a word (start or end).

Pattern - \bcat <br>
Test string - `cat`tle <br>
Test string - _cattle (No match as cat is not at the beginning of word).

Pattern - cat\b <br>
Test string - tom`cat` <br>
Test string - tomcat_ (No match)


Actually, word boundary is first character in string (if first character is a word characters, i.e.\w); or last character in string (if last character is word character); or between two characters in a string where one is word character and other is not.

Pattern - ABC\b <br>
Test string - xy`ABC` xy`ABC`πlm xyABClm (as π here forms a word boundary, the ABC in second 'word' matches)

##### Backreferencing and non-capturing group

A pattern may have multiple groups. When the pattern matching is happening in a test string, then any group that matches actually gets stored which can the be referenced further in the pattern.

Pattern - (talent).*\1 <br>
Test string - You know, `talent is what talent` does. <br>

If however a group should not be captured then it must be prefixed with ?:

Pattern - (\w\w) (?:\d\d) (\w\w) = \2 <br>
Test string - `AB 34 LM = LM`

##### Lookarounds

`?=` - Look ahead positive <br>
`?!` - Look ahead negative <br>
`?<=` - Look behind positive <br>
`?<!` - Look behind negative <br>
`?>` - Atomic group <br>

`A(?=B)` - First occurrence of Expression A where Expression B follows <br>
`A(?!B)` - First occurrence of Expression A where Expression B does not follow <br>
`(?<=B)A` - First occurrence of Expression A where Expression B precedes <br>
`(?<!B)A` - First occurrence of Expression A where Expression B does not precede <br>

Pattern - ABC(?=X) <br>
Test string - ABCJ`ABCX`

They can even be combined.

Pattern - A(?=.*D.*)(?=.*C.*) <br>
Test string - `A`BCD <br>
Test string - ABDE (No match. D is present but C is not)

##### Inline modifiers

They are (?) like constructs and when used they change the specified mode for remaining part of the pattern.

Pattern - a(?i)mjo <br>
Test string - `aMjO`h (after the inline modifier the case of the pattern does not matter)

##### Groups

One thing to keep in mind about regular expression matching is that results are given in full match as as well as captured groups. Captured groups are nothing but the portions corresponding to the caputre-able groups in the pattern. Anything in () in a pattern is potentially a group.

Pattern - (?:href=\\")(.*?)" <br>
Test string - Questions? Corrections? <a `href=\"https://twitter.com/NSHipster\"`>@NSHipster</a> or <a `href=\"https://github.com/NSHipster/articles\"`>on GitHub</a>."

There are 2 full matches and each of the matches have 1 group each.

Match 1 - href=\"https://twitter.com/NSHipster\ <br>
Group 1.1 - "https://twitter.com/NSHipster\

Match 2 - href=\"https://github.com/NSHipster/articles\" <br>
Group 2.1 - "https://twitter.com/NSHipster\articles

##### Non-english word characters

The below expression matches non-English word characters such as ∆ † µ © ˚ ø. ([link](https://stackoverflow.com/a/150078/1135417))

PCRE flavor - [^\x00-\x7F] <br>
