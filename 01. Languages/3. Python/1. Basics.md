##### Checking the Python version -

Check the default version used by python. <br>
`python --version`

Keep in mind that multiple python versions might be installed on the system and it isn't necessary that the latest version is used by default.

Get a list of all python versions installed. <br>
`ls -sl /usr/local/bin/python*`

This is probably not quite a very accurate method, but seems to work. What it is clearly doing is that it is listing all the files/folders in the mentioned folder which is a likely place for all Python versions to be installed in. You could then skim through all the results and see which ones are installed.

Creating alias for the [default python version](https://stackoverflow.com/questions/7679674/changing-default-python-to-another-version).

Get currently running python version.
```
import sys
sys.version_info
```
##### Writing Python code on console -

Enter the console by typing `python` (or python3.6 if that is the version you want to use). The Python interpreter then gets active and what you see is `>>>`

The code can then be entered there. For example, `print("Hi")`. This immediately prints the message on console.

To exit the Python interpreter - `exit()/quit()`


##### Running a python script from console -

Just give the python version followed by the script name (or path). If the script has a shebang which specifies the version to be used, the python version name need not be given here. <br>
`python3.6 filename.py`

`shebang` line tells which version to use if run as an executable (i.e. without using python command). Also good practice to specify even if the command is explicitly given.
```
#!/usr/bin/env python3.6
#!/usr/bin/env python2
```


##### Deleting variables -

When applied to an object reference that refers to a data item that is not a collection, the `del` statement unbinds the object reference from the data item and deletes the object reference. (But I could see the same happening for a list too.)

```
var1 = 5
del var1
```

Trying to access `var1` after this will cause an exception. This can be caught using `try ... finally`.


##### Hashable objects -

`Hashable` objects are objects which have a `__hash__()` special method whose return value is always the same throughout the object’s lifetime, and which can be compared for equality using the `__eq__()` special method.

All the built-in immutable data types, such as `float`, `frozenset`, `int`, `str`, and `tuple`, are `hashable` and can be added to sets.

##### Dynamic code execution -

###### eval and exec -

`eval` evaluates a single expression and `exec` executes the passed code.

`exec` takes an entire code block that has Python statements: loops, `try:` `except:`, `class` and function/method definitions and so on and runs them.

So `eval` can run `"3*4"` but not `"x = 3*4"`. `exec` can totally run  `"x = 3*4"`, can still run `"3*4"` but not do anything useful out of it.

`eval` always returns the evaluated value from the expression, exec just ignores any thing that might get returned from the passed string.

`exec` can in fact also be passed an additional argument called context which is used to make variables from the code available in the string (though this seemed redundant to me when I tried).


```
a1 = 2
a2 = eval("3*4 + a1")
print(a2)                          # Prints 14

x1 = 5
exec('x2 = 4 + x1 + math.pi')
print(x1)                          # Prints 12.14

b1 = 2
b2 = exec("3*4 + a1")
print(a2)                          # Prints None, exec does not return anything

eval("x1 = 3*4")                   # This will not compile, the passed string is not an expression
```

[eval, exec and compile](https://stackoverflow.com/questions/2220699/whats-the-difference-between-eval-exec-and-compile-in-python/29456463#29456463) explanation


Some more dynamic programming and introspection functions - `compile, delattr, dir, getattrs, global, __import__, etc.`

###### Mutability -
Immutable types are a lot faster than mutable types.

Tuples are immutable, lists are mutable.
```
sampleTuple = ('One','Two')
sampleTuple[0] = ('Three') # Cannot be done
sampleTuple = ('Three') # Can be done
```
Every time a mutation is attempted on an immutable type, actually a copy gets created.
```
a = 5
a+= 2
```
Now there are actually two different allocations.

##### Collections (or whatever is the right term for Lists, etc.)  -

Anything added to a `list` must be `iterable`.
```
list1 = [2,5]
list1+= 6   #This is not iterable. Why?
list1+= [6] # This is iterable. Why?
```

```
list2 = ["string1", "string2"]
list2+= "string3"
```
Don't do the above. This will compile but treat every character as a separate item. As a string is `iterable` and `append()` appends each item of the `iterable` individually, this will happen.

##### When interacting with console -

Read user entered data from console -
`entry = input("Enter something - ")`

The output of a python script (i.e. what it is printing) can straight away be printed into a file instead of the console.
```
ScriptPath > OutputPath (overwrites existing content)
ScriptPath >> OutputPath (appends content)
```
Getting input from contents of a file and printing the output in another file.
`ScriptPath < InputPath > OutputPath`

`input()` raises an exception if it receives an `EOF` (end of file) character. This can happen when reading from a file. So it must be handled using a `try`. The error type is `EOFError`.

###### Command line arguments

Command line arguments are the arguments that are passed from command line while running the script. This concept probably holds true for all executables, not just python and not just those that are run literally from command line. Even Xcode allows to command line arguments while running an app.

Pass command line arguments - `ScriptPath.py arg1 arg2`
Access command line arguments - `sys.argv` (1st item in the list is name under which the program was invoked, after that the remaining items are all the passed command line arguments.)
