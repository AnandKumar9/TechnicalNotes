There are 4 kinds of functions in Python.

1. Global functions
2. Local functions
3. Lambda functions
4. Methods

Global objects (including functions) are accessible to any code in the same module (i.e., the same .py file). But then, they can also be accessed from other modules.

Local functions (also called nested functions) are functions that are defined inside other functions. These functions are visible only to the function where they are defined

Lambda functions are expressions, so they can be created at their point of use.

Methods are functions that are associated with a particular data type and can be used only in conjunction with the data type.

Lambda functions -

These are short inline functions created using the following syntax.
lambda parameters: expression

```
s = lambda x: "" if x == 1 else "s"
print(s(5))
```

What this means is that the name of function is s and it takes one argument called x.

Lambda with multiple arguments.
```
lambda2 = lambda x, y: 9
print(lambda2(1, 2))
```

Functions' syntax -

```
def func1(parameter1, parameter2, parameter3 = defaultValue):
  ...
```

It is not allowed to have parameters with no default value positioned after parameters with default value.


While calling names can also be used. Both the below are valid.

```
func1(3, 2)
func1(parameter1 = 3, parameter2 = 4)
```

When are the default arguments created -

When default values are given they are created at the time the def statement is executed (i.e., when the function is created), not when the function is called. This does not matter when the default argument is something immutable like string, but does matter when its something mutable like an array.

```
def func1(parameter1, parameter2 = []):
```

With this what will happen is that the list is created well before function is called. And that it not really what you want. For it to be truly created when invoked, the signature needs to be like this.

```
def func1(parameter1, parameter2 = None):
```

Sequence unpacking operator in functions' declartion -

Sequence unpacking operator (`*`) can also be used in a function declaration. When used this way, all the corresponding parameters passed to the function are treated like a tuple.

```
def func1(*args):

def addItems(alphabet, *args):
    print(alphabet, sum(args))

addItems('A', 1, 2, 5)     # Prints A 8
```

If however the arguments were to be accessed using keywords, then even that can be done by having the function declaration specify `**`. Conventionaly, the argument is called `kwargs` (keyword args).

```
def add3(alphabet, **kwargs):
    sum = 0
    if kwargs is not None:
        for key, value in kwargs.items():
            sum += value
    return sum

print(add3('B', first = 1, second = 2))     # Prints B 3
```

Mandating positional arguments while calling -

It is also possible to use * as a parameter by itself. This is used to signify that there can be no positional arguments after the `*`, although keyword arguments are allowed.

```
def func1(parameter1, parameter2, *, parameter3):

func1 (1, 2, 3)                    # This will not compile
func1 (1, 2, parameter3 = 'ABC')   # This will compile
```

Positional argument are those which do not have a name specified during invocation.

Mapping unpacking operator while calling -

`**` is mapping unpacking operator that can be used on mapping types (i.e. dictionaries) while calling a function. So what it does is that it automatically treats the passed dictionary's keys as arguments name. The dictionary keys do need to be exact though, in fact it should not even have an extra key.

```
def add1(a, b):
    print(a, b)

add1(**dict({"a" : 1, "b" : 2}))        # Prints 1 2
add1(**dict({"b" : 1, "a" : 2}))        # Prints 2 1

add1(dict({"a" : 1, "b" : 2, "c" : 3})  # This will not compile
add1(dict({"a" : 1})                    # This will not compile
```

Generator functions -

A generator function is something that returns an iterator object (rather a generator iterator object). Syntactically it looks pretty much like a usual function but instead of using the `return` keyword it used the `yield` keyword.

An yield expression can be used only within the function body of a genrator function.

```
def quarters1(next_quarter = 0.25):
    while True:
        yield next_quarter
        next_quarter += 0.25

for quarter in quarters1():
    print(quarter)
    if quarter == 1.0:
        break
```

The above example prints 0.25, 0.5, 0.75, 1.0.

Generators provide lazy evalauation and hence are particularly useful when a large list needs to be iterated.


Now apparently a generator object can also be sent a value. This can be used to stop the generator object.

```
def quarters2(next_quarter = 0.25):
    while True:
        received = yield next_quarter
        if received is None:            # If nothing is sent to generator using send() methods, this succeeds.
            next_quarter += 0.25
        else:
            next_quarter = received

result = []
generator = quarters2()
while len(result) < 6:
    x = next(generator)
    if x > 1.0:
        x = generator.send(100.0)
    result.append(x)
```

This prints [0.25, 0.5, 0.75, 1.0, 100.0, 100.0].


Generator expressions -

A generator expression is syntactically lot like list comrehensions (they use `()` instead of `[]`). Semantically they are like generators, i.e. they are more memory efficient but are not as powerful (probably they do not respond to send(), etc.).

```
gen_exp = (x ** 2 for x in range(10) if x % 2 == 0)
for element in gen_exp:
    print(element)
```

In very simple terms, from what I have understood so far coroutines are functions that allow repeated inputs. Its like generator functions, but whereas generator functions provide data coroutines consume data.

```
def grep(pattern, identifier):
    print("Coroutine now running)
    while True:
        line = (yield)                        # This fetches the sent argument.
        if pattern in line:
            print(identifier, line)

search = grep('coroutine', "A")               # Initializes the coroutine, nothing has been run yet
next(search)                                  # The coroutine now runs. Prints "Coroutine now running"
search.send("I love you")                     # Does not print anything as the input does not match the pattern
search.send("I love coroutines instead!")     # Prints "A coroutine". Identifier passed earlier verifies its same coroutine.
search.close()                                # Closes the coroutine
```

Decorators -

Think of decorators as something that can augment several functions in a single shot. Say there are several somewhat related functions all of which need to be modified in the same way. Now instead of adding the relevant code in all of them, the code can be just put in a decorator function and then all the necessary functions can be prefixed with the decorator.

```
def positiveNumber(function):

    @functools.wraps(function)
    def wrapper(*args, **kwargs):
        result = function(*args, **kwargs)
        if result > 0:
            return result
        else:
            return "Not a positive number"
    return wrapper

@positiveNumber
def func1(x):
    return x

@positiveNumber
def func2():
    return -2

print(func1(5))     # Prints 5 Not a positive number
print(func2())      # Not a positive number
```

So the way decorators work is that they define a local function which in turn calls the original function and this local function is then returned by it. Now anytime say func1() is called, Python probably automatically looks at the decorator qualifier and invokes the wrapper function instead passing to it the same arguments as those passed to func1().

By the way, functools.wraps is probably something that makes the name and docstring of the decorated function available to the wrapper function during runtime. This helps with introspection.

In fact its even possible for the decorator function itself to take more arguments of its own. This is how it is done.

```
def positiveNumberAugmented(a, b):

    def decorator(function):
        def wrapper(*args, **kwargs):
            result = function(*args, **kwargs)
            if result > 0:
                return result + a + b
            else:
                return "Does not give a positive number"
        return wrapper
    return decorator

@positiveNumberAugmented(1, 2)
def func4():
    return 5

print(func4())     # Prints 8 (i.e. 5 + 1 + 2)
```

Function annotations -

Function annotations can be used for providing documentation for the function. They are mainly used by static analyzers such as linters, code completion libraries and IDEs. All the documentation is also made available in an `__annotations__` dictionary. The annotation should be provided with colon.

```
def func6(x: "An annotation for you") -> bool:
    print(x)

print(func6.__annotations__)      # Prints {'x': 'An annotation for you', 'return': <class 'bool'>}
```

The last positional parameter can be of the form `*args`, with or without an annotation; similarly, the last keyword parameter (if present) can be of the form `**kwargs`, again with or without an annotation.

Partial functions -

It is possible to have a short synatx for creating a new function from an existing function by reducing its arguments. The same thing always gets passed to the unexposed argument.

def func1(x1, x2):
    print(x1 + x2)

func1Partial = functools.partial(func1, x2 = 0)

func1Partial(1)                    # Prints 1. Also the second argument cannot be passed.
