Initializer method -

There already exists a default dunder initializer.

```
class Point:
  def __init__(self, x = 0, y = 0):
    self.x = x
    self.y = y
```

The Point class now automatically has two attributes named x and y.

The self argument is automatically provided by Python while initializing.
a = Point(3, 4)

All object attributes (data and method attributes) must be qualified by self.

`__init__()` is the initializer. `__new()__` is what creates the object. While init() usually needs to be implemented, new() seldom needs to be implemented.

Inside an init, it is usually advisable to call the super's init but the default implementation of object (the default base class here) init does not do anything and hence super has not been called in the above example. If it were to be called though, its called like this.

Methods for comparison operators -

Python provides special methods for all the comparison operators.
```
__lt__(self, other)     x < y
__le__(self, other)     x <= y
__eq__(self, other)     x == y
__ne__(self, other)     x != y
__ge__(self, other)     x >= y
__gt__(self, other)     x > y
```

All instances of custom classes support == by default, and the comparison returns False—unless we compare a custom object with itself. `__ne__()` (not equal) inequality operator (`!=`) too is implemented automatically if a custom implementation is not provided.

While writing any of the above methods it is also possible to return `NotImplemented`, if the comparison is not supportable. And if this is returned, Python automatically raises a `TypeError` exception.

str(), repr(), format() methods -

repr() is another method used to get a expression that describes the class. The passed expression is then evaluated using eval() function to see if it can be converted to a string (apparently most can be). And if it cannot be converted to a string, then something else is done (what?).

```
def __repr__(self):
     return "The point is at {}, {}".format(self.x, self.y)
```

str() function works like the repr() function, except that it calls the object’s __str__() special method. The result is intended to be understandable to human readers and is not expected to be suitable for passing to the eval() function.
```
def __str__(self):
     return "Its a point"
```
Apparetly str() takes precedence over repr().


There is also format() which takes a single object and an optional format specification and returns a string with the object suitably formatted.
```
def __format__(self, format_spec):
   return format(self.__value, format_spec)
```

Access control -

Making a method accessible using attribute syntax -

If a method is qualified with property decorator, it becomes accessible using attribute syntax.

In fact if just left as below, it will be accessible only as a read-only attribute.

```
@property
 def sum(self):
     return self.x + self.y

print(a.sum)      # Not a.sum()
```

The @property part is actually called decorator function. Probably any @<something> before a function definition is called a decorator function.
The effect of using @property is the same as calling the property() function with just one argument, the getter function. (Need to understand this better.)

Sttaic methods and class methods -


Static methods -

Usually every other method while calling should have self as first argumnt, however this can be skipped by using staticmethod decorator. Static methods are simply methods that do not get self or any other first argument specially passed by Python. Howvere their use is considered to be un-Pythonic.

```
@staticmethod
  def func2():
      print("func2")

a.func2()
```

Class methods -

Class methods are set up by using the built-in classmethod() function decorator. Their first argument is automatically added by Python and it is the method’s class.

```
@classmethod
  def func3(cls):
      print("func3")

Point.func3()
```

Even though new() is a classmethod, if at all implemented it need not be given a classmethod decorator as Python already knows that this method is always a class method.

Accessing attributes -

While attributes are usually accessed with simple dot notation, they can be overridden in several ways. There are some builtin methods that help achieve this.

`__getattr__` - If implemented, this method is invoked only if the attribute does not actually exist. So this does not override the usual value and this is the getter method that should usually be implemented (if at all).

`__getattribute__` - If implemented, this method is invoked even if the attribute actually exists and hence can override the usual value.

`__setattr__` - If implemeted, overrides the setting of an attribute's value.

`__delattr__` - Overrides deletion of an attribute, i.e. when something like 'del x.attr1' is called. So probably can be used to block some deletions, etc. So attributes can be deleted too (just like variables), and on doing so they should not be accessed after the deletion.

__dir__ - Returns all the attributes and its values (if the class does not have slots)

Slots -

Slots is a way to fix the attributes that a class can have. If a class has slots defined, only the entries in the slots are allowed as the class's attributes and new arbitrary attributes cannot be added from any of its methods (even init).

```
class Song:
    __slots__ = ("name")

    def __init__(self, name):
      self.artist = "Need an artist"       # This will not compile as slots does not have an entry for such an attribute
      self.name = name
```

And any class that has slots, does not get the `__dict__` dictionary which all its attributes and its values.

By default, all instances of custom classes are hashable, so hash() can be called on them and they can be used as dictionary keys and stored in sets. But if __eq__() is implemented, instances are not hashable. Something more needs to be done to make them hashable.

Polymorphism is the fact that any object can be used as though it were an object of any of the class's base classes.

If they still need to have same names, then the only way is to have the class in a different module from the file where the instance of that class is created. That way there is no ambiguity.
