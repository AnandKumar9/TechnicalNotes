
The if-else construct -

```
if varA == 3:
  ...
elif varA == 20:
  ...
else:
  ...
```

Simple conditons can be concisely written in one line. A lot like ternary operators in other languages.

```
expression1 if boolean_expression else expression2
varB = 10 if varA == 1 else 20
```

while loop construct -

```
while boolean_expression:
  ...
else:
  ...
```

There is an optional else portion too which fires when the boolean expression turns false. So it runs even if the while loop has run all its iterations as the condition will become false at some stage.
If however the loop is broken out of due to a break statement, or a return statement (if the loop is in a function or method), or if an exception is raised, the else clause’s suite is not executed.

while loop construct -

```
for expression in iterable:
  ...
else:
  ...
```

Here too there is an optional else part. If the loop runs to completion it terminates, and any else suite is executed. If the loop is broken out of due to a break statement, or a return statement (if the loop is in a function or method), or if an exception is raised, the else clause’s suite is not executed.

Exception handling -

General syntax -

```
try:
    ...
except ValueError as err:
    ...
else:
    ...
finally:
    ...
```

There must be at least one except block, but both the else and the finally blocks are optional.

The else suite is executed when the try block’s suite has finished normally but it is not executed if an exception occurs. So semantically its an 'else' for 'except'.

The finally block is always executed at the end.


Catching exceptions (Misc.) -

When multiple except blocks are provided, they must be ordered from most specific (lowest in the hierarchy) to least specific (highest in the hierarchy). Only the first matching exception suite is run. To match an exception group, the exception must be of the same type as the (or one of the) exception types listed in the group, or the same type as the (or one of the) group’s exception types’ subclasses.

It is usually bad practice to use except Exception since this will catch all exceptions and could easily mask logical errors in our code.
except Exception:

Just except: can also be written. An except block like this will catch any exception, including those that inherit BaseException but not Exception. This too should never normally be done.

If none of the except blocks matches the exception, the program is terminated.

A rather pointless try...finally is also possible where the finally always executes after try, unless the program terminates due to an exception in try.
```
try:
  ...
finally:
  ...
```

Raising exceptions -

There are 3 syntaxes for raising exceptions.

	1. raise exception(args)
	2. raise exception(args) from original_exception       # Raises a chained exception that includes the original_exception exception
	3. raise                                               # Re-raises currently active exception, if none raises a TypeError exception

Creating a custom exception -

Any custom exception should inherit Exception class.

class exceptionName (baseException): pass

Throwing assertions -

assert boolean_expression, optional_expression

assert (count > 0), "The count should be greater than 0"

If the boolean_expression evaluates to False an AssertionError exception is raised. If the optional optional_expression is given, it is used as the argument to the AssertionError exception—this is useful for providing error messages.
