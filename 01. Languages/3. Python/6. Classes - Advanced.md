Functors and Closures -

Functors -

Functors are special classes that have implement the __call__ special method. The thing about these classes is that an instance created for them can itself be treated like a function. Now as being classes they can have some state using attributes, these functions themselves can make use of the state. So that is what makes them unique.

classTrimCharacters:

	def __init__(self,characters):
		self.characters=characters

	def __call__(self,stringToStrip):
		return stringToStrip.strip(self.characters)

trimVowels = TrimCharacters("AEIOU")
print(trimVowels("AEBCDU"))                # Prints BCD

Closures -

The same thing as functors can be achieved using closures. They are indeed a lot like Swift closures, i.e. functions that can capture state. But can they be passed around too like Swift closures (guess they can, as Python functions themselves can be passed around as references).

def makeCharactersTrimmer(characters):
    def trimmer(string):
        return string.strip(characters)
    return trimmer

vowelsTrimmer = makeCharactersTrimmer("AEIOU")
print(vowelsTrimmer("AEBCDU"))             # Prints BCD

In general, closures are used lot more than functors.

Context managers -

Any class that has the special methods enter and exit implemented is called a context managers. They are almost like the init and deinit methods of Swift classes. enter gets called when the instance has been initialized and exit get called when the instance has gone out of scope.

Any class, etc. which is a context manager can be used like this. In fact the enter and exit methods too fire only when the context manager is is invoked in a 'with'.

with expression as variable:     # The as part is optional
     suite

class File():

    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        self.open_file = open(self.filename, self.mode)
        return self.open_file

    def __exit__(self, *args):
        self.open_file.close()


for _ in range(10):
    with File('foo.txt', 'w') as infile:
        infile.write('foo')


Many of Python's built-in types are context managers. File object returned by open() is a context manager and is in fact a commonly used example. Many of the threading related classes too are.

Context managers also typically do not need a finally block because they are guaranteed to execute their “exit” code (even in the face of exceptions). Need to test this.

Descriptors -

Descriptors allows to control attributes access of one class from another class. However for this you still need to have access to the source code of the first class. (What real purpose does it then serve?).

So the way to do it is to implement any of the special methods __get__, __set__, __delete__ for a class. Such a class is known as descriptor class. And then the real class should just have an attribute directtly initialized with this descriptor class. In fact that class can even have an empty slots to ensure that it should not have any other attribute.

class DescriptorA:

    def __init__(self):
        self._name = ''

    def __get__(self, instance, owner):
        return self._name

    def __set__(self, instance, name):
        self._name = name.title()

    def __delete__(self, instance):
        del self._name

class PersonA:
    __slots__ = {}
    name = DescriptorA()

It can also be made lot more dynamic where the attributes are set, fetched using getattr() etc.

The entire thing can also be achieved using attribute accessors (i.e. getattr, etc.) and even with fget, etc. , methods. What then is the great benefit of using descriptors. In fact, it seems that they are actually not used that much.

Class Decorators -
Just like a decrators can augment functions, a class decorator can augment classes. A most common example is using class decorator to implement singleton classes.

def singleton(cls):
    instances = {}

    def get_instance():
        if cls not in instances:
            instances[cls] = cls()
        return instances[cls]

    return get_instance

@singleton
class ClassA(object):
    pass

print(id(ClassA()))     // Prints some id
print(id(ClassA()))     // Prints the same id as above

So there needs to be a function that somehow returns a function (get_instance above) taht returns a class. And then the top level function can be added as a qualifier to the classes it should augment. In the above example, every class this decorator is added to becomes a singleton.

Abstract Base Classes -

In Python, ABCs are actually primarily used to specify interfaces (like Swift protocols). The derived classes must provide implementations for the abstract methods and properties of the inherited ABC.

Even though its syntactically not mandated, as a common practice an ABC should have at least one abstract method or property. If however the ABC does not have any abstract method or property, it can in fact be directly instantiated. Whereas if it does have any abstract method or property (as is usually the case), then they must be reimplemented by its derived classes and only those derived classes can be instantiated (not the ABC itself).

Any method in the ABC can be made to have no implementation by using the keyword pass. if it is also marked as abstract, then the derived class needs to implement it. Any concrete method in an ABC (i.e. a method that is not marked as abstract), can obviously be overridden in a derived class. And then the overriding implementation can call the super's implementation if needed.

All ABCs must have a metaclass of abc.ABCMeta (need to check this), or must be derived from one of its subclasses (even ABC itself).


from abc import ABC, abstractmethod, abstractproperty

class AbstractClassExample(ABC):

    def __init__(self, value):
        self.value = value
        super().__init__()

    @abstractmethod
    def do_something(self):
        pass

    def func1(self):                  # As this is not an abstract method, it need not be overridden
        pass

class DoAdd42(AbstractClassExample):

    def do_something(self):
        return self.value + 42

print(DoAdd42(10))                    # Prints 52


There are plenty of builtin ABCs, especially in numbers and collections modules. Number, Complex, Callable, Hashable, Set, etc.

Multiple Inheritance -

The reason multiple inheritence is often avoided is that if the same method is present in two inherited classes, then you are not sur which one will be used. Its resolved using Python's method resolution order which probably is not exactly known.

Here are various ways in which multiple inheritance can be avoided when needed.

1. Use single inheritance and have a metaclass for any additional API. A metaclass can be used to give the promise of an API without actually inheriting any methods or data attributes.
2. Use multiple inheritance with one concrete class and one or more abstract base classes for additional APIs.
3. Use single inheritance and aggregate instances of other classes.

(How to implement each of these?).

If it still needs to be implenented though, don't just simply call super for any overridden method. Especially, when multiple super classes may have that method, only call what is necessary and in the right order.

Metaclasses -

A custom metaclass is one that inherits type (not object). And then any other class can have this custom metaclass as its metaclass, doing so automatically lets it have the attributes and methods of the metaclass.

So metaclasses allow to specify a type with a certain interface. And then any other type can be made to have that interface by spcifying its metaclass. in a way its like using ABCs to specify interface, and its indeed commonly documented that metaclasses are barely used.

Creating a metaclass -
It should inherit type and well probably should have its init implemented.

class InterfaceMeta(type):

    def __new__(cls, name, parentClasses, dictAttributesMethods):

        if 'class_id' not in dct:
            dct['class_id'] = name.lower() + "-id"                             # Create/update attributes and methods

        return super(InterfaceMeta, cls).__new__(cls, name, parents, dct)      # This actually creates the type


Registering the metaclass with a custom class - (In Python 2, the syntax is slightly different.)

class Interface1(object,metaclass=InterfaceMeta):
	filename = dct['file']

print(Interface1.class_id)                                         # Prints Interface-1


It could also be achieved this way, though this does not exactly make InterfaceMeta as the metaclass of Interface2.

Interface2 = InterfaceMeta('Interface1',(),dict(file='tmp.txt'))

print(Interface2.class_id)                                         # Prints Interface-2
