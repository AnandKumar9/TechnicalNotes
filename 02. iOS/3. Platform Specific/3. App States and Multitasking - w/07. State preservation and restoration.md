You indicate to UIKit which view controllers and views you want to preserve by assigning them restoration identifiers and UIKit then does the hard work of saving the necessary data to an archive file. However, this does not concern persistence of any application related data, for which Core Data, user defaults, etc. should continued to be used.

The state restoration process works only if the system itself terminates the app. If the app is force quitted from the recently used apps list when it has still not been terminated by the system, the state restoration does not work when the app is launched again. This is because the state preservation data is deleted if the user force quits the app (and also when the restoration process fails) as well as once app is launched (as the same data should not be used in a later launch).

application:willFinishLaunchingWithOptions: method is called before state restoration is performed and application:didFinishLaunchingWithOptions: method is called after any state restoration has occurred. Any state initialization should be performed before state restoration occurs as things such as data model, etc. might be needed during the restoration process. application:willFinishLaunchingWithOptions: is available only iOS 5 onwards.

**********

For state preservation and restoration to be applicable for an app, the following is necessary.

1. App should opt-in for this feature.

This is done by implementing application:shouldSaveApplicationState: and application:shouldRestoreApplicationState: UIApplicationDelegate methods. If these methods return YES, the state preservation and restoration is done. If for any reason, it should not be done then these methods can be made to return NO. There can be any reason for this, such as restoration not being desirable when the last time the app launched was an older version with a different UI.

2. Each view controller or view to be preserved must have a restoration identifier assigned.

If any view controller or view does not have a restoration identifier, it is not preserved. This can be set in storyboard or xib files. In case the view controller is initialized from the code, it can be configured in the code as well using the UIViewController property restorationIdentifier. They should be used for tab bar controllers and navigation controllers too. Typically in case of table view controller, the restoration identifier must be given to the table view controller as well as the table view in it.

The sequence of restoration identifiers (restoration path) while navigating to a screen must be unique for the restoration to be successful. Also, if a view controller does not have a restoration identifier, that view controller and all of its views and child view controllers are not preserved even if any of the child view controllers has a restoration identifier.

**********

In case of table views and collection views, there is a special protocol called UIDataSourceModelAssociation that can be used. It provides methods which if implemented, allow UIKit to automatically preserve and restore the scroll position and selected cell. No separate code needs to be written to manually set the scroll position or show a cell as selected. This protocol should be implemented by the same object that provides the table view and collection view datasource methods.

One of these methods (modelIdentifierForElementAtIndexPath:) should provide a unique identifier for every index path. This method is automatically called when the system tries to save the state. The other method (indexPathForElementWithModelIdentifier) should return the appropriate index paths when an identifier is passed to it. This method is called when the system tries to restore the state during app launch. None of these methods should be explicitly called in the code.

**********

In case of web views if they have restoration identifier assigned URL history, the scrolling and scaling position for each page and some more information about the page is automatically preserved and restored by UIKit.

For tab bar controllers and navigation controllers, things such as selected tab and current view controller are preserved and restored by UIKit.

**********

In case of a view controller that supports state restoration (as it has a restoration identifier) that is not being launched from the storyboard or a xib file but from code, then either it must have a restoration class or the restoration process must be handled in the app delegate where viewControllerWithRestorationIdentifierPath: method is called if the restoration class is not found.

Restoration class is a class that implements the UIViewControllerRestoration protocol. The only method in this protocol is
viewControllerWithRestorationIdentifierPath:coder: and it should return the view controller in its desired restored state. restorationClass is a property of UIViewController.

Also, UIStateRestoring protocol is implemented by UIViewController. It has two methods (encodeRestorableStateWithCoder:, decodeRestorableStateWithCoder:) which are called by the system while encoding in preservation and while decoding during restoration. These methods must never be explicitly called in the code, however if needed they can be overridden and in the overridden implementation their super implementation must be called eventually. This is often needed when any custom data needs to be encoded/decoded as well (although it is not a good practice to use restoration coder for storing any data.)

There are certain keys that are available in restoration archives which can tell which was the app version on which the preservation was done (UIApplicationStateRestorationBundleVersionKey), when was it preserved, etc. These are known as system restoration keys and are available in the app delegate shouldRestoreApplicationState: method.

**********

UIKit writes the preservation related data to an an encrypted on-disk file. As this file is encrypted, state preservation as well as restoration occurs only when the device is unlocked.

It is often advisable to encode version number of an app and preserve it with rest of app’s data. This can be done in application:willEncodeRestorableStateWithCoder: method of app delegate.

Even if a view controller is not preserved due to any reason (such as a parent view controller not having a restoration identifier), it can still be encoded (using NSCoder?) and preserved manually. These could be later used for manual restoration.

Following UIKit views have state information that can be automatically preserved - UICollectionView, UITableView, UIWebView, UIScrollView, UIImageView, UITextField, UITextView.
