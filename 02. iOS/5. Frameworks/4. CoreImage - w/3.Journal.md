Creating a context using OpenGL and drawing the output directly to UI -

Creating a CGImage from CPU only to draw it back on UI is still a wasteful way of doing the drawing. Its better to do it without having to go through CoreGraphics (i.e. CGImage). This in fact can be achieved as OpenGL and Core Image are interoperable. 

To share resources between an OpenGL context and a Core Image context, CIContext should be created in a different way (not through init(options:)).
let eaglContext = EAGLContext(API: .OpenGLES2)
let ciContext = CIContext(EAGLContext: context)

A EAGLContext can be used as the backing context for a GLKView or for drawing into a CAEAGLayer.

When a CIContext has an associated OpenGL context, a filtered image can be drawn with OpenGL using the following call. (Note how the method says drawImage and not createImage as in the previous approach.)
ciContext.drawImage(filter.outputImage, inRect: outputBounds, fromRect: inputBounds)

The inRect parameter is the rectangle in the coordinate space of the GL context into which the image should be drawn. If you want to respect the aspect ratio of the image, you may need to do some math to compute the appropriate inRect.

Forcing Core Image to always run on CPU instead of GPU -

Whenever possible, Core Image performs filtering on the GPU. However, it does have the ability to fall back to the CPU. Filtering done on the CPU may have better accuracy, since GPUs often exchange some fidelity for speed in their floating-point calculations. Core Image can be forced to run on the CPU by setting the value of the kCIContextUseSoftwareRenderer key in the options dictionary to true when creating a context. You can determine whether a CPU or GPU renderer is in use by setting the CI_PRINT_TREE environment variable to 1 in the scheme configuration in Xcode. This causes Core Image to print diagnostic information every time a filtered image is rendered.
