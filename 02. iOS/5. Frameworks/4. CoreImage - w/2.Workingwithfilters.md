Creating a filter -

Creating a new filter of specific type is as simple as this.
let blurFilter = CIFilter(named:"CIGaussianBlur")

The filters have these properties which tell about its inputs, outputs and attributes.
inputKeys, outputKeys, attributes.

For example CIColorControls filter has an entry called inputBrightness in its attributes dictionary. inputBrightness is actually this dictionary.
For numerical parameters, the dictionary will contain kCIAttributeSliderMin and kCIAttributeSliderMax keys, which bound the expected input quantities. Most parameters also contain a kCIAttributeDefault key, which maps to the default value of the parameter.
inputBrightness = {
    CIAttributeClass = NSNumber; CIAttributeDefault = 0;.. CIAttributeSliderMin = -1; CIAttributeType = CIAttributeTypeScalar;};

Most filter properties are not set directly, but with KVC. So be careful about not setting a wrong property.
blurFilter.setValue(10.0 forKey:"inputRadius")

The actual implementation of each filter (i.e. the kernel) is actually written as a subset of something called GLSL, the shading language of OpenGL and is designed to make the fullest use of the hardware. Also whenever possible, Core Image defers work until the future. Oftentimes, no allocations or processing take place until the output of final filter in a filter graph is actually requested.

Getting all system filters.
let filterNames = CIFilter.filterNamesInCategory(kCICategoryBuiltIn) as [String]
QuartzComposer app is useful for simulating various filters even without coding.

Working with CIImage -

A CIImage is actually a more general entity than a UIImage, since a CIImage may have infinite extent. Obviously infinite image can’t be stored in memory, but conceptually what it implies is that image data can be requested from an arbitrary region in the 2D plane and a meaningful result still received. (What does it really mean?)

Creating a CIImage from a UIImage is very simple.
let inputImage = CIImage(image: uiImage)

Creating a CGImage directly by applying a filter is usually a synchronous method and takes non-trivial time. It should not be done from the main thread.

Applying the filter -

The input image can be set to the filter even before the context is created.
self.filter1.setValue(inputCIImage, forKey:"inputImage")

When the filtering actually needs to be done, that is when a context should be created. And then the filtering can be done using various context methods. They all usually produce the result as CGImage. These methods however are synchronous and take a significant time to process and hence should not be run in main thread.

self.filter1.setValue(inputCIImage, forKey:"inputImage")
self.ciContext = CIContext(options: nil)
let outputCGImage = self.ciContext.createCGImage(self.filter1.outputImage!, fromRect: inputCIImage!.extent)
let uiImage = UIImage(CGImage: outputCGImage)

The reason input image’s extent is used is that the output image often has different dimensions than the input image. For example, a blurred image has some extra pixels around its border, due to sampling beyond the edge of the input image. (Again what does this really mean?)

It would have also been possible to create a UIImage directly from a CIImage (how to do that though?), but this approach has issues. If such an image is displayed in a UIImageView, its contentMode property is be ignored. Using an intermediate CGImage takes an extra step, but does not cause the above issue.

Building a filter graph -

let sepiaColor = CIColor(red: 0.76, green: 0.65, blue: 0.54)

let monochromeFilter = CIFilter(name: "CIColorMonochrome", withInputParameters: ["inputColor" : sepiaColor, "inputIntensity" : 1.0])
monochromeFilter.setValue(inputImage, forKey: "inputImage")

let vignetteFilter = CIFilter(name: "CIVignette", withInputParameters: ["inputRadius" : 1.75, "inputIntensity" : 1.0])
vignetteFilter.setValue(monochromeFilter.outputImage, forKey: "inputImage")
