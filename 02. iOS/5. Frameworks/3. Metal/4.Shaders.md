###### General shader syntax -
<br>
```shaderType returnType shaderName(parmeter1, parameter2, ...)```

******************

Shader types - vertex, fragment, kernel.

Vertex and fragment shaders are needed for graphics programming. kernel probably is only needed for GPGPU programming.

The vertex shader is passed all vertices one by one and they should return the position and optionally the color for each of these vertices. So if needed the shaders can modify the vertex positions before returning.

The fragment shader should return at least a color for the fragment. The return type is usually half4 (a 4-component color value RGBA).

Vertex shader gets run infrequently, but the fragment shader gets run a lot of times.

Keep in mind that shaders run on GPU and putting as much of appropriate code in shaders as possible is what makes the code more efficient.

###### Semantic attributes -

The vertex and fragment shaders have some pre-determined arguments available to them. In C++ (i.e. the language on which MSL is based), semantic attributes are specified using [[ ]] syntax (link). So lets look at below vertex shader declaration.

```
vertex float4 basic_vertex(const device packed_float3* vertices [[buffer(1)]], unsigned int vertexID [[vertex_id]]) {
```
So the vertex qualifier specifies that its a vertex shader.
float4 specfies that it returns the MSL type float4 (a vector of 4 floats).

Now let's leave the first arguments types for now. buffer(x) is a semantic argument as it is specified inside [[ ]]. Indeed buffer(x) is a special attribute that Metal provides, it gives the a pointer to the buffer attached to the render command encoder at index x. Keep in mind that multiple buffers can be attached to a render command encoder using setVertex(:offset:index:) method. So buffer(0) is the first buffer attached to the command encoder, buffer(1) is the second buffer and so on. vertices indicates the name using which the buffer can be accessed in the function.

Now regarding the second argument. Here too [[ ]] indicates vertex_id is a semantic attribute and that it is accessed using the name vertexID. In fact vertex_ID gives the ID of the current vertex being accessed. Keep in mind that the shader function is called once for every vertex.

There are some more semantic attributes that Metal provides to vertex shaders and they can all be found in the MSL specs guide. Some of them are instance_id, base_vertex, etc.

Fragment shaders again have their own semantic attributes.
