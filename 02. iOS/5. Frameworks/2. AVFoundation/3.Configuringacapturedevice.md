###### Session presets

`Resolution` of an image refers to the number of pixels in it. It can either be specified as width and height of the image or as an absolute value. That is either as 2048*1536 or as 314728 (i.e. nearly 3.1 Megapixels). Higher the resolution, better the quality of image.

The `preset` of a capture session can be specified, what it means is that the quality/resolution of the image to be captured can be specified. Here are the possible values.

Following are the available presets.

`AVCaptureSessionPresetHigh` - Default. Gives the highest possible quality if a movie has to be recorded. its said that the resolution depends upon device but I got 1080*1920 in both 6s and 5 (for back camera). <br>

`AVCaptureSessionPresetMedium` - Slightly lower quality, ideal for movie sharing in wi-fi. Its said that the actual values may change (does it mean that in the same movie recording session the resolution of feed may change?). <br>

`AVCaptureSessionPresetLow` - Possibly the lowest quality, meant for movie sharing over cellular data. Here too it is said that the actual value may change. <br>

`AVCaptureSessionPreset640x480` - Corresponds to VGA quality. <br>

`AVCaptureSessionPreset1280x720` - Corresponds to 720p HD quality. <br>

`AVCaptureSessionPresetPhoto` - Gives the best possible photo capture quality. Not available for movie recording. In 6s it is as good as 3024*4032 and on a 5 it is 2448*3264. <br>

`AVCaptureSessionPreset1920x1080` - This is also there (what does the documentation say). <br>

Now the thing is that `AVCaptureSessionPresetHigh`, `AVCaptureSessionPreset1280x720`, `AVCaptureSessionPreset1920x1080` have height/width ratio of 1.78 whereas all other presets have a height/width ratio of 1.33.

Now the aspect ratio of all iPhone screens other than 4s is close to 1.77. That's why if a photo is captured with AVCaptureSessionPresetHigh preset it seems to perfectly fit into the entire screen.

The resolution changes between front and back cameras.

Before setting a session preset, it must be checked that the session can support that preset. Although this is probably not needed for standard presets such as High, Medium, Low (and maybe PresetPhoto too). Its rather needed for size-specific configurations such as AVCaptureSessionPreset1280x720.
```
if self.captureSession.canSetSessionPreset(AVCaptureSessionPresetPhoto) {
	self.captureSession.sessionPreset = AVCaptureSessionPresetPhoto
}
```

Resolution is one of the few things which are configured using a capture session object and not the captured device. In fact, AVCaptureDevice too has a supportsAVCaptureSessionPreset: method and it probably tells the same thing as AVCaptureSession’s canSetSessionPreset: method.

Device specific camera specs [link](https://developer.apple.com/library/content/documentation/DeviceInformation/Reference/iOSDeviceCompatibility/Cameras/Cameras.html)

There is probably another way available to find exact resolutions that a device camera can take (link).


###### Focus mode and point

Capture devices also have a `focusMode` property which is applicable for video capture devices. Before changing it, a lock must be set and it must also be checked whether the desired focus mode is supported by the capture device. For instance the front camera does not seem to support ContinuousAutoFocus mode. Here are the various possible focus modes.

`Locked` - Focus point is locked and does not change after that. Actually feed shows up pretty bad if used.<br>
`AutoFocus` - Focus point is set again instantly and then returns to locked.<br>
`ContinuousAutoFocus` - Default. Focus point is continuously automatically readjusted as necessary. Can be set for the back camera.<br>

```
if let _ = try?self.captureDevice?.lockForConfiguration() {
     let focusMode = AVCaptureFocusMode.ContinuousAutoFocus
     if self.captureDevice?.isFocusModeSupported(focusMode) == true {
          self.captureDevice?.focusMode = focusMode
     }
     self.captureDevice?.unlockForConfiguration()
}
```

> Its difficult to clearly say the difference between these modes, but may be there is truly a change that happens. You can use the `adjustingFocus` property to determine whether a device is currently focusing and it can also be observed using KVO. (link on when to use auto-focus in real cameras)


`focusPointOfInterest` allows to specify the focus point of the capture device. The point is specified in this scale - {0,0} represents the top left of the picture area, and {1,1} represents the bottom right in landscape mode with the home button on the right — this applies even if the device is in portrait mode.

However for it to actually work  the `focusMode`, `exposurePointOfInterest` and `exposureMode` must also be set.

Also, here too the changes must be made in a lock and after checking whether the capture device in question supports focusPointOfInterest top be changed.

```
if let captureDevice = self.captureDevice, let _ = try? captureDevice.lockForConfiguration() 
    let focusMode: AVCaptureFocusMode = .continuousAutoFocus
    let exposureMode: AVCaptureExposureMode = .continuousAutoExposure

    if captureDevice.isFocusPointOfInterestSupported &&
        captureDevice.isFocusModeSupported(focusMode) &&
        captureDevice.isExposurePointOfInterestSupported &&
        captureDevice.isExposureModeSupported(exposureMode) {
        
        captureDevice.focusPointOfInterest = pointOfInterest
        captureDevice.focusMode = .continuousAutoFocus
        
        captureDevice.exposurePointOfInterest = pointOfInterest
        captureDevice.exposureMode = .continuousAutoExposure
        
    }

    self.captureDevice?.unlockForConfiguration()
}
```

Now `AVCaptureVideoPreviewLayer` has a method called `captureDevicePointOfInterest` which converts a point from the video preview layer’s coordinate system to that needed by capture device’s focus point of interest property. It even takes layer’s videoGravity and frame size into consideration. However for this to work, the session should probably already be running. Tested it, it does return the correct point.

```
let self.captureDevice?.focusPointOfInterest = self.previewLayer.captureDevicePointOfInterestForPoint(CGPointMake(40.0, 540.0))
```

> The above did give me a point of 0.83, 0.91 on 6s which indeed represents a point towards the bottom left of the physical device. It is written in the reference that the coordinates of the argument point represent pixel values, however they seem to be work as point values instead.


###### Exposure -

There is something called `exposureMode` as well with the possible values of `Locked`, `AutoExpose`, `ContinuousAutoExposure` and `Custom`. But no change is perceptible yet if I change the values. The default is `ContinuousAutoExposure`. And then there is another property called `exposurePointOfInterest`.

> Focus point of interest and exposure point of interest are mutually exclusive, as are focus mode and exposure mode. (what does it actually mean, is it that one does not affect the other?)

###### Torch and flash -

`torchMode` property allows to turn on the torch always, as needed or never. The default is `never`.

```
if self.captureDevice?.hasTorch == true {
     let torchMode = AVCaptureTorchMode.On
     if self.captureDevice?.isTorchModeSupported(torchMode) == true {
     if let _ = try?self.captureDevice?.lockForConfiguration() {
          self.captureDevice?.torchMode = .On
          self.captureDevice?.unlockForConfiguration()
     }
   }
}
```

`flashMode` property is similar too with the possible values of `On`, `Off`, `Auto`. The default is `Auto`. And there is a `flashAvailable` property too.

It is not necessary if torch is there it will be available too (may be when another app is using the torch).

Back camera has a torch, front camera does not. I also saw when the app I build is running with its camera on, the default torch in device’s control center is disabled. So it is possible for torch to be unavailable when being used by another app.
