##### Bit mask variables and when are they needed

To put it simply bit masks are a simple way to store multiple values in a single variable. The same thing could have been done using a set or array as well, but bit masks are lot more efficient and quicker to work with at processor level.

For example the UIView property autoresizingMask is a bit mask. It can have multiple values at the same time.
```
UIViewAutoresizing - UIViewAutoresizingFlexibleLeftMargin, UIViewAutoresizingFlexibleWidth, etc.
```

##### Bitwise operators to work with bit masks

This is how flags can can be stored in a bit mask variable - (the | operator is called Bitwise OR).
```
view.autoresizingMask = UIViewAutoresizingFlexibleWidth | UIViewAutoresizingFlexibleHeight;
```

For adding another flag (this probably also works if the flag was already added) - (Bitwise OR)
```
view.autoresizingMask |= UIViewAutoresizingFlexibleWidth;
```

For checking if a flag is already added - (Bitwise AND)
```
if (view.autoresizingMask & UIViewAutoresizingFlexibleWidth == UIViewAutoresizingFlexibleWidth) { .. }
or may be simply - if (view.autoresizingMask & UIViewAutoresizingFlexibleWidth) { .. }
```

For toggling a flag (i.e. add if not there, remove if there) - (Bitwise XOR)
```
view.autoresizingMask = view.autoresizingMask ^ UIViewAutoresizingFlexibleWidth;
or simply - view.autoresizingMask ^= UIViewAutoresizingFlexibleWidth
```

For removing a flag if present - (Bitwise NOT)
```
view.autoresizingMask = view.autoresizingMask & ~UIViewAutoresizingFlexibleWidth;
or simply - view.autoresizingMask ~= UIViewAutoresizingFlexibleWidth
```

> References - Swinden blog, Big nerd ranch blog (quite detailed)

The way these operators work are that they take two boolean variables of equal length and then perform the concerned operation on each bit. So it may be that in the case of UIViewAutoresizing as there are 5 possible values (excluding `UIViewAutoresizingNone`), the variable has 5 bits. Every option has a pre-assigned bit position. So say `UIViewAutoresizingFlexibleWidth` has an assigned position of 2nd bit then if a bitwise OR has to be done, then the actual variable is just ORed with 00010. The resulting variable is then certain to have its 2nd bit as 1 which is nothing but `UIViewAutoresizingFlexibleWidth`.

The main trouble with using bit mask variables is that they are often difficult to debug and see in the console. Even the operations are not as readable unless you are used to them. So when performance is not exactly becoming an issue when they are not used, its fine not to use them.

##### Bitwise left and right shift

In addition to above operators there are also bitwise left and right shift operators. They shift all the bits towards left or right by the specified no. of positions.
Hence 11001101 (i.e. 205) `<<` 2 will result in 00110100 (i.e. 52) (though depending on platform it can result in 1100110100, i.e. 820 as there are more bits available and there is not need to truncate) and 11001101 `>>` 2 will result in 00110011 (i.e. 51).
`<<=` and `>>=` perform the shift and then assign the new values to the original variable.

##### NS_OPTIONS

`NS_OPTIONS` is the macro used for creating bit mask variables. It is typedef for an enum with options, i.e. an enum where all the values denote a bit mask. However, the type for options is usually NSUInteger (can it be anything else at all?).

```
typedef NS_OPTIONS(NSUInteger, PhotoVariantOperationError) {
    operationErrorNone = 0,
    operationErrorQuantityPerSKU = 1 << 0,
    operationErrorQuantityTotal = 1 << 1,
    operationErrorPriceTotal = 1 << 2
};
```

For checking if a variable does not have any of the bit masks on, an & cannot be done with operationErrorNone however. Instead an `==` must be done.
```
if (operationError == operationErrorNone) {..}  or if (operationError != operationErrorNone) {..}
```
But not this
```
if (operationError & operationErrorNone) {..}
```

If its a true bit mask, then an `&` can be done.

The reason bitwise shift operators are used instead of straight integers in `NS_OPTIONS` is that if integers were used they would have needed to be assigned as multiples of 2 (i.e. 2,4,8,..) and not as 1,2,3, etc. If it were 1,2,3 the other bit mask operators (such as OR and AND) will not work. ##### Basic boolean logic gates

Some theory, the basic boolean logic gates -

OR - Any one needs to be true
AND - All need to be true
NOT - Negates the current state

NAND - Any one needs to be false (NOT AND)
NOR - Both need to be false (NOT OR)
XOR - Only one should be true, i.e. both should be different (EXCLUSIVE OR)

XNOR (NXOR) - All need to be same (a reverse of XOR)

> The term mask stems from masking tapes which are used to tape portions that should not be painted and are then removed after the painting is done. Similarly in case of bit mask variables, there is often one that is of specific interest and everything else is cleared. For example, a value like 00010 will be used to OR the value in question when 2nd bit is the one of interest.
