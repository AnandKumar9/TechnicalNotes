##### try, catch, throw, finally

`@try` - The code which can throw an error or exception is put in this block. <br>
`@catch` - The flow comes to one of these matching blocks once it gets an exception in the `@try` block. <br>
`@finally` - This block is executed irrespective of the fact an exception is thrown or not. <br>

If a piece of code has been put in a `@try` block, then if the error occurs the code flow is not stopped. It just straight away goes to the `@catch` and `@finally` blocks. The error message is still shown in the debugger console. However, the important thing is that the code execution doesn't get stopped.

A `@try` block must be accompanied by at least one `@catch` block. `@finally` block can be skipped.

There can be several @catch blocks to catch different types of exception. The @catch blocks must be ordered from most-specific to the least-specific.
> Need more clarity on the different types of exceptions that can be there and how they can be caught.

A `@finally` block typically contains clean-up statements.
```
[itemD release];
```

Here are some sample exception handling blocks.
```
@try {
     [itemD showUnexistingDetails];
}
@catch (NSException * e) {
     NSLog(@"Error occured - %@", [e name]);
}
@finally {
     [itemD release];
}
```

##### NSException

A `NSException` object has these instance variables - `name`, `reason`, `userInfo`.

`name` - Returns an NSString object used to uniquely identify the receiver. <br>
`reason` - Returns an NSString object containing a “human-readable” reason for the receiver. (same as what is shown in the debugger console) <br>
`userInfo` - Returns an NSDictionary object containing application-specific data pertaining to the receiver. If there is no application-specific data then the object doesn't contain anything. <br>

Exceptions are resource-intensive and should not be used simply to show errors. This can be done using functions.

Exceptions can also be deliberately thrown using the `@throw` directive.
```
@throw e;
```
`e` is normally an object, but any Objective-C object can be thrown as an exception object.
