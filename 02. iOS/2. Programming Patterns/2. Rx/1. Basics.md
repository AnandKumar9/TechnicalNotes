#### Observable , Event, and Subscription

An `Observable` is something that can emit a sequence of `Events`, which can then be observed by the `Subscriber`. Typically, most things are either an Observable or a Subscriber.

`Events` can be of 3 types - `next`, `completed`, `error`

The closure specified in `subscribe { }` receives all events emitted by an Observable. <br>
Similarly, the closure specified in `subscribe(onNext: { })` receives all `next` events.

#### Creating Observables

There are multiple ways to create an Observable. They can be created using `Observable` as well as `Subject` APIs.

###### Using Subject

`PublishSubject<T>` creates an observable to which new values (of type T) can be added. Subscribers get new events as they happen.

```
private let publishSubject1 = PublishSubject<String>()

subscription1 = publishSubject1.subscribe {
    print("A \($0)")
}
```

`BehaviorSubject<T>` creates an observable to which new values (of type T) can be added. Subscribers get latest event to have happened and new events as they happen. Also, (I think) they need to be initialized with a `next` event.

```
private let behaviorSubject1 = BehaviorSubject<String>(value: Date().description)

subscription1 = behaviorSubject1.subscribe {
    print("B \($0)")
}
```

`ReplaySubject<T>.createUnbounded()` creates an observable to which new values (of type T) can be added. Subscribers get all events to have happened and new events as they happen.

```
private let replaySubject1 = ReplaySubject<String>.createUnbounded()

_ = replaySubject1.subscribe {
    print("D \($0)")
}
```

It's also possible to initialize `ReplaySubject` using `create(bufferSize:)`. With this, likely the subscribers will not get all the events that were emitted in the past but only the last n events.

`BehaviorRelay<T>` is like `BehaviorSubject` in the sense that its subscribers get the latest `next` event as well as subsequent `next` events. However, it cannot be made to emit a `completed` or `error` event. New events are added to it using `accept(:)`.

```
private let behaviorRelay1 = BehaviorRelay<String>(value: Date().description)

behaviorRelay1.accept(Date().description)
_ = behaviorRelay1.subscribe { print("TEST \($0)") }
```

###### Using Observable

`Observable.just()` takes the passed argument and emits that as the solitary next event followed by a `completed` event.
```
private var observable = Observable.just([0,1,1,2,3,5,8]) // Just<Swift.Array<Swift.Int>>
```

`Observable.from()` takes a sequence argument and emits each of its elements as separate events followed by a `completed` event.
```
private var observable = Observable.from([0,1,1,2,3,5,8]) // ObservableSequence<Swift.Array<Swift.Int>
```

`Observable.of()` seems to be doing the same thing as `Observable.just()`. Don't know what is the difference between them.

If these are subscribed to, they then emit all their events to a subscriber. So observable created using they seem to work like `ReplaySubject`.

`Observable.create { }` allows to create an observable where the events to be emitted are specified in the closure itself.
```
private var observable8 = Observable<Int>.create { observer in
    observer.on(.next(5))
    observer.on(.next(4))
    observer.on(.completed)
    return Disposables.create()
}
```

`Observable.deferred{ }` too is similar, in the sense that the observable is created only when someone subscribes to it. Also, every time someone subscribes to it a new observable is created.
```
private let o7: Observable<String> = Observable.deferred {
    return .just("Hi")
}
```

`Observable.empty()` creates an observable that just emits a `completed` event. <br>
`Observable.error(:)` creates an observable that just emits a `error` event. <br>
`Observable.never()` creates an observable that does not emit any event. <br>

#### Adding events that the Observable can then emit

`on(.next(element:))` or `onNext()` add a `next` event to the underlying observable.
```
publishSubject1.on(.next(Date().description))
publishSubject1.onNext(Date().description)
```

`.on(.error)` or `onError()` add a `error` event to the underlying observable.
```
publishSubject1.on(.next(Date().description))
publishSubject1.onNext(Date().description)
```

`on(.completed)` or `onCompleted()` add a `completed` event to the underlying observable.
```
publishSubject1.on(.completed)
publishSubject1.onCompleted()
```

`accept(:)` adds a `next` event to a `BehaviorRelay`.
