Coordinate systems of frame and bounds -

A view's coordinate system's origin is at its top left (unless bounds.origin is something else?) and the axes go right and down. Every subview has also got its own similar coordinate system. (Probably windows also have their own coordinate system.)
Anytime you look at the frame of any view it is shown in its immediate superview's coordinate system. (In below example image view is actually a subview of the xib view)

XIB view frame -
```
<CustomView: 0x7f9ad265a9e0; frame = (94 60; 187.5 237.5); autoresize = W+H; layer = <CALayer: 0x7f9ad265add0>>
```
Image view frame -
```
<UIImageView: 0x7f9ad265b050; frame = (0 0; 187.5 237.5); autoresize = RM+BM; userInteractionEnabled = NO; layer = <CALayer: 0x7f9ad26594f0>>
```

It is true that frame gives the view's dimensions in its superview's coordinate system and bounds gives the view's dimensions in its own coordinate system. Hence the origin part of bounds is usually 0,0 (as that is the default bounds center, though it can be changed).

XIB view frame -
```
<CustomView: 0x7f9ad265a9e0; frame = (94 60; 187.5 237.5); autoresize = W+H; layer = <CALayer: 0x7f9ad265add0>>
```
XIB view bounds - 0.000000 0.000000 187.500000 237.500000

Switching between coordinate systems -

It is possible to get the dimensions (i.e. both origin and size) of a rect in any other view's coordinate system. For that of course the other view needs to be specified and the view using which the rect was originally determined also needs to be specified. Just by itself a rect doesn't know which coordinate system it was originally derived from (its just a struct after all).

There are two variants of the methods. to methods and from methods. In to methods, the receiver view is the view in which the rect was originally determined and the argument view is the view to whose coordinate system the rect needs to be changed. In from methods its the other way round.

The rect methods are convertRect:toView: and convertRect:fromView:.

`convertRect(_: CGRect, toView: UIView?)` method just takes the rect passed in first argument, thinks of it to have been specified in the receiver view’s (or layer’s) coordinate system and then gives a CGRect that would specify the same rect in the view  (or layer) mentioned in second argument. Remember the rect argument is just a value, once passed it is not tied to any view or layer anymore.

`convertRect(_: CGRect, fromView: UIView?)` method is just the opposite. It takes the rect passed in first argument, thinks of it to have been specified in the coordinate system of the view or layer specified in the second argument and then gives a CGRect that would specify the same rect in the receiver view  (or layer).

```
CGRect imageViewRectInRootView = [self.customViewXIB.imageView convertRect:self.customViewXIB.imageView.frame toView:self.view];
NSLog(@"Image view center in root view's system - %f %f",imageViewRectInRootView.origin.x,imageViewRectInRootView.origin.y);
```

```
CGRect imageViewRectInRootViewUsingFromMethod = [self.view convertRect:self.customViewXIB.imageView.frame fromView:self.customViewXIB.imageView];
NSLog(@"Image view center in root view's system using From method - %f %f",imageViewRectInRootViewUsingFromMethod.origin.x,imageViewRectInRootViewUsingFromMethod.origin.y);
```

Similar methods also exist for converting points (`CGPoint`) between coordinate systems. And also there are the same set of methods (fromWindow, toWindow, etc.) to convert to and from the window's coordinate system.

`CGRectIntersection` is CGGeometry function that returns the intersection rect of the two passed rects. Thats it and it does not have anything to do with this or that view’s coordinate system. It takes two rects, assumes that they are in the same coordinate system and gives the intersection rect. If there is no intersection CGRectIsNull is returned.
