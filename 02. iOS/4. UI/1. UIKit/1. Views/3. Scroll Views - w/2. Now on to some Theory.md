UIScrollView automatically provides following functionalities -

1. Allows to scroll over content that does not fit entirely on the screen.
2. Allows zooming with standard pinch gestures.
3. Restricts scrolling to a single screen of content at a time (in paging mode).

To support pinch zoom gestures, the scroll view delegate needs to be set and it should be specified which of the view’s subviews must be zoomed.

contentSize is the size of the content that the scroll view needs to display. contentOffset is what specifies the current visible portion of the scroll view. contentInset specifies a padding area (usually at the top and bottom) around the scroll view thereby giving it more buffer space so that the toolbar and navigation bar do not interfere with the scroll view. ([link](http://joystate.wordpress.com/2014/03/11/contentinset-and-contentoffset-properties-of-uiscrollview/))

When using contentInset, the scroll indicators scroll over the inset as well. To take this into account, scrollIndicatorInsets can be used which is given an appropriate value prevents the scroll indicators from displaying on the inset area.

Only the content size of a scroll view needs to be set programatically. Everything else can be configured from the interface builder. One necessary step is to specify the subviews that the scroll view should have. By default, a scroll view usually already has two subviews, i.e. an image view each for both the scroll indicators.

While supporting zooming as well as when using scroll view in an auto layout, the most common technique is to add a single view to the scroll view and then add all the necessary subviews to that single view. In case of zooming, this allows that single view to be specified as the content to be zoomed and then all its subviews zoom accordingly. In case of auto layouts, this allows the constraints to factor in the scroll view as otherwise a pinning constraint would have just permanently pinned a subview to an edge thereby not allowing a scroll to happen. ([link](http://stackoverflow.com/a/13548039/1135417))

A scroll view’s contents can be scrolled using two gestures. A drag gesture and a flick gesture. A flick gesture doesn’t just do a scroll but also imparts a momentum that causes the scrolling to continue even after the gesture is completed.

As scrolling occurs, the scroll view tracks state using tracking, dragging, delegating and zooming properties.
tracking - YES if user’s finger is in touch with screen.
dragging - YES if user’s finger is in touch with screen and has moved.
decelerating - YES if the scroll view is decelerating as a result of a flick gesture, or a bounce from dragging beyond the scroll view frame.
zooming - YES if the scroll view is tracking a pinch gesture to change its zoomScale property.

viewForZoomingInScrollView: is the delegate method that must mandatorily be implemented for supporting zooming. It should return the view to be zoomed. However there are other things also that should be done.
The permissible amount of zoom can be specified using minimumZoomScale and maximumZoomScale properties. Their initial values are 1.0.
The zoom can actually be performed using any of the following methods. setZoomScale:animated: sets the current zoom scale to the specified value. The zoomToRect:animated: method zooms the content in order to fill the specified rectangle. 

When the content of a scroll view is zoomed, the content of the zoom view is simply scaled in response to the change in the scroll factor. It doesn’t automatically redraw the content. If the application needs the content to be redrawn, more logic needs to be included where the zoomed content is already pre-rendered in small chunks. (This shown in the ScrollViewSuite sample code. But its now a deprecated codebase.) If however the application needs to draw zoomed content real time, Core Animation needs to be used. The UIView class’s layer needs to be changed to CATiledLayer and drawing needs to be done using drawLayer:inContext:.  

For making the scroll view zoom in response to tap gesture as well (in addition to pinch gesture), more work is needed. Custom code needs to be written in viewForZoomingInScrollView: to detect different kid of touches and zoom accordingly. The usual guideline is to have double tap for zooming and the views should have a single level of zoom. However in some cases, such as in Maps app it needs to be differently. Usually in a Maps app, double tap does just one level of zoom in. Some apps even supporting zooming with two finger touch.

The paging mode of scroll view allows user to scroll a single screen worth of content at time. This is useful when displaying sequential content as in eBook or a series of instructions. pagingMode Property must be set to YES. contentSize must be set so as to fill the height of the screen and the width should be width of the screen multiplied by the number of pages to be displayed. The scroll indicator should also be disabled as the scroll position is usually better off shown in a separate page control.

The subviews of a paging scroll view can be implemented in two ways. One way is to draw all the contents at once and include them in the contentSize. However this in inefficient and not recommended especially when the content area is large. Other way is to have multiple views (this is shown in PageControl sample code).

Supporting a large number of pages in a paging scroll view, can be accomplished using only three view instances. One for displaying current page, another for displaying previous page and the third for displaying the next page.

Scroll views can also be nested if needed. A special case is cross-directional scrolling, i.e. when  a scroll view that is a subview of another scroll view scrolls at a 90 degree angle. All this is supported by default and should not require any custom logic.
