Hiding/showing status bar on a per view controller basis -

The 'View controller-based status bar appearance' key in info.plist must be set to YES. The way I think this works is that with this info.plist key being set to YES, the OS checks with every view controller on what its preferred status bar visibility state is. With this overriden computed property, view controllers can have their own preferred state.

override var prefersStatusBarHidden: Bool {
   return true
}

This general approach does not work for view controllers embedded in navigation controller though. For getting it to work for such view controllers, this approach can be used. The property needs to be changed on the navigation controller's navigationBar.

Changing the status bar style on a per view controller basis -

Same as above. The corresponding property to be overriden is preferredStatusBarStyle. In the below example it is set to .lightContent (i.e. white fonts on status bar).

override var preferredStatusBarStyle: UIStatusBarStyle {
    return .lightContent
}

Controlling home indicator appearance in iOS X -

Hide/show home indicator on a per view controller basis. If set to hidden, it isn't that the home indicator is immediately hidden.  Instead it is hidden only if the user does not touch the screen for some time. If he touches the screen, the home indicator becomes visible again (can see this happening in simulator). However even then this property does not provide any gurantee that the home indicator will be shown/hidden. In fact, this should be used only when absolutely necessary.

override func prefersHomeIndicatorAutoHidden() -> Bool {
    return true
}


Inform system that the home indicator show/hide intent should be refetched.
setNeedsUpdateOfHomeIndicatorAutoHidden()

Telling that the home indicator show/hide preference should be dictated by a child view controller.

override func childViewControllerForHomeIndicatorAutoHidden() -> UIViewController? {
	return childController
}

Controlling screen edge gesture recognizer in iOS 11 -

It is possible for a screen edge swipe gesture to be handled by the app and not by the system (for things such as taking user to home screen in X or bringing up control center in other phones). In such a case the first swipe is delivered to app and any immediate second swipe to be delivered to system instead.

Indicating the edges for which first swipe gesture should be delivered to app.

override func preferredScreenEdgesDeferringSystemGestures() -> UIRectEdge {
    return [.top, .bottom]
}


Telling system to refetch the edges for which swipe gesture should be delivered to app.

setNeedsUpdateOfScreenEdgesDeferringSystemGestures()


Telling that the swipe gesture delivery should be dicatated by a child view controller.

func childViewControllerForScreenEdgesDeferringSystemGestures() -> UIViewController {
   return childVC
}
