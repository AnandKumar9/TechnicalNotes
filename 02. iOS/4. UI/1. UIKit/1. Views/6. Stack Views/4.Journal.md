###### Use `arrangedSubviews` for getting contained views

The views in a stack view are truly its subviews. However the `arrangedSubviews` NSArray property has all the views of the stack view and is the right property to use to get the contained views.

The stack view ensures that the `arrangedSubviews` array is always a subset of its subviews array. Therefore, whenever the `addArrangedSubview:` method is called, the stack view adds the view as a subview, if it is not already. Whenever an arranged view’s `removeFromSuperview` method is called, the stack view removes the view from its arrangedSubview array.

> Removing a view from the stack’s array of arranged views does not automatically remove it from the view hierarchy. However, removing the view from the view hierarchy does removes it from the arranged views array.

###### Multi-line labels

Sometimes, if there is a multi-line label in `UIStackView` (i.e. no. of lines is 0 and the line break style is word wrap), even then the no. of lines are not dynamically adjusted until the stack view has a fixed width (i.e. a hardcoded width constraint). (link) This is weird though as stack view’s width may well not be fixed but instead determined by other constraints that you have set. Also, in some situations this issue did not occur (for instance in the Ray Wanderlich Vacation Spot app.)

###### Hiding views and animating if needed

> Stack view take care of its subview views being hidden and automatically take care of adjusting the spacing, overall height, etc.

In iOS, the view’s hidden property is normally not animatable. However, It actually becomes animatable for views as soon as they are placed in a stack’s arranged views array. The actual animation is managed by the stack, not the view.

> Use the `hidden` property to animate adding views to or removing them from the stack.

###### Misc.

`UIStackView` is a non-drawing view, meaning that  `drawRect()` is never called and its background color is ignored. (What is a non-drawing view?)

There can be nested stack views. When working with nested stack views, it is easiest to work from the inside out.

There can be stack views inside a scroll view.

When you embed a view in a stack view, any constraints to other views are removed. Constraints for subviews can still be set if needed. For instance, sometimes a label can have an enormous intrinsic content size, then specific height or width constraint can be set inside it.

In general, you should not use dynamic stack views to simply implement a scratch-built table view clone.

In Xcode 9, `standard` spacing can also be specified for stack views. This probably automatically takes care of subviews' relative sizes and dynamic font sizes as well.
