Just like a table view has sections and rows, a collection view has sections and items. Sections group items together.

A collection view has 3 kinds of UI elements - items (cells), supplementary views, decoration view. Supplementary views are placed just below individual cells (not necessarily) and provide some information regarding the cells. Each cell can have multiple supplementary views associated with it--one for each named "kind". As such, headers and footers are just the beginning of what can be done with supplementary views. Decoration view is (usually?) placed above the entire collection view and is not supposed to have any data regarding the collection view.

Just as in table views, collection views too have datasource and delegate methods. Decoration views in the collection view however do not source their data (i.e. views) from the collection view data source. Having a datasource is mandatory in collection views, but having a delegate is optional.

The items are displayed as per the layout used by the collection view. The collection view layout provided by UIKit, i.e. flow layout is the one that is most commonly used. If at all, the items need to be arranged in a very special way which cannot be done using a flow layout, a custom layout (i.e. a subclass of UICollectionViewLayout) can be created and used.

*************

The layout specifies the attributes of every cell, supplementary view, etc. using layout attributes (UICollectionViewLayoutAttributes). For example, every item has a layout attributes for itself. Following are some of the properties of UICollectionViewLayoutAttributes.

1. indexPath - This is what indicates that an attribute object is for which item.

2. frame - Specifies the frame to be used by the item

3. zIndex - Specifies the item's position on z axis. This property is used to determine the front-to-back ordering of items during layout. Items with higher index values appear on top of items with lower values. This property is handy when there can be multiple items having the same frame.

4. transform3D - Specifies the 3D transform of the item.

For creating a new UICollectionViewLayoutAttributes object, a class constructor such as layoutAttributesForCellWithIndexPath: should be used. Do not use new or alloc init.

*************

While creating custom layouts, the below methods of UICollectionViewLayout must be mandatorily overridden.

1. layoutAttributesForElementsInRect: - It should return the layoutAttributes of all the cells and views in the specified rectangle. 

2. collectionViewContentSize - It should return the size (CGSize, i.e. height and width) of the entire collection view's content, not just the content that is currently visible. This returned size is also used by the collection view to configure the scroll view and its scroll directions appropriately. (Unlike flow layout, a custom layout does not have only one direction set as the scroll direction automatically.)

3. layoutAttributesForItemAtIndexPath:

4. prepareLayout - Need not be mandatorily implemented, but usually is. The default implementation does not do anything. It can be overridden to do any preparation or set up that needs to be done before the layout is updated. The layout is updated when the collection view is rendered for the first time or when it gets invalidated for any reason. Normally this is the method where the layout attributes for the elements are calculated and kept. (When the layout is not likely to change frequently and hold hundreds of items, it is recommended to calculate the layout information of all the items upfront (i.e. create a cache) and then access them whenever the collection view requests it.)

5. shouldInvalidateLayoutForBoundsChange - Need not be mandatorily implemented. Indicates if the layout should be invalidated anytime the collection view’s bounds change, i.e. when a scroll is done. By default, it returns NO.
When a collection view layout could be rendered from code or from a xib, then it is better to invoke the initial set up code from both init and initWithCoder: methods.

invalidateLayout should be called if any of the custom properties of a collectionViewLayout has changed and the collection view should be rendered again as per the new values. Invalidating a layout however does not animate the items, the changes are reflected in the UI without any animation. Also, invalidateLayout does not begin the layout process immediately.The layout process begins only in the next update cycle. Hence, the invalidateLayout method can be called multiple times in quick succession without triggering an immediate layout update each time.

Collection views can have three types of reusable view subclasses in their layout - Cells, Supplementary views, Decoration views.

Flow layout has headers and footers as supplementary views and they are optional. When needed, flow layouts can also be subclassed. One such scenario might be when additional supplementary and decoration views are needed, for which methods such as layoutAttributesForSupplementaryViewOfKind:atIndexPath: can be overridden.

Anytime cells or views are inserted or deleted from a collection view, the layout object needs to know what layout attributes to use for start location (in case of insertion) and end location (in case of deletion) while animating. These initial attributes are provided by overriding methods such as initialLayoutAttributesForAppearingItemAtIndexPath: and finalLayoutAttributesForDisappearingItemAtIndexPath:. prepareForCollectionViewUpdates is a method that is called whenever the contents of collection view are about to change and can be used for doing any kind of setup, etc.

*************

UIView -> UICollectionReusableView -> UICollectionViewCell
UICollectionReusableView denotes all cells, supplementary views, decoration views in a collection view. For cells in particular, a subclass of UICollectionReusableView (UICollectionViewCell) is there.
UICollectionViewCell has a property contentView which is basically what can be used to assign views to it.
UICollectionViewCell also has a prepareForReuse method that can be used to prepare any clean up activity before showing the cell again. The default implementation does not do anything but if it is being overridden the super should still be called. 
prepareForReuse is actually a UICollectionReusableView method and is called for supplementary views too.

registerClass:forCellWithReuseIdentifier: is a UICollectionView method that tells the collection view what class to use for creating a cell of a particular type. registerNib:forCellWithReuseIdentifier: is a similar method and tells what nib file to use instead. Either of these two methods must have been called before dequeueReusableCellWithReuseIdentifier:forIndexPath: for that identifier is called.

indexPathsForVisibleItems returns an array of visible items in the collection view. It does not include any supplementary views that are currently visible.

The dequeueing process in collection views always returns a valid view, either by really dequeueing a view or by creating a new view.

*************

Collection view cells are registered with just a reuse identifier, but for registering supplementary views and decoration views another identifier called kind string is also needed. In collection views, the layout is responsible for defining the kinds of supplementary views and decoration views it supports. UICollectionViewFlowLayout class supports two kinds of supplementary views - section header view (UICollectionElementKindSectionHeader) and section footer view (UICollectionElementKindSectionFooter).

registerClass:forSupplementaryViewOfKind:withReuseIdentifier: is the UICollectionView class used for registering the class to be used for creating supplementary views for the collection view.

registerClass:forDecorationViewOfKind: is used for getting the getting the class used for decoration view. Unlike the register methods for collection view cell and supplementary view (which are UICollectionView methods), this is a UICollectionViewLayout method.

collectionView:viewForSupplementaryElementOfKind:atIndexPath: is the UICollectionViewDataSource method used for getting the view to be used for supplementary view for a particular index path.

+layoutAttributesForSupplementaryViewOfKind:withIndexPath: creates and returns a layout attributes object that represents a particular supplementary view.

-layoutAttributesForSupplementaryViewOfKind:atIndexPath: returns the layout attributes for the supplementary view of the specified index path. It must be overridden if the custom layout defines any supplementary views.

+layoutAttributesForDecorationViewOfKind:withIndexPath: creates and returns the layout attributes of decoration view for a specified index path.

-layoutAttributesForDecorationViewOfKind:atIndexPath: returns the layout attributes for the specified index path.
