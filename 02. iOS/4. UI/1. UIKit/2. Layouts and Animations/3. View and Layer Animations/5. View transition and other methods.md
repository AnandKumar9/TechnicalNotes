transition(with:duration:options:animations:completion:) method creates a transition for the specified container view in first argument using the specified options and performs the specified animations. Subviews can even be added, removed, etc. in the animation block. 
If .AllowAnimatedContent option is specified, the animation is done by changing the properties dynamically and drawing or else it is done just using snapshot images.e

```
UIView.transitionWithView(self.view2, duration: 2.0, options: [.TransitionFlipFromLeft], animations: {
                    self.view2.backgroundColor = UIColor.magentaColor()
                    self.view2.center = CGPointMake(150, 150)
                    self.view2.bounds = CGRectMake(0, 0, 100, 100)
                }, completion: {finished in if (finished) {
                }})
```
**********

transition(from:to:duration:options:completion:) method creates a transition as per the specified options where the view in first argument is removed from the superview and the view in second argument is added to the superview. So the animation happens in their common superview (which need not necessarily be the root view). By default the second view replaces the first view in the view hierarchy (but is there a duplicate created if the second view already existed in the view hierarchy). The view transition starts immediately unless another animation is already in-flight, in which case it starts immediately after the current animation finishes.
```
UIView.transitionFromView(self.view1, toView: self.view2, duration: 1.0, options: [.ShowHideTransitionViews, .TransitionFlipFromRight], completion: {finished in
                if finished {
                    self.view2.backgroundColor = UIColor.magentaColor()
                }
            })
```
As the first view is removed, care must be taken not to assume its presence in methods such as viewWillLayoutSubviews as they will be called again.

ShowHideTransitionViews is an interesting argument as it hides/shows the views instead of adding/removing them from the view hierarchy.

**********

`performWithoutAnimation(_:`) is an interesting method in the sense that whatever code is present in its argument is guaranteed to be executed without any animation. So if any code needs to happen when some other animations start, that code can just be put in this method in the animations block.
```
UIView.transitionWithView(self.view2, duration: 4.0, options: [.TransitionFlipFromLeft, .AllowAnimatedContent], animations: {
                UIView.performWithoutAnimation({
                    self.view2.center = CGPointMake(150, 150)
                    self.view2.bounds = CGRectMake(0, 0, 100, 100)
                })
                self.view2.backgroundColor = UIColor.magentaColor()
                }, completion: {finished in if (finished) {
                    }})
        }
```
`perform(_:on:options:animations:completion:)`, i.e. performSystemAnimation is another animation method but its utility is quite unclear. It performs a pre-defined system animation  (at the moment the only possible option is deleting the views specified in second argument) and also in parallel performing any animations specified in the animations argument. Thats it. The duration cannot be specified and is same as that of the system animation in first argument.

The weird part is that the only available option at the moment, i.e. .Delete is not even something that is animated and instead happens right away. Also when I tried it, not just the specified view is deleted but even another view having the same frame got deleted alongside too.

**********

UIViewController too has an animation method called `transition(from:to:duration:options:animations:completion:)` that is very similar to
UIView’s `transition(from:to:duration:options:completion:)` method. It adds the to view controller as a child to the receiver view controller, performs the animation as specified and then removes the from view controller from the receiver view controller’s hierarchy. The completion block is there in the last argument and the animation options (the same UIViewAnimationOptions, i.e. TransitionFlipFromLeft, TransitionCrossDissolve, etc.) can also be specified in another argument.

This method is of course meant only for container view controllers.

Snapshotting API -

`snapshotView(afterScreenUpdates:)` is a UIView method that can be used to create a replica view of any view. The argument specifies if the screenshot should be taken after recent changes have been incorporated.
var view = self.view.snapshotViewAfterScreenUpdates(false)

This method can be used to get a snapshot view for animations where updating a large view hierarchy might be expensive. Because the content is captured from the already rendered content, this method reflects the current visual appearance of the view and is not updated to reflect animations that are scheduled or in progress. But it works faster than trying to render the contents of the current view into a bitmap image yourself and hence can be useful.

resizableSnapshotView(from:afterScreenUpdates:withCapInsets:) is a similar method that also allows to specify cap insets that can be stretched in the resulting view. But what does that mean and how can it be useful.
var view = self.view.resizableSnapshotViewFromRect(self.view.frame, afterScreenUpdates: false, withCapInsets: UIEdgeInsetsMake(150, 10, 10, 10))

drawHierarchy(in:afterScreenUpdates:) creates a snapshot of the passed view’s hierarchy on to the current graphics context which can then be used to apply graphical effects such as blur, etc. It is not as fast as the snapshotting methods but is the recommended way to apply blur or maybe even to get screenshot as a UIImage.

UIGraphicsBeginImageContextWithOptions(self.view.bounds.size, false, 0.0);
self.view.drawViewHierarchyInRect(self.view.bounds, afterScreenUpdates: false)
let viewImage: UIImage = UIGraphicsGetImageFromCurrentImageContext();
UIGraphicsEndImageContext();
