###### Creating layout guide constraints programmatically with the easy API

The documentation says to use `topLayoutGuide` in `viewDidLayoutSubviews` if you are using a UIViewController subclass, or `layoutSubviews` if you are using a UIView subclass. [link](http://stackoverflow.com/a/21688629/1135417)

`self.topLayoutGuide.length` and `self.bottomLayoutGuide.length` in fact do seem to be working from `viewDidLayoutSubviews`, so may be that is the right place to use `topLayoutGuide.length` and `bottomLayoutGuide.length`. Doing it in `viewDidLayoutSubviews` does not cause any wobbliness either. Doing it from `viewWillAppear` returns 0 length and doing it from `viewDidAppear` gives the right length but makes it wobbly.

Both `topLayoutGuide` and `bottomLayoutGuide` are `UIViewController` properties. UIView does not have these exact properties. (But it does have something called layoutGuides, so what is that?). 

They both conform to the `UILayoutSupport` protocol. length is actually a method of this protocol. It indicates the height of these layout guides in points.

###### Creating a constraint to top layout guide
 ```
- (void)viewDidLayoutSubviews {
     NSLayoutConstraint *topConstraint = [NSLayoutConstraint constraintWithItem:self.imageView
                                                                      attribute:NSLayoutAttributeTop
                                                                      relatedBy:NSLayoutRelationEqual
                                                                         toItem:self.topLayoutGuide
	                                                                attribute:NSLayoutAttributeBottom
                                                                     multiplier:1.0
                                                                       constant:0];
     [self.view addConstraint:topConstraint];
     [self.view setNeedsLayout];
}
 ```

###### Making a subview's height proportional to the distance between top and bottom layout guides
 ```
CGFloat visiblePortionLength = (self.view.frame.size.height - [self.topLayoutGuide length] - [self.bottomLayoutGuide length]);
NSLayoutConstraint *heightConstraint = [NSLayoutConstraint constraintWithItem:self.imageView
                                                                    attribute:NSLayoutAttributeHeight
                                                                    relatedBy:NSLayoutRelationEqual
	                                                                 toItem:nil
                                                                    attribute:NSLayoutAttributeNotAnAttribute
                                                                   multiplier:1.0
                                                                   constant:0.5*visiblePortionLength];
[self.view addConstraint:heightConstraint];
 ```
Another thing to keep in mind is that constraints can be created only between items that have a common ancestor in the view hierarchy. Or else an exception is thrown.

###### translatesAutoresizingMaskIntoConstraints for new views

When programmatically instantiating views (even if an xib is used for it), `translatesAutoresizingMaskIntoConstraints` property must be set to NO.

By default its value is YES, i.e. the system automatically creates a set of constraints based on the view’s frame and its autoresizing mask. When you add your own constraints for a programmatically instantiated view, they inevitably conflict with the auto-generated constraints. This creates an unsatisfiable layout.

So anytime you see a custom view that did not render correctly and also see weird constraints in the console that you know you didn't create, just ensure that the custom view'`s translatesAutoresizingMaskIntoConstraints` is set to NO. When views are created from interface builder (i.e. the view is within a view controller in interface builder or storyboard, not in just a view xib), the system automatically sets the view'`s translatesAutoresizingMaskIntoConstraints` to NO.

Care must be taken though to not just have `translatesAutoresizingMaskIntoConstraints` as NO but also to create sufficient constraints. It should not be assumed that the view will have an intrinsic content size because it will not have any.

[link](http://objectivetoast.com/2014/06/02/translating-autoresizing-masks-into-constraints/) - Objective toast (goes quite deep into how and when translatesAutoresizingMaskIntoConstraints comes into play)


###### Creating margins constraints programmatically with the easy API and layoutMarginsGuide

```
NSLayoutConstraint *marginConstraint = [NSLayoutConstraint constraintWithItem:self.imageView
                                                                            attribute:NSLayoutAttributeLeading
                                                                            relatedBy:NSLayoutRelationEqual
                                                                               toItem:self.view.layoutMarginsGuide
                                                                            attribute:NSLayoutAttributeLeading
                                                                           multiplier:1.0
                                                                             constant:0];
 ```

###### Creating constraints using Visual Format language

Visual format language lets you create multiple constraints at once, using a very compact expression. It also lets you create only valid constraints. However it cannot account for errors in the key strings and also different identifiers cannot be assigned (the same identifier can still be assigned to all the constraints that are created and returned in the array by iterating through the array).

 ```
NSDictionary *viewsDictionary = @{@"imageView":self.imageView,@"viewBottomLayoutGuide":self.bottomLayoutGuide};
NSArray *constraints = [NSLayoutConstraint constraintsWithVisualFormat:@"V:[imageView]-distance-[viewBottomLayoutGuide]"
                                                                       options:0
                                                                       metrics:@{@"distance":@0}
                                                                         views:viewsDictionary];
 ```
The options argument probably only indicates the alignment to be used. The type is an enum called NSLayoutFormatOptions and it has values such as `NSLayoutFormatAlignAllLeft`, `NSLayoutFormatAlignAllRight`, `NSLayoutFormatAlignAllBottom`, etc.

`NSDictionaryOfVariableBindings` macro can be used only in Objective-C.

Another thing to keep in mind is that if the distance is not explicitly specified, probably by default the constraint is drawn between the margins (at least when one of the items is the top or bottom layout guide) and not the edge.

Visual format language [reference](https://developer.apple.com/library/mac/documentation/UserExperience/Conceptual/AutolayoutPG/VisualFormatLanguage.html#//apple_ref/doc/uid/TP40010853-CH27-SW1)
