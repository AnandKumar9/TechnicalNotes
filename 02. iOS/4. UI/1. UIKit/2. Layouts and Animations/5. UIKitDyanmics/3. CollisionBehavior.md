A collision behavior stops the movement of the concerned views when they collide with each other or with any identified boundary. The boundary can be the reference view of the animator (if so configured) or even a bezier path. (Collisions are CPU intensive though and should be added wisely.)

Also some bounce automatically happens as a part of collision behavior when the collisions happens.
collisionMode determines what kinds of collisions are actually allowed, the default is both boundaries and items but just one of them can also be specified.

#### Treating the reference view as a boundary

Setting translatesReferenceBoundsIntoBoundary as true lets makes the reference view to be treated as a boundary. This can also be achieved using the setTranslatesReferenceBoundsIntoBoundaryWithInsets method which also allows to set an inset to the reference view.
```
collisionBheavior.translatesReferenceBoundsIntoBoundary = true
```

#### Creating a boundary from a bezier path

If a view has collision with bezier path, the view’s path of course changes. But the bezier path of course stays the same. So if the bezier path was made from a view’s frame, the view will not move. 

A bezier path can be added along along some view’s frame in this way using the addBoundaryWithIdentifier(_:forPath:) method. There are some restrictions though (as explained in the reference) for the path to be valid for collision behavior. For example, the path should be non-intersecting.
```
self.collisionBehavior.addBoundaryWithIdentifier("view2 frame", forPath: UIBezierPath(rect:self.view2.frame))
UIBezierPath(CGRect)
```

#### Delegate callbacks

A collision behavior even has a delegate (UICollisionBehaviorDelegate) which can be used to get callbacks for things such as collision starting, ending, etc. It has these methods.
```
collisionBehavior(_:beganContactForItem:withBoundaryIdentifier:atPoint:)
collisionBehavior(_:beganContactForItem:withItem:atPoint:)
collisionBehavior(_:endedContactForItem:withBoundaryIdentifier:)
collisionBehavior(_:endedContactForItem:withItem:)
```

The boundary identifier reported for the reference boundary is always nil.

#### Collision bounds 

iOS9 even supports non-rectangular collision bounds.
UIDynamicItem now has a new optional property called collisionBoundsType of the enum type UIDynamicItemCollisionBoundsType. It can be a rectangle (derived from bounds), ellipse (derived from bounds height and width) or path (a custom bezier path that needs to be specified using collisionBoundingPath property). The custom bezier path must be convex, counter clockwise wound and non-self intersecting. The point 0,0 of bezier path represents the center of the dynamic item’s bounds (need to test this).
