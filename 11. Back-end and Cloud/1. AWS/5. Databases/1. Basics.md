###### Relational and Non-Relational Databases

`Relational database` is the typical conventional database, something that has tables, fields and rows. A `non-relational` database whereas has collections, documents and key-value pairs. Its more space efficient as a new field (if required for only some records) need not be added to all records.

There are 6 kinds of RDS offered by AWS - `SQL server`, `Oracle`, `MySQL server`, `PostgreSQL`, `Aurora` (Amazon's own DB), `MariaDB`.

RDS runs on virtual machines, but you don't have access to those VMs. <br>
RDS is not serverless (apart from serverless Aurora). <br>

`DynamoDB` is Amazon's NoSQL solution

###### Read Replicas and MultiAZ deployments

Amazon RDS `Read Replicas` allow to create one or more read-only copies of your database instance within the same AWS region or in a different AWS region. Updates made to the source database are then asynchronously copied to your Read Replicas. This provides scalability for read-heavy workloads. Read Replicas can also be promoted to become a standalone database instance when needed. However, if primary database is lost for any reason, there is no automatic failover. It has to be done manually. There can be 5 read replicas of an Amazon RDS DB. ([reference](https://aws.amazon.com/rds/details/read-replicas/)).

Currently, Read Replicas are supported by Amazon RDS for MySQL, MariaDB, PostgreSQL, Oracle and Amazon Aurora.

With Amazon RDS `Multi-AZ deployments`, data is synchronously replicated to a standby in a different Availability Zone (AZ). In the event of an infrastructure failure, Amazon RDS performs an automatic failover to the standby, minimizing disruption to the applications.

In case of Read Replicas though, every time something is written to primary instance a replica is made on the secondary db.

Read Replicas can even be combined with MultiAZ deployments.

> An EC2 instance connects to a database using a connecting string (which is nothing but the database's DNS record).

###### OLTP and OLAP

`Online Transaction Processing (OLTP)` is something that pulls up discrete records.

`Online Analytics Processing (OLAP)` is something that pulls up much more detailed and intelligent reports. It internally runs a whole bunch of queries on the DB.

Data Warehousing is used for very large and complex datasets. It is usually used for doing queries on data and uses different types of architectures form a database perspective. For OLTP and OLAP, different databases are used.

`Redshift` is Amazon's OLAP solution.

`ElastiCache` is a web service for working with in-memory cache in the cloud. It is typically used with web applications (including web servers). This helps when a web server is getting a lot of traffic. It supports 2 open source in-memory caching engines - `Memcached`, `Redis`
