#### Processes and Threads

There are two basic units of execution in concurrent programming - Processes and threads.
A system normally has many active processes and threads. This is true even in systems that only have a single execution core, and thus only have one thread actually executing at any given moment.

A `process` has a self-contained execution environment. Each process has its own memory space.  To facilitate communication between processes, most operating systems support `Inter Process Communication (IPC) resources`, such as pipes and sockets.

Most implementations of the Java virtual machine run as a single process. A Java application can create additional processes using a `ProcessBuilder` object.

`Threads` are like lightweight processes. They exist within a process (every process has at least one) and share the process's resources, including memory and open files.

Multithreaded execution is an essential feature of the Java platform. Every application has at least one thread, i.e. the `main thread`. This main thread has the ability to create additional threads, as we'll demonstrate in the next section.

#### Thread object

Each thread is associated with an instance of the class `Thread`. They are typically used in two ways. Either by instantiating Thread obects or by passing the application's concurrent tasks to an `Executor`.

###### Creating a Thread object

It can be created in two ways.

1. By subclassing `Thread` (which itself implements `Runnable`). Here the code to be run concurrently is put in `run()` (note that `run()` is actually a required function in `Runnable` interface).

```
public class HelloThread extends Thread {
    public void run() {
        System.out.println("Hello from a HelloThread thread!");
    }

    public static void main(String args[]) { }
}
```

2. By getting a class to implement `Runnable`. The code to be run concurrently is put in `run()`. This is a better and more common way.

```
public class HelloRunnable implements Runnable {
    public void run() {
        System.out.println("Hello from a HelloRunnable thread!");
    }

    public static void main(String args[]) {  }
}
```

Typically the main for such objects also include a `start` invocation to start a new thread.
```
public static void main(String args[]) {
    (new Thread(new HelloRunnable())).start();
}
```

###### Pausing execution with sleep

`Thread.sleep()` causes the current thread to suspend execution for a specified period. It is an efficient means of making processor time available to the other threads but these sleep times are not guaranteed to be precise. The sleep period can also be terminated by interrupts, and if that happens it throws an `InterruptedException`.

```
for (int i = 0; i < importantInfo.length; i++) {
    System.out.println("Print something");
    Thread.sleep(4000);
}
```

###### Interrupts

A thread's execution can be instructed to be interrupted (i.e. stopped?) from another thread by sending a `interrupt()`. Its upto the thread on what to do when it receives it. Typically they catch the interrupt, stop the current execution and cascade the interrupt further.

Methods that can throw an `InterruptedException` (such as `sleep()`) are usually designed to cancel their current operation and return immediately when they themselves receive an interrupt.

It seems as if a thread also keeps track of whether it has received an interrupt that has not yet been acted upon. This can be found by using `Thread.interrupted()`.
> How is this possible though? If something thows an interrupt, wouldn't it be caught right away?

```
if (Thread.interrupted()) {
    throw new InterruptedException();
}
```

The interrupt mechanism is implemented using an internal flag known as the `interrupt status`. Invoking `Thread.interrupt()` sets this flag. When a thread checks for an interrupt by invoking the static method `Thread.interrupted()`, interrupt status is cleared.

The non-static `isInterrupted()` method however, which is used by one thread to query the interrupt status of another, does not change the interrupt status flag.

By convention, any method that exits by throwing an `InterruptedException` clears interrupt status when it does so.

###### Joins

`join()` allows one thread to wait for the completion of another.

If t is a Thread object whose thread is currently executing, then the below causes the current thread to pause execution until t's thread terminates.
```
t.join();
```

 However, `join()` is dependent on the OS for timing and cannot be completely relied upon.

`join()` responds to an interrupt by exiting with an `InterruptedException`.
