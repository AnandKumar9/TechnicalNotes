###### Access level modifiers in a class

At top level - `public`, `package-private`(no explicit modifier)

At member level — `public`, `private`, `protected`, or `package-private` (no explicit modifier)

If a class has no modifier (the default, also known as package-private), it is visible only within its own package.

`private` modifier specifies that the member can only be accessed in its own class.

`protected` modifier specifies that the member can only be accessed within its own package (as with package-private) and, in addition, by a subclass of its class in another package.

A `final` method cannot be overridden in a subclass

#### class (static) members

class variables are specified using `static`. They cannot use the `this` keyword as there is no instance for this to refer to.

###### Declaring constants using static variables

`static` modifier, in combination with the `final` modifier, is also used to define constants. The final modifier indicates that the value of this field cannot change.

```
static final double PI = 3.141592653589793;
```

###### Static Initialization Block

A `static initialization block` is a normal block of code enclosed in braces `{ }`, and preceded by the `static` keyword. It can be used to initialize values for static variables.

```
class Hexagon extends Polygon {
    static Boolean shouldHave6Sides;

    static {
        shouldHave6Sides = true;
    }
}
```

A class can have any number of static initialization blocks, and they can appear anywhere in the class body. The runtime system guarantees that static initialization blocks are called in the order that they appear in the source code.

Alternatively, private static methods can also be used for initialization.
```
public static varType myVar = initializeClassVariable();
```

> There can be `initializer blocks` for instance variables too.
```
class Hexagon extends Polygon {  
    Boolean isProperlyInitialized;
    {
        isProperlyInitialized = (numberOfSides == 6);
    }
}
```
The Java compiler also copies initializer blocks into every constructor. Therefore, this approach can be used to share a block of code between multiple constructors.

`Blocks` are in fact another Java construct and need not be marked as `static`. They can even be used inside methods and can encapsulate a piece of code with its own variables declared, etc.

```
public static void main(String[] args) throws CloneNotSupportedException {
    {
        int n = 1;
        System.out.println(String.format("Snippet %s", n));
    }
    // `n` cannot be used here.
}
```
