Content scripts are how the communication with hosting webpage actually happens.

An extension can have a bunch of content scripts. Each script can then itself have several JavaScript and css files.

###### API available to them -

Content scripts are only allowed to use a part of the Chrome API. It can use some of the `chrome.extension` API (`getURL`, etc.), some of the `chrome.runtime` API (`getManifest`, `connect`, etc.), `chrome.storage`, `chrome.i18n` (an internationalization API).

It also cannot use variables or functions defined by its extension's pages (i.e. its js files?) or even the ones defined by the actual hosting webpage.


###### Injecting universally -

The content script can either always be injected by specifying so in the manifest file.

```
"content_scripts": [
    {
      "matches": ["a bunch of rules],
      "css": ["mystyles.css"],     // List of css files to be injected
      "js": ["jquery.js", "myscript.js"]    // List of js files to be injected
    }
  ],
```

So its almost as if one element in the manifest file's content_scripts is what a content script is (abstractly speaking).


###### Programmatic Injection-

The content script can also be injected programmatically so that it gets injected only when needed. This is typically done using `chrome.tabs.executeScript` (for injecting JS) or `chrome.tabs.insertCSS` (for injecting CSS).

So in the below example, a js in the extension is listening to a browser action. And when the extension icon is clicked, it just injects the script in the hosting webpage.

```
chrome.browserAction.onClicked.addListener(function(tab) {
  chrome.tabs.executeScript({
    code: 'document.body.style.backgroundColor="red"'
  });
});
```

The script to be injected can also be in a separate file altogether.
```
chrome.tabs.executeScript(null, {file: "content_script.js"});
```

Note though that for programmatic injection, there must be an entry in the manifest file.

```
"permissions": [
  "activeTab"
],
```

###### Execution context -

Content scripts execute in a context referred to as isolation world. The scripts can access webpage's DOM but not any variable or function defined by any of the webpages' JS. Nor can the webpage's JS access any variable or function defined by the content script.

###### Communication between content script and hosting webpage -

For content script and the hosting webpage to talk with each other messages need to be used. One posts message to itself and the other intercepts it.
