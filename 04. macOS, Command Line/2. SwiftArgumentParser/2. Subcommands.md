#### What is a subcommand

Subcommands are basically the argument that is passed right after the exe's name, with usual arguments passed following it. It essentially looks like a way to talk about arguments when an exe is complicated enough to provide many different sub-features.

Examples of subcommands - `git branch`, `swift run`, `swift build`, etc.

#### High-level steps

1. The `ParsableCommand` needs to have a static property named `configuration` (of the type `CommandConfiguration`). This is where all the possible subcommands for the exe are specified.
2. Have a struct that conforms to `ParsableArguments`, this can be used to configure all the arguments passed after the subcommand.
3. Define the subcommands one-by-one.
   1. They all need to be nested struct in the actual exe's `ParsableCommand` struct and be `ParsableCommand`conformant themselves too.
   2. They all would have `configuration: CommandConfiguration` property themselves too (just an abstract is enough).
   3. They can have the subsequent passed arguments' parsing configuration specified using a `@OptionGroup` property.

#### Code snippet examples

Step 1: You can provide a static `configuration` property for a command that specifies its subcommands and a default subcommand, if any.

```
struct Math: ParsableCommand {
    static var configuration = CommandConfiguration(
        abstract: "A utility for performing maths.",
        subcommands: [Add.self, Multiply.self, Statistics.self],
        defaultSubcommand: Add.self)
}
```



Step 2: Next, define a `ParsableArguments` type with properties that will be shared across multiple subcommands. Types that conform to `ParsableArguments` can be parsed from command-line arguments, but don’t provide any execution through a `run()`method.

```
struct Options: ParsableArguments {
    @Flag(name: [.long, .customShort("x")], help: "Use hexadecimal notation for the result.")
    var hexadecimalOutput = false

    @Argument(help: "A group of integers to operate on.")
    var values: [Int]
}
```



Step 3: Define the subcommands. The arguments parsing configuration is specified using an `@OptionGroup` property wrapper.

> `OptionGroup` doesn’t define any new arguments for a command; instead, it parses the arguments defined by another `ParsableArguments` type.

```
extension Math {
    struct Add: ParsableCommand {
        static var configuration
            = CommandConfiguration(abstract: "Print the sum of the values.")

        @OptionGroup var options: Math.Options

        mutating func run() {
            let result = options.values.reduce(0, +)
            print(format(result: result, usingHex: options.hexadecimalOutput))
        }
    }

    struct Multiply: ParsableCommand {
        static var configuration
            = CommandConfiguration(abstract: "Print the product of the values.")

        @OptionGroup var options: Math.Options

        mutating func run() {
            let result = options.values.reduce(1, *)
            print(format(result: result, usingHex: options.hexadecimalOutput))
        }
    }
}
```
