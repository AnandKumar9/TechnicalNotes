##### Parsing custom types

Parsing can be done to any type that conforms to the `ExpressibleByArgument` protocol. Standard int, float, strings, booleans already conform to it. 

```
struct Path: ExpressibleByArgument {
    var pathString: String

    init?(argument: String) {
        self.pathString = argument
    }
}

struct Example: ParsableCommand {
    @Argument var inputFile: Path
}
```

A default implementation also exists for `RawRepresentable` types, like string-raw value enumerations.

```
enum ReleaseMode: String, ExpressibleByArgument {
    case debug, release
}

struct Example: ParsableCommand {
    @Option var mode: ReleaseMode
}
```

To use a non-`ExpressibleByArgument` type for an argument or option, a throwing `transform` function that converts the parsed string to the desired type needs to be provided though.

```
enum Format {
    case text
    case other(String)

    init(_ string: String) throws {
        if string == "text" {
            self = .text
        } else {
            self = .other(string)
        }
    }
}

struct Example: ParsableCommand {
    @Argument(transform: Format.init)
    var format: Format
}
```

##### Flag Inversions

If a `@Flag` property wrapper is initialized with `inversion` parameter, then the flag name passed in the command can have a possible value that will be interpreted as the inverted value of the flag.

```
struct Example: ParsableCommand {
    @Flag(inversion: .prefixedNo)
    var index = true

    @Flag(inversion: .prefixedEnableDisable)
    var requiredElement: Bool
}

> example --no-index --disable-required-element ## Interpreted as false false
> example --enable-required-element ## Interpreted as true true
```

To provide more than just two options, an enum conforming to `EnumerableFlag` flag can be used.

```
enum CacheMethod: String, EnumerableFlag {
    case inMemoryCache
    case persistentCache
}

enum Color: String, EnumerableFlag {
    case pink, purple, silver
}

struct Example: ParsableCommand {
    @Flag var cacheMethod: CacheMethod
    @Flag var colors: [Color] = []
}

> example --in-memory-cache --pink --silver
```

When a `@Flag` is of type `Int`, the value is parsed as a count of the number of times that the flag is specified.

```
struct Example: ParsableCommand {
    @Flag(name: .shortAndLong)
    var verbose: Int
}

> example -vvvv   # verbose is counted as 4 here
```

##### Specifying a parsing strategy

If an `@Option` property wrapper is initialized with `parsing` property with the value being `.unconditional`, for a given key the very next entry is taken as the corresponding value even if that value was prefixed with `--`.

```
struct Example: ParsableCommand {
    @Flag var verbose = false
    @Option(parsing: .unconditional) var name: String
    @Argument var file: String?
}
    
> example --name --verbose Tomás
Verbose: false, name: --verbose, file: Tomás
```

The `.scanningForValue` strategy, on the other hand, looks ahead in the list of command-line inputs and uses the first un-prefixed value as the input, even if that requires skipping over other flags or options.

There are similarly alternate array parsing strategies as well, things like `.unconditionalSingleValue`, `.upToNextOption`, `.remaining`, etc. for `@Option var file: [String] = []`.

([Reference](https://apple.github.io/swift-argument-parser/documentation/argumentparser/declaringarguments#Specifying-a-parsing-strategy))
