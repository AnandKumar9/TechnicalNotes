##### Guiding principles of Syntax Tree

What actually happens behind the scenes in Swift is that every source code gets converted into a custom data structure known as `syntax tree`. This data structure stores the `lexical structure` i.e. the relative position of text and whitespace, and also the `syntactic structure` i.e. the relationship between the nested syntactic elements and their neighbors (i.e. the more syntax aware things). 

There are few more priciples it adheres to.

1. Its fully `immutable and persistent `, in the sense that any changes to the source code are saved in a new version. Why its so, I don't know but that's how its APIs seem to be. It supposedly enables safe manipulation across threads.
2. It has `source fidelity` i.e. it saves everything that the source code has. Non-syntax entitites like whitespace, comments, compiler directives are known as `Trivia`.
3. It also shows `resilience `when faced with understandable errors. It can represent two broad classes of errors: missing syntax and unexpected syntax.
   1.  `Missing syntax` are syntax elements that are expected but missing in the source code. Such errors are represented in the tree as tokens with a `SourcePresence/missing` source presence, and the expected missing tokens are saved as `SourcePresence/present` nodes. 
   2. `Unexpected syntax` is any superfluous text, such as if there happens to be whtespaces in a function name. Unexpected nodes allow parsers to gracefully recover during parsing by scanning forward in the input stream until they reach a known recovery point.


([Documentation](https://github.com/apple/swift-syntax/blob/main/Sources/SwiftSyntax/Documentation.docc/Working%20with%20SwiftSyntax.md#syntax-trees))

##### Syntax Nodes

SyntaxTree is made up of a series of `syntax nodes`. Many of these nodes are in turn conform to one of the `SyntaxProtocol` protocols.

 `DeclSyntaxProtocol` is used for declarations like struct, class, enum, protocol. `StmtSyntaxProtocol` is used for things like if, switch, do.  `ExprSyntaxProtocol` for expressions like function calls, literals, and closures. `TypeSyntaxProtocol` for types like `Array<String>`, `[String: String]`, and `some Protocol`. `PatternSyntaxProtocol` for patterns like `case (_, let x)`.

`SyntaxCollection` is a special kind of syntax node that represents syntax with a variable number of children. For example, a code block value can contain zero or more statements in between a pair of braces. To represent these children, a `CodeBlockSyntax` value has a `CodeBlockSyntax/statements` accessor that returns a `CodeBlockItemListSyntax` value. The elements of this syntax collection are `CodeBlockItemSyntax` values.

##### Syntax Tokens

At the leaves of the syntax tree are `TokenSyntax` values. A token syntax value represents an atomic unit of syntax and any associated trivia, like an identifier and the whitespace around it. Taken together, the tokens of a syntax tree represent the lexical structure of the source code. This structure is used by linters and formatters to analyze the textual content of source code. So in 'import Foundation' 'Foundation' is a token (for that matter 'import' is a token too but then its also a 'ImportDeclSyntax'.)

##### Syntax Trivia

These are  whitespace, comments, compiler directives, and erroneous source code. Tools like compilers often discard trivia during source code processing. However, maintaining trivia is important for tools like editors, IDE, etc. The precise type for them is `Trivia`. Trivia associated with token syntax can be inspected with the `TokenSyntax/leadingTrivia-7p6tp` and `TokenSyntax/trailingTrivia-5jclz` accessors.
