#### Bubble Sort

Compare element 1 and element 2 and swap if needed, then compare element 2 and element 3 and swap if needed, and go all the way. Next iteration, go upto the peunultimate index, and so on. The largest element 'bubbles up' to the last index in the first iteration, the second largest element 'bubbles up' to the penultimate position in the second iteration, and so on.

> The in-focus index that can get swapped is changing throughout a major iteration. <br>The foirst major iteration looks at the whole array and then keeps shrinking from the end of array.

#### Insertion Sort

Compare element n and element 'n-1', and bring element 'n-1' to the correct position in that slice. Then consider a slice of last 3 elements and bring the first element there in the correct position in that slice. Keep going to the first element (i.e. the entire array) this way. For every slice, the first element before any sorting gets spurted (aka inserted) to the correct index in that slice by the end of the major iteration through that slice.

I can also think of it as 'Spurt Sort', things don't *bubble up* and instead thet *spurt up*.

> The in-focus index that can get swapped is fixed throughout a major iteration. <br>The first major iteration starts from the end of array, and then keeps expanding towards the start of array.

> Note that in the classic implementation a left to right traversal happens with the latest element being put in its correct index (just the opposite of my approach).

#### Selection Sort

Start with the entire array, find the largest element, and swap with the final element. Then look at the slice which includes all the but the last element and swap the largest element in that with the final element in that slice. In any given slice, the largest element is identified (i.e. selected) and moved to the end.

>The in-focus index that can get swapped is unknown and ascertained at the end of a major iteration. <br>The first major iteration looks at whole array and then keeps shrinking towards the end of array.

#### Heap Sort

> Revise what Binary Tree, and Max Heap are before reading this

Assume two functions are there - `build-max-heap()` that given an unsorted array creates a max-heap sequene from it, and `heapify()` that given a binary tree converts it into a max-heap.

Now the way this is done is that anytime a max-heap is created, swap the first element with the last element of the heap, the swapped element that was at the beginning is now the part of a separate sorted array. And then keep repeating this process.

There are clear formulas to create an array into a binary tree, and then clear algorithms to convert a binary tree into a max-heap.

#### Quick Sort

Works with picots, Identify a pivot and move it to the end. Now starting traversal from left find the first element that is greater than the pivot, and starting traversal from the right find first element that is lesser than the pivot, swap the two, and then continue the process until the 'first element from left that is greater' has a higehr index that then 'first element from right that is lesser', and then swap the item from left with the pivot. The pivot is now at the correct sorted position in the final sorted array. Continue the process excluding the pivot.

A key startegy lies in chosing the initial pivot.
