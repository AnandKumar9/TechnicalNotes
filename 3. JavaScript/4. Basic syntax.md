##### Linebreak as auotmatic semicolon

Linebreak is implicitly interpreted as `;`, aka the end of existing statement. Sometimes howevere when an existing statement is clearly not complete, a linebreak is not automatically interpreted as a semi-colon until it does look complete.
```
// These are actually one line
alert(3 +
1
+ 2);
```

And yet there are times when automatic semicolons are not inserted as you would expect.
```
// This shows an error after first alert.
alert("Hello")
[1, 2].forEach(alert);
```

So while its not mandatory to end lines with `;`, its a good practice to do that anyway.

##### Comments

They can be inserted anywhere. `//` is for one-line comment and `*/ /*` is for multi-line comments.

##### Modern mode (`"use strict"`)

In 2009, ECMAScript 5 appeared and along with adding some new features to the language, also modified the behavior of some of the old features (which really needed those modifications). However, for backward compatibility reasons most of these changes continue to be off by default and to get them to come into effect the string `"use strict"` needs to be specified at the top of the script.

```
"use strict";
alert( "I'm here!" );
```

> It can in fact even be put at the top of a function in which case, it comes into effect only for that function. In fact, its already enabled by default in classes and modules (which are actually new things in JavaScript!).

So to put it briefly, there is an `old mode` and a `strict mode`.

##### Variables

`let` specifies a variable, `const` specifies a constant. If an attempt is made to change a constant's value, there is an error.

Different ways of declaring and initializing a variable with `let`.
```
let userName = "Anand";
let name;
name = "Ruchi";

let a, b = "x", "y";
```

Also, a variable should be declared only once. The name must contain only letters, digits, or the symbols `$` and `_.` When the name contains multiple words, camelCase is commonly used.

And importantly just like in many other languages, in JavaScript too case matters.

> Long back, it was technically possible to create a variable by a mere assignment of the value without using `let`. This still works now if we don’t put `use strict` in our scripts to maintain compatibility with old scripts.

It is also a common practice to name variables directly assigned to constant values, as all upper case.
```
const COLOR_GREEN = "#0F0";
```

A variable can at one moment be a string and then store something else (say a number). Programming languages that allow such things `dynamically typed`, meaning that there exist data types, but variables are not bound to any of them.
