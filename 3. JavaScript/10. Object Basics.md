Its like classes in other languages, which in other words is like a dictionary.

### Basics

#### Creating an Object

Creating an empty object -
```
let user = new Object();
let user = {};
```

Creating an object with properties (i.e. keys) -
```
let user = {
    name: "John",
    age: 30,
    "likes birds": true // multiword property name are allowed but must be quoted
};
```

Its possible to add new properties after the object has been created. Just simply assign it a value as if it always existed.
```
user.isAdmin = true;
```

In fact its then even possible to delete a property.
```
delete user.isAdmin;
```

#### Accessing object properties

Dot syntax works, except when accessing multi-word properties. For multi-word proeperties, the alternative square bracket notation has to be used.
```
user.age = 39;
user["likes birds"] = true;

let key = "likes birds";
user[key] = true;
```

#### Computed Properties

Its a way to have dynamic property names at the time of object creation. in the below example, guava is a computed property.

```
let fruit = "guava"
let bag = {
    [fruit]: 5,
  };
alert( bag.guava );
```

#### Property Shorthand

Its an easy way to create an object from a set of existing variables such as the object's properties are the variable names and their corresponding values are the variables' values.

```
{
  name,
  age,
};
```

is the same as
```
{
  name: name,
  age: age,
};
```

In fact the same object can have normal properties and shorthands.

#### Checking if a property exists

Unlike most other languages, in JavaScript trying to access a property that does not exist does not give an error. It instead just returns `undefined` and that can be checked using `===`.

```
user.noSuchProperty === undefined
```

And there is another operator `in` which does the same thing.
```
let user = { age: 30 };
let key = "age";

key in user
```

> The trick is that `undefined` does not work well when there is a property that exists but has its value set as `undefined`. In such a case, `in` still works. Its hence, always better to use `in`.

#### for ... in loop

Its a way to iterate over all the existing properties of an object.

```
for (key in object) {
  // executes the body for each key among object properties
}

for (let key in user) // A let before key is also fine.
```

> While iterating through an object, integer properties (i.e. string that can be converted to-and-from an integer) are returned in a sorted fashion (by name?) but other properties appear in creation order.

#### Adding methods to objects

Methods can be added to objects.

After the object has been created
```
let user = {
  ...
};
function sayHi() {
  alert("Hello!");
};

user.sayHi = sayHi;

user.sayHi();
```

Or even while its being created.
```
user = {
  sayHi: function() {
    alert("Hello");
  }
};

// The below approach is called 'method shorthand' and does not even require the function keyword.
user = {
  sayHi() {
    alert("Hello");
  }
};
```

#### this

A function implementation can access the obect it is in using `this`. (Although, it actually works even if `this` is not used.)
```
sayHi() {
    // "this" is the "current object"
    alert(this.name);
  }
```

In fact, `this` can be used in a function defintion even when the function is not already in an object. If that function later gets assigned to an object, it becomes useful then. If the function gets called while its not tied to the object referring to `this`, in `strict mode` it returns `undefined`. In non-strict mode, it refers to the global object.

Arrow functions are special. They don’t have their own `this`. If `this` is referenced from such a function, it’s taken from the outer 'normal' function.
