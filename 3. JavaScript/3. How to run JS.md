#### How to run JS from Browser

##### Putting raw JS in `script` tag

Raw JS code can be put inside `<script>` tags in a HTML, and then probably run as they are encountered. So if there is a script tag in the html's body it will run when the page loads.
```
<!DOCTYPE html>
<html>
<body>
  <script>
    alert( "I'm JavaScript!" );
  </script>
</body>
</html>
```

The `<script>` tag also has a few attributes that were needed earlier but are redundant now. Old HTML standards required script tags to have a `type` attribute but the new standard does not. In fact, the new standard use this attribute to mean something else altogether (JS modules). <br>
There was also a `language` attribute but that's redundant too now as JS is now the default labguage for scripts in webpages. <br>
And long time back it was also advised to have comments (`!--`) inside script tags to hide the JS code from old browsers that didn't process script tags, but every browser released since previous 15 years supports JS.
```
 <script type="text/javascript">
 <script type="text/javascript"><!--
    ...
//--></script>
```

##### Using `src` attribute to get JS from another file

JS scripts can also be put in files of their own and just the relative/absolute path to the script specified in the `script` tag with a `src` attribute. It can also be full URL.
```
<script src="/path/to/script.js"></script>
<script src="https://cdnjs.cloudflare.com/lodash.js"></script>
```

A single `<script>` tag can’t have both the `src` attribute and code inside. If `src` is set, the script content is ignored.

> Usually the scripts are placed in a separate file (and not as raw code within HTML itself). One more benefit of this is that if the browser can save the script in its cache and use that if multiple pages happen to need the same script.
