#### Basic Syntax

```
function name(parameter1, parameter2, ... parameterN) {
  ...body...
}
```

A function can access an outer variable as well. Outer variables are known as global variables in JavaScript, and are usually avoided. The outer variable is only used if there’s no local one.

A function always gets a copy of the values passed to it.

If a function is called, but an argument is not provided, then the corresponding value becomes `undefined`.

Default argument values can be specified in function declaration using `=`.
```
function showMessage(from, text = "no text given") {
```

A function with an empty `return` or without it returns `undefined`. A newline should not be given between `return` and the value, as its interepreted as an `undefined` being returned.

Functions that are used very often may sometimes have ultrashort names. For example, the jQuery framework defines a function with `$`, but usually its better to   not name functions like that.

A function can be called earlier than it is declared and defined.

#### Function Expressions

Functions as variables.

```
let sayHi = function() {
  alert( "Hello" );
};
```

When functions are passed as argumentto another function, those functions are termed as `callback` functions.
```
function ask(question, yes, no) {
  if (confirm(question)) yes()  // Why no ; here?
  else no();
}

ask(
  "Do you agree?",
  function() { alert("You agreed."); },
  function() { alert("You canceled the execution."); }
);
```

In strict mode, when a function declaration is within a code block, it’s visible everywhere inside that block. But not outside of it.

`IIFE` is the term used for Immediatiely Invoked Function Expressions.
```
(function() {
  // ... Some code
})();
```

#### Arrow Functions

Its another way to create functions.
```
let func = (arg1, arg2, ..., argN) => expression;
```

```
let sum = (a, b) => a + b;
```

If there are no arguments, parentheses will be empty but they should be present.
```
let sayHi = () => alert("Hello!");
```

Multiline arrow functions are possible too.
```
let sum = (a, b) => {  // the curly brace opens a multiline function
  let result = a + b;
  return result; // With curly braces, an explicit return is needed
};
```

Arrow functions do not have `this`. If `this` is accessed, it is taken from the outer scope. They do not have `arguments` variable or `super` either.

#### Rest Parameters

If a function is called with more arguments than its declaration asks for, there is no error and the extra arguments are just ignored by the function.

The extra parameters passed while calling the function if needed, can still howwever be captured by the funtion using `rest parameters (i.e. ...arr)`. They must be at the end.
```
function sumAll(x, y, ...args) {
  // Do something. args is an array.
}
sumAll(1, 2, 3, 4) ;
```

#### `arguments` variable

`arguments` is a special array-like object that contains all arguments by their index. Its not a full-fledged array though, so even if it supports subscript access it does not support more advanced array functions like `map` (which rest parameters' array does).

Also, arrow functions do not have access to `arguments` array.

```
function showName() {
  alert( arguments.length );
  alert( arguments[0] );

  // for(let arg of arguments) alert(arg); // it's iterable
}
```

#### Spread Syntax

When `...arr` is used in a function call, it 'expands' an iterable argument arr into the list of arguments.

```
let arr = [3, 5, 1];
alert( Math.max(...arr) ); // Math.max needs a simple comma separated list of arguments, not an array.
```

##### Copying an array/object

While it can be done with `Object.assign()`, it can also be done with spread syntax.
```
let arr = [1, 2, 3];
let arrCopy = [...arr];
```

#### Variable scope, Closure

If a variable is defined inside a `code block, i.e. {}`, it is only visible inside that code block. For this reason, any variable defined inside for loop, etc. is visible only within iteration of that loop. In fact, in case of a for loop even if a 'let i = 1' is done in the declaration which is technically not in '{ }', its treated as its inside the block.
```
{
  let message = "Hello";
  alert(message);
}
```

> But a code block by itself can't be assigned to a varible. So, its not really like Swift closure either.

#### Lexical Environment

In JavaScript, every running function, code block {...}, and the script as a whole have an internal (hidden) associated object known as the `Lexical Environment`.

It consists of `Environment Record` which is an object that stores all local variables as its properties (and some other information like the value of `this`), and a reference to the outer lexical environment i.e. the one associated with the outer code.

> Its a topic with lot more low level details, check JavaScript.info section on closures ([link](https://javascript.info/closure)). Also, check the 'Garbage collection' and 'Real-life optimizations' sections in the same page.

#### Closure

In general programming language terms, a `closure` is a function that remembers its outer variables and can access them. In JavaScript, all functions (with the exception of `new Function` functions) are naturally closures as it already happens that way by default . They automatically remember where they were created using a hidden `[[Environment]]` property, and then their code can access outer variables.

#### Function object

Functions are objects too and have some useful properties. `name` is the property that gives the function name. `length` is a property that returns the number of function parameters (the rest parameters are not counted).

```
function sayHi() {
  alert("Hi");
}

alert(sayHi.name);
alert(sayHi.length);
```

#### NFE

`NFE` is an abbreviation for `Named Function Expression`. In the below example, `func` is an added name for the function expression.
```
let sayHi = function func(who) {
  alert(`Hello, ${who}`);
};
```
This name can then be used to refer the function within itself.

#### `new` function syntax

Its another way to create functions. The function is created literally from a string, that is passed at run time.

```
let sum = new Function('a', 'b', 'return a + b');
alert( sum(1, 2) );
```

When a function is created using new Function, its `[[Environment]]` is set to reference not the current Lexical Environment, but the global one. So, such function doesn’t have access to outer variables, only to the global ones. If new Function had access to outer variables, it would have problems with minifiers. (JavaScript.info [link](https://javascript.info/new-function#closure)).

#### `setTimeout` and `setInterval`

Two rudimentary ways to run a function at a later time. `setTimeout` runs it once, and `setInterval` runs it repeatdely.

```
let timerId = setTimeout(func|code, [delay], [arg1], [arg2], ...)

let timerId = setInterval(func|code, [delay], [arg1], [arg2], ...)
```

```
function sayHi() {
  alert('Hello');
}

setTimeout(sayHi, 1000); // Run after 1 sec
clearTimeout(timerId); // Cancel the scheduled run
```

```
let timerId = setInterval(() => alert('tick'), 2000);
setTimeout(() => { clearInterval(timerId); alert('stop'); }, 5000); // Cancel after 5 sec
```

([JavaScript.info link](https://javascript.info/settimeout-setinterval))
