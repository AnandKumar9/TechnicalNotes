The concept is similar to that of reactive programming. `Promise` represents something that allows producing and consuming code to be linked.

##### Basic syntax

It needs to be passed a function (known as `executor function`) that takes two arguments that are functions themselves, `resolve()` and `reject()`. `resolve` should be called when there is a successful outcome to report, and `reject` should be called if an error happens.

The executor is called immediately, and should eventually respond with at most one success or error (if multiple are reported, they get ignored).

```
let promise1 = new Promise(function(resolve, reject) {
  setTimeout(() => resolve("done"), 2000);
  // setTimeout(() => reject(new Error("Whoops!")), 2000);
})
```

And then this can be observed using `then`, `catch`, etc. in this way. The first argument here is a function that is invoked when there is a success, and the second argument is a function that is invoked when there is an error.

```
promise1.then(
  (value) => console.log(value),
  (error) => console.log(error)
);
```

##### Using then, catch, and finally

Its also possible to skip the error function argument altogether if the error reporting is not something that is needed.
```
promise1.then(
  (value) => console.log(value)
);
```

If error is all that is of interest, then that can be done by passing `null` in the first argument or also by using `catch`.
```
promise1.catch(
  (error) => console.log(error)
);
```

And if `finally` is specified it is invoked when `then` or `catch` is invoked. It can be used for cleanup operations. Note that whether finally happens before or after depends upon whether its put before or after. A finally handler simply passes through results and errors to the next handler.

```
// Prints 'value, Cleanup'
promise1
.then(
  (value) => console.log(value)
).finally(
  () => console.log("Cleanup")
);

// Prints 'Cleanup, value'
promise1
.finally(
  () => console.log("Cleanup")
)
.then(
  (value) => console.log(value)
);
```

##### Chaining promises

If a `.`then (or `catch`/`finally`, doesn’t matter) handler returns a promise it is passed on to the next promise.

```
new Promise(function(resolve, reject) {
  setTimeout(() => resolve(1), 1000);
}).then(function(result) {
  return result * 2;
}).then(function(result) {
  return result * 4;
});
```

Technically, its also possible for the handlers to return a `Thenable` object, i.e. an arbitrary object that has a method `.then`. It gets treated the same way as a promise and allows 3rd-party libraries to implement promise-compatible objects of their own. (More description in JavaScript.info [link](https://javascript.info/promise-chaining#summary).)

##### Implicit try…catch

The code of a promise executor and promise handlers has an implicit try..catch around it.

```
new Promise((resolve, reject) => {
  throw new Error("Whoops!");
}).catch(....);
```
is the same as
```
new Promise((resolve, reject) => {
  reject(new Error("Whoops!"));
}).catch(....);
```

Also, `.catch` handles errors in promises of all kinds. Be it a reject() call, or an error thrown in a handler.

##### Promise API

The properties `state` and `result` of the Promise object are internal. They can’t be directly accessed.

There are 6 static methods of Promise class. Most of them help in working with multiple promises together such that they unify into a single promise.

`Promise.all(promises)` - Waits for all promises to resolve and returns an array of their results. If any of the given promises rejects, it becomes the error of Promise.all, and all other results are ignored.

`Promise.allSettled(promises)` – Waits for all promises to settle and returns their results as an array of objects with status of "fulfilled" or "rejected", and
value (if fulfilled) or reason (if rejected).

`Promise.race(promises)` – Waits for the first promise to settle, and its result/error becomes the outcome.

`Promise.any(promises)` – Waits for the first promise to fulfill, and its result becomes the outcome. If all of the given promises are rejected, AggregateError becomes the error of Promise.any.

`Promise.resolve(value)` – Makes a resolved promise with the given value.

`Promise.reject(error)` – Makes a rejected promise with the given error.

##### Microtasks queue

Promise handling is always asynchronous, as all promise actions pass through the internal `promise jobs` queue, also called `microtask queue` (V8 term). So .then/catch/finally handlers are always called after the current code is finished.

If a code snippet needs to executed only after .then/catch/finally, they need to be chained into a `.then` call.

```
Promise.resolve()
  .then(() => alert("promise done!"))
  .then(() => alert("code finished")); // This will happen esrlier if not put in a `then()`.
```

##### Async/Await

Async/await is a special syntax to work with promises in a more comfortable fashion.

If the `async` keyword is placed before a function, it gets it to always return a promise and subsequently allows `await` to be used. The `await` keyword before a promise makes JavaScript wait until that promise settles, and then if it’s an error generates an exception or otherwise returns the result.

```
async function loadJson(url) { // (1)
  let response = await fetch(url); // (2)

  if (response.status == 200) {
    let json = await response.json(); // (3)
    return json;
  }

  throw new Error(response.status);
}

loadJson('no-such-user.json')
  .catch(alert);
```
