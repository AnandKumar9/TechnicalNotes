##### App IDs

###### What is App ID and Bundle ID

`Team ID` is constant for one developer account and probably changes only when the account is renewed. For my account it is 7SPT8XUUFN. (After account renewal it is now 49SX6Y82KT.)

> Apps with the same Team ID can share Keychain data in a device, such as usernames and passwords.

`Bundle ID` is what is unique for every App ID of a given account. It is usually written as the reverse domain name of the app in question.

```
App ID - Bundle Seed ID (unique 10 character string, i.e. Team ID) + Bundle ID (i.e. CFBundleID or Bundle ID search string)
```

App IDs can be of two types - 

1. `Wildcard App IDs` - Has a single `*` character as the last character in the Bundle Identifier. In the bundle identifier field in Xcode, the asterisk can be replaced with any string as long as it matches the wildcard pattern. Since the Team ID remains same, this allows a single App ID to build and install multiple apps. However, wildcard IDs cannot be used for apps that use APNS, IAP, iCloud, or Game Center. Simplifies provisioning of devices during development phase (how?). 

   > A wildcard App ID called iOS wildcard ID is automatically created by Xcode and is used in the development provisioning profile called iOS Team Provisioning Profile.

2. `Explicit App IDs` - Has a specific string (and not an asterisk character) as the Bundle Identifier. It is usually the reverse domain name string that exactly matched the Bundle ID in Xcode. Can match only one app. Hence, a separate provisioning profile is required for all such apps. Has to be used for apps that need APNS, IAP, iCloud or Game Center.

   > As of ~2015, Explicit App IDs are automatically enabled for IAP and Game Center, however for remaining things they have to be manually configured.

#### Profiles

##### What is a Provisioning Profile

A `Provisioning Profile` has the details of its certificate (i.e. `cer` file) in it. When the ipa is being generated in Xcode, there is (most probably) no need to also have the cer file installed in the Mac. However, the Mac must have the corresponding `p12` file installed (i.e. present in the keychain).

The provisioning profile also has details of its App ID. In case of development profile, it also has a set of device IDs.

The first time a device is registered in Xcode, Xcode creates a development provisioning profile called `iOS Team Provisioning Profile` which uses the iOS Wildcard App ID. Xcode automatically keeps on adding new developer certificates and registered device IDs to the iOS Team Provisioning Profile so that the profile can be used for all apps that do not require an explicit App ID.

Provisioning Profiles can also downloaded from the provisioning portal or exported to disk from the Xcode organizer and they are saved with the file extension `.mobileprovision`. Once on disk, the provisioning profile can even be viewed with a text editor. It is an xml having a lot of details.

###### Distribution method

While creating a distribution provisioning profile, in addition to a distribution certificate, an App ID, and a set of device IDs, the distribution method also needs to be selected. The distribution method can be either `App Store` or `Ad Hoc`. An Ad Hoc distribution provisioning profile can be tied only up to 100 devices.

###### Renewing Provisioning Profiles

> Review and edit this 

the end of year, the provisioning profiles (both development and distribution) also expire. You may expect that the certificates will expire but will still be shown in the developer portal. However when I checked about 5 months after expiration, there weren’t any certificates at all.

In any case what needs to be done is two fresh csr files should be created in the Mac, one for development and other for distribution.

Then go to developer portal and create development and distribution certificates through them. Download these certificates and double click on them to add them to keychain. They will be added in the keychain along with the corresponding p12 files as well. These p12 files should also be exported and stored securely somewhere along with the cer files.

Finally go to developer portal, provisioning profile. At this stage, all the profiles that were not having the label ‘Managed by Xcode’ and were shown as expired until now, will probably be shown active on their own again. This also includes the iOS Team Provisioning Profile for the wildcard app ID, i.e. ‘iOS Team Provisioning Profile: *’. However, the distribution profile (which in my case is OutOnAWeekendDistributionProfile) will still be shown as expired. It should be edited and linked to the newly generated distribution certificate and then it gets active again. Download this and add it to iPhone configuration Utility.

At the same time you may also go to Xcode - preferences - account and do a refresh. All the provisioning profiles are downloaded again. And then the same set of provisioning profiles are also shown in iPhone configuration utility. Now, the app can be run on iPhone from Xcode directly. Xcode automatically installs the new development team provisioning profile to the device. It need not be installed to the device from the configuration utility.

#### Misc.

##### Code Signing Identity in Xcode

In Xcode, both the Code Signing Identity (i.e. ~ the developer account) and the provisioning profile to be used for an app are specified in its build settings.

`Code Signing Identity - Private key + Digital certificate`

##### .entitlements file

When an Xcode project has a provisioning profile attached to it, it also has a `.entitlements` file where all the entitlements are listed. At least that is how it was ~2015.

##### Generating xcarchive and ipa

For an archive to be created, the provisioning file tied to the app in its Code Signing Identity must have the same bundle ID as that of the app; and also the corresponding p12 file (i.e. private key) must be present in the Mac's keychain.

When the ipa is being generated in Xcode, there is (most probably) no need to also have the cer file installed in the Mac. However, the Mac must have the corresponding p12 file installed (i.e. present in the keychain).

For an ipa to be installable on a device, the device must be having the provisioning profile using which the app was built. For provisioning profiles which are shown as ‘managed by Xcode’ in developer portal, probably this is not necessary and the app can be installed straight away by running from Xcode. Xcode probably automatically takes care of installing the provisioning profile. For other kind of provisioning profiles, however having the profile installed on device is necessary and it can be done from iPhone configuration utility.

##### iPhone Configuration Utility

> This software is not available now, used to do plenty of things to deal with provisioning. Probably the software to now use is [Apple Configurator](https://support.apple.com/apple-configurator).

In iPhone Configuration Utility, the device will show up only if the device was tied to the provisioning profile and an app will show up only if that app uses a provisioning profile which is tied to that device.

If an ipa's provisioning profile is not already installed in the iPhone Configuration Utility, that ipa cannot be added in the iPhone Configuration Utility's applications.
