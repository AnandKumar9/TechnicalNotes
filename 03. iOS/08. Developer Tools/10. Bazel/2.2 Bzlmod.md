##### What is it and how to enable it

[Reference](https://bazel.build/external/migration)

Bzlmod was introduced with Bazel 6.3, it does away with the `WORKSPACE` and instead uses `MODULE` file as the repository root marker file. The WORKSPACE file approach has some [shortcomings](https://bazel.build/external/overview#workspace-shortcomings) which this Bzlmod doesn't.

To enable it the `.bazelrc` file should have `--enable_bzlmod` flag, and apply it to the `common` command so it applies to every command.

```shell
# Enable Bzlmod for every Bazel command
common --enable_bzlmod
```

##### Fetching external dependencies

With WORKSPACE file,  `http_archive()` is used to download repository rules. With Bzlmod however, `bazel_dep()` is used. The dependency has to be available in [Bazel Central Registry](https://registry.bazel.build) or your [custom Bazel registry](https://bazel.build/external/registry).

`````shell
## MODULE.bazel
bazel_dep(name = "bazel_skylib", version = "1.4.2")
bazel_dep(name = "rules_java", version = "6.1.1")
`````
