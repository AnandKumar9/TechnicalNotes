#### Basics

**GCC** - Legacy compiler for C based languages, had both compiler front-end and back-end. Was debeloped by Ruchard Stallman and used since the 80s.

**Clang** - Compiler front-end for C based languages, feeds into LLVM back-end. Was first used in ~2007, and replaced GCC. Its focus was to have user friendly messages and do faster compilation.

**swiftc** - Compiler front-end for Swift.

**LLVM back-end** - Compiler back-end. Sometimes also known as LLVM CodeGen or Target backend.

> LLVM back-end, clang, swiftc were all developed by Chris Lattner around ~2003, 2007, 2010 respectively. Clang+LLVM combination was so successful that several other major languages (Rust, Julia, Kotlin/Native) then started using LLVM back-end by adding LLVM IR support. <br>LLVM IR was groundbreaking as prior to it no standard compiler front-end output standard existed that could be used across languages, compilers were monolithic. Each compiler front-end (GCC, etc.) used its own private, incompatible IRs.

Compiler front-end has to generate **LLVM IR** (LLVM Intermediate Representation), which in turn becomes input for LLVM back-end. LLVM IR is always in clear text. 

**LLVM Bitcode** is an additional thing generated by compiler front-end for release builds. Its a compact form of LLVM IR and is in binary (hence not clear text). Its used for later for optimizations in App Store pipeline and is use dby linkers.

LLVM back-end then generates machine code which goes inside **object files**.

#### Compiler location

Doing `where swiftc` returns this, which is actually just a **shim** (i.e. something which internally redirects to something in Xcode Toolchain directory)

```
/usr/bin/swiftc
```

To get the location from Xcode Toolchain `xcrun --find swiftc` needs to be done which returns this, that is the **driver** (i.e. something which then decides which binary to actually run like swiftc/clang, etc. Note there is no swiftc in this location)

```
/Applications/Xcode.app/Contents/Developer/Toolchains/XcodeDefault.xctoolchain/usr/bin/swiftc
```

To get the actual swift comiler binary what needs to be done is `$(xcrun --find swiftc)` and it returns the below location, which is the **actual swift compiler front-end binary** and is ~150 MB (Xcode 16, 2025)

```
/Applications/Xcode.app/Contents/Developer/Toolchains/XcodeDefault.xctoolchain/usr/bin/swift-frontend
```
