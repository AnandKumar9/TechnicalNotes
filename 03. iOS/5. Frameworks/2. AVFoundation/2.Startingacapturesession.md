###### Creating a capture session, input and output

To capture anything, first a session (i.e. `AVCaptureSession`) has to be initiated. And creating an `AVCaptureSession` is as simple as just creating an AVCaptureSession object. It does not need any special initializer.
```
let captureSession = AVCaptureSession()
```

Then input (`AVCaptureInput`) needs to be added to the session. An `AVCaptureDeviceInput` is initialized using an `AVCaptureDevice`. The `AVCaptureDeviceInput` object created this way automatically provides an input of the associated capture device’s type to the capture session.
```
let captureInput = AVCaptureDeviceInput(device: self.captureDevice)
```

And then output (`AVCaptureOutput`) is added to session. `AVCaptureStillImageOutput` is used to capture high quality still images. It has however been deprecated in iOS10 and replaced by `AVCapturePhotoOutput` which supports modern features such as live photo, wide-gamut colors, etc. too.

Creating a `AVCaptureStillImageOutput` is as simple as creating a new object.
```
let stillImageOutput = AVCaptureStillImageOutput()
```

Should always do `canAddInput` and `canAddOutput` before adding. `canAddInput` for instance also verifies if the input is already added.

An `AVCaptureInput` vends one or more streams of media data. For example, input devices can provide both audio and video data. Each media stream provided by an input is represented by an AVCaptureInputPort object. A
capture session uses an `AVCaptureConnection` object to define the mapping between a set of `AVCaptureInputPort` objects and a single `AVCaptureOutput`.

Front and back camera inputs have 3 ports each (on 6s).
Audio input (i.e. microphone) has just 1 port.

Possible outputs (i.e. concrete subclasses of `AVCaptureOutput`) - <br>

`AVCaptureStillImageOutput` - For capturing still image along with metadata<br>
`AVCaptureMovieFileOutput` - For getting output as a movie file<br>
`AVCaptureVideoDataOutput` - For processing frames from the video being captured<br>
`AVCaptureAudioDataOutput` - For processing audio dÂata being capture<br>
`AVCaptureMetadataOutput` - For getting metadata, typically used for barcodes and face detection<br>

###### Running through capture devices -

All the capture devices available in a system can be accessed through `AVCaptureDevice.devices()`. Microphone has the media type as `AVMediaTypeAudio`. Back and front cameras are two different devices and the media type for both of them is `AVMediaTypeVideo`. The front and back cameras can be distinguished using the position property. For microphone capture device the position property has the value Unspecified (not Front or Back).

```
let devices = AVCaptureDevice.devices() as! [AVCaptureDevice]
for device in devices {..}

AVCaptureDevice - hasMediaType
if (device.hasMediaType(AVMediaTypeVideo)) {
if (device.hasMediaType(AVMediaTypeAudio)) {
```

Media types:
```
AVMediaTypeVideo, AVMediaTypeAudio, AVMediaTypeText, AVMediaTypeClosedCaption, AVMediaTypeSubtitle, AVMediaTypeTimecode, AVMediaTypeMetadata, AVMediaTypeMuxed
```

```
if (device.position == AVCaptureDevicePosition.Back) {
if (device.position == AVCaptureDevicePosition.Front) {
```

`devicesWithMediaType()` is another method to get all the capture devices of a certain media type.

To display a description of a device to the user, you can use its `localizedName`.

The list of available devices may change. Current input devices may become unavailable (if they’re used by another application), and new input devices may become available, (if they’re relinquished by another application). All these changes can be observed through `AVCaptureDeviceWasConnectedNotification`, ` AVCaptureDeviceWasDisconnectedNotification` and `AVCaptureSessionRuntimeErrorNotification` notifications.

A single session can supposedly take care of multiple inputs and outputs at the same time (need to try this).

The connection between an input and output in a session is represented by an `AVCaptureConnection` object. When inputs and outputs are added to a session, the session automatically forms connections between all the compatible capture inputs’ ports and capture outputs.

> Now when I added a camera input, a microphone input and a still image output to a capture session, the still image output still indeed showed it has just 1 connection, i.e. the one with the camera input.

Capture inputs have one or more input ports.

Capture outputs can access data from one or more sources (for instance `AVCaptureMovieFileOutput` object accepts both video and audio data). 
What it probably means is that if a session has a capture input for a camera and another capture input for a microphone and then it also has a movie output added, then this output can be connected to both the input sources. (Need to try this).

An capture output object has all its connections listed in connections property.

A capture connection object maintains a list of its output (i.e. `AVCaptureOutput` object) and input ports (i.e. the ports of the individual capture input objects that are added to the session). It does not tie itself to the capture input object itself and even with the input ports it does not tie itself to all the ports of the associated capture input objects, but only a subset (why does it not tie itself to other ports?). ###### Starting and stopping a session

The `stopRunning` method of capture session stops the flow of data from inputs to the outputs. It is a synchronous method and in case of a preview layer, the layer just shows the last feed it had received (i.e. an image).

> Always make sure to call `stopRunning` once capture is done. I had weird problems of video feed getting frozen (on app minimization and reactivation) when I was not calling stopRunning in a view controller where the preview layer belonged to a view controller that was a child view controller in a container view controller and I was switching between view controllers.

Both these methods are synchronous methods and hence should be called from a separate serial queue or else the main UI will get blocked.
