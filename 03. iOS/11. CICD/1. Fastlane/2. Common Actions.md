##### Common actions

`gym` - Builds app <br>
`scan` - Run the tests <br>
`clean_build_artifcats` - Probably does a clean <br>
`clear_derived_data` - Clears Derived Data folder <br>
`increment_build_number` - Increments the build no. by 1 <br>

`cocoapods` - Does a pod install <br>
`carthage` - Runs carthage (i.e. probably carthage update) <br>

`add_git_tag` - Adds an annotated git tag to the current branch. The documentation specifies the format used for this tag. <br>
`push_to_git_remote` - Pushes to origin (what is the commit message?) <br>
`ensure_git_status_clean` - Raises an exception and stops there are any uncommitted changes in the main project. Typically put in `before_all`. <br>

`snapshot` - Automates taking localized screenshots on every device
`deliver` - Uploads screenshots, metadata and app to App Store. Works with every single locale. <br>

`sigh` - Downloads and syncs provisioning profiles <br>
`cert` - Downloads and syncs certs <br>
`match` - Allows to create a private github repo of provisioning profiles and `certs` <br>

`hockey` - Uploads to Hockey in some way (need to check this) <br>
`notification` - Creates a OS X notification <br>


###### Scan -

OK, so scan is the action to run unit tests.

By default it stores test results in test_output folder in html format as well as a junit format. Open the report.html file.
And it overwrites the previous run's results files.

```
scan(device: "iPhone X")     // If no device is specified it seems to run on 5S simulator by default
```

###### Slather -

The most common gem used for converting code coverage data to well known formats is slather. To run it, first do a scan with code coverage enabled and then call slather. Not all the attributes given below are mandatory.

```
scan(device: "iPhone X", code_coverage: "true")
slather(
  build_directory: "./derivedData",
  scheme: "PreCustomer",
  proj: "PreCustomer.xcodeproj",
  html: "true",
  cobertura_xml: "true",
  output_directory: outputDirectory
)
```

The `build_directory` attribute is important as slather needs to know where the project's build directory is (that is where the code coverage data gets stored after test/scan). If it is not the default location (which will usually be the case with Carthage), then this must be specified. Or else slather fails.

##### Configuration files

Actions are probably also called tools. And some of the tools have a configuration file too.

scan -> scanfile <br>
deliver -> deliverfile <br>
gym -> gymfile <br>
snapshot -> snapshotfile <br>

`fastlane scan init` - Creates a scanfile

###### scanfile syntax -

```
scheme "Scheme1" -> The scheme to be tested
devices ["iPhone 6s (10.2)", "iPhone 7 Plus(10.2)"]  -> The devices to be tested
```

It seems that if information in a config file conflicts the information fastfile, fastlane does not run. So there should not be any conflicting information.

##### Misc.

`CURRENT_PROJECT_VERSION` build setting needs to be set when incrementing a build number.
Also `ITSAppUsesNonExemptEnryption` key should be set to false in info.plist while doing a deliver.
