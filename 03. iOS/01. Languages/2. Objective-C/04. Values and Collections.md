`NSInteger` and `NSUInteger` are some more scalar types available in Objective-C.
> The difference between them and the usual C scalar types such as int, float is not very clear but it is certain that they cannot be used interchangeably.

It is arguable, but it seems -
1. Use NSInteger, NSUInteger when a API specifically asks for it.
2. Use int, long, etc. when the length of the no. will be small enough to not really matter.
3. Use int32_t, int64_t from stdint.h when the length matters.
4. Use intptr_t, unintptr_t when the int needs to be able to hold a pointer value.

Objective-C collections such as `NSArray`, `NSDictionary`, `NSSet` can only hold objects.
Some of the Cocoa API (such as `NSRange`) uses C structures. C structures can hold primitive types.

`NSValue` works as on object wrapper around basic C scalar types as well as pointers and structures. They can be used to represent them as objects.
`NSNumber` itself is a subclass of `NSValue`.

`NSArray`, `NSDictionary`, `NSSet` are some of the common collection classes.
Rather than maintaining a separate copy of each collected object, these collection classes use strong references to keep track of the contents.
Literal syntax for creating an array - @[obj1, obj2, obj3]
Literal syntax for creating a dictionary - @{@"key1":obj1, @"key2":obj2}
Literal syntax for objectAtIndex: method of NSArray - array[i]

Although the collection classes such as NSArray are themselves immutable, there is nothing to stop their collected objects themselves from changing if their respective data type allows it.
