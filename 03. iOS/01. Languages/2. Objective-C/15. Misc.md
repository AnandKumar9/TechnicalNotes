##### instancetype

`instancetype` - It is a contextual keyword that can be used as a result type to signal that a method returns a related result type. However unlike id, it can only be used as the return type in a method declaration.

In case of methods that start with the words alloc, init even though they return id, the compiler automatically understands that they return an instance belonging to the class for which those methods are declared. This helps as then any method which does not belong to that class is caught during build time itself if attempted to be sent to an instance of that class. But in case of class constructors (such as +array method of NSArray), compiler does not do this automatically and hence such incorrect methods are not caught during runtime. That is where instancetype comes in. If a method's return type is instancetype, the compiler understands that its return type is of a related class and does the type checking accordingly.

The thumb rule is any time there is a class constructor whose name does not begin with init (or alloc in case of an allocation method), have its return type as instancetype. In fact, its a good practice to have it for constructor methods that are instance methods too (not just class methods.)

(If the return type would have been hard coded to the class name itself, it would cause a problem with subclasses. Hence, id/instancetype need to be used. However, it should be kept in mind that instancetype is not available in older compilers.)
Link
Also if instance type is not used and id is used instead, the compiler would not know the return type in case of factory methods and will throw type mismatch warnings.

While initializing a class in the constructor method, always a [[self alloc] init] should be done instead of [[ClassName alloc] init] as this way when the method is inherited by a subclass, it automatically returns the subclass and not the parent class.

##### Singleton class

Singleton class is a class which can have only one instance in the lifetime of an application. Mostly such classes are accessed using a class method called shared<class name>. They are never accessed using an alloc/init or any other initializer method. UIApplication is one such class. When needed, custom singleton classes can also be created from code. (Link)

Typically, a shared class method such as below needs to be created. The class should be referred using this method and never using an alloc/init.

```
+ (instancetype)sharedManager {
    static OfflineLogsManager *sharedManager = nil;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        sharedManager = [self new];
    });
    return sharedManager;
}
```

Any initialization can be done in a method such as this. If a breakpoint is put here, it can be verified that this method is called just once irrespective of how many times the singleton class is used.
```
- (id)init {
    if (self = [super init]) {
        self.appDelegate = (AppDelegate *)[[UIApplication sharedApplication] delegate];
        self.managedObjectContext = self.appDelegate.managedObjectContext;
    }
    return self;
}
```

And then this class can be accessed from the code, in the below way.
```
[[OfflineLogsManager sharedManager] submitOfflineForms];
```

##### Launch arguments and environment variables

For the purposes of debugging an app target, launch arguments and environment variables can be thought to be equivalent—both change the runtime behavior by defining certain values.
Any argument passed on launch overrides the current value in NSUserDefaults for the duration of execution. Environment variables have a wider scope, more along the lines of a global variable. Unless otherwise specified, environment variables are passed YES or NO to enable or disable a particular feature.

UI wise the difference between launch arguments and environment variables is that launch arguments begin with a dash (-) and don't have a separate field for argument values.

##### Enumeration

Fast Enumeration is a feature that allows to iterate through a collection. It essentially is the 'For .. in' construct.
for (StudentGroup *curStudent in exchangeStudents){
     ....
}

A NSEnumerator object is used to traverse through a collection, such as NSArray, NSSet and NSDictionary. The objectEnumerator method configures the NSEnumerator object to traverse the collection in sequence and the reverseObjectEnumerator method configures the NSEnumerator object to traverse to traverse the collection in reverse sequence. The next object in the collection is accessed using the method nextObject.
Using fast enumeration is faster than using NSEnumerator. It is also safe as the collection being traversed cannot be modified during enumeration (i.e. traversal).
for (id obj in [sortedArray reverseObjectEnumerator]) {
 ...
 } //(Here both fast enumeration and enumerator object have been used)

An easy way to reverse an array - reversedArray = [[array reverseObjectEnumerator] allObjects]

##### Designated Initializers

Marking a method as designated initializer.

To clearly mark an initializer method as a designated initializer, the `NS_DESIGNATED_INITIALIZER` macro can be added to it. However, such a method must follow the below rules or else there are warnings shown by compiler.

1. The implementation of a designated initializer must chain to a superclass init method (with [super init...]) that is a designated initializer for the superclass.

2. The implementation of a convenience initializer (an initializer not marked as a designated initializer within a class that has at least one initializer marked as a designated initializer) must delegate to another initializer (with [self init...]).

3. If a class provides one or more designated initializers, it must implement all of the designated initializers of its superclass.

```
- (instancetype)init NS_DESIGNATED_INITIALIZER;
```

##### `isMemberOfClass` on Class cluster.

isMemberOfClass: returns YES if the receiver is of the type specified in the argument. isKindOfClass: returns YES if the receiver if of a type that inherits at any level from the class specified in the argument. However, isMemberOfClass: does not work with class clusters. Class clusters are something that is present a lot in Foundation framework, it basically means that a number of private concrete subclasses are under a public abstract superclass. Both NSString and NSArray are class cluster, hence isMemberOfClass: will not return a YES for them even when the receiver is a NSString or NSArray. In their case, isKindOfClass: should be used.

##### Selectors

The method in an uncompiled source code message to an object is replaced by a unique identifier (of type SEL) when the source code is complied. The term selector can be used to refer to both of them, i.e. the name of method in uncompiled code's message as well as the unique identifier which replaces the method name after compilation.

All methods with same name have same selector. Also, no two selectors in the compiled code can be same.

However, a class method and an instance method can have the same name. Even though this will result in same selector being assigned for them, it is fine as they belong to separate domains.

Remember that in Objective-C jargon, a method name always means the complete name of the method, i.e. along with it's colon signs and all arguments.

The @selector directive allows to convert any passed argument to the type SEL, i.e. it creates a selector for whatever is passed to it as an argument. The argument need not even be an actual method name, it can be anything. This directive will create a SEL identifier for it just as if it really is a method.

SEL selectorName;
selectorName = @selector(initWithNameH:);


NSStringFromSelector function returns the method name for a selector.

NSLog(@"%@",NSStringFromSelector(selectorName));


Similarly NSSelectorFromString function converts a character string to a selector at runtime.
-- What is the practical use of NSSelectorFromString.


One difference between @selector directive and NSSelectorFromString function is that  @selector takes the string without quotes and NSSelectorFromString takes a proper string. Hence, a variable which has the concerned string for the method cannot be used with @selector.


##### String format specifiers

%@ - Objective-C object, printed as string returned by descriptionWithLocale: or description:. (descriptionWithLocale: is a method defined in several classes such as NSArray, NSDictionary, etc. which return a string object that represent their content).

%d - Signed 32-bit integer (i.e. int).
%3d - At least 3 characters for an int. For instant 1 will be shown as 001.

%f - 64-bit floating point number (i.e. double).

%lu - Long unsigned int (may also need to be specified as %lx depending upon no. of bits?)

%02lu - At least 2 characters for the long unsigned int. If there is just 1 , pre-pend with 0.

%c - Characters

%s - In layman terms, used to print C strings. For example, the string returned by the macro `__PRETTY_FUNCTION__`. As per the documentation it stands for a null-terminated array of 8-bit unsigned characters, which is nothing but a C string. Note - @"XYZ" is an object or to be precise a NSString, not a C string.

%p - Prints a void printer in hexadecimal. A void pointer is a reference to any random thing in memory, whereas id is a reference to an Objective-C object in particular. (In simple language, prints the address of the variable.)

(http://developer.apple.com/library/mac/#documentation/Cocoa/Conceptual/Strings/Articles/formatSpecifiers.html)

%% - For printing % literal.

\" - For using quotation mark in a NSString. " is escaped with a \ character. For example - @"\"139\""
