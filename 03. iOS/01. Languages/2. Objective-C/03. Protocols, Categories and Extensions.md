##### Categories

Categories allow to add methods to existing classes, even for the framework classes for which the original implementation source code is not available.

They are declared as below.

```
@interfaceClassName (CategoryName)

@property(nonatomic,strong)NSString*variableC1;
- (void)printVariables;
@end

And then there implementation is done in another implementation block.

@implementationSuperClass (Category)
 - (void)printVariables {
    NSLog(@"X1 - %@", self.variableX1);
}
@end
```

Typically the declaration and definition are placed in separate .h and .m files and named as `ClassName+CategoryName`. All the category methods are available to all the instances of the original object. Just the category .h file needs be imported for that. The category .h file of course itself imports the class's .h file.

Categories can be used to declare instance methods as well as class methods.

They do not allow to declare properties per se, but there is a workaround available to achieve the same behavior.
Properties can be declared in category, then `@dynamic` attribute used for them in the implementation (not `@synthesize` as that will throw a compilation error) and then associated objects can be used to persist the value.

```
#import <objc/runtime.h>

static void *SuperClassKey;

@implementation SuperClass (Category)

@dynamic variableC1;

- (NSString *)variableC1 {
    NSString *result = objc_getAssociatedObject(self, &SuperClassKey);
    return result;
}

- (void)setVariableC1:(NSString *)variableC1 {
    objc_setAssociatedObject(self, &SuperClassKey, variableC1, OBJC_ASSOCIATION_RETAIN_NONATOMIC);
}
```

#### Extensions

A class extension (anonymous category) allows to add methods to a class whose implementation source code is available. It can keep these methods private as they are declared only in the class's implementation file. Unlike regular categories, extensions can even add properties and instance variables.

```
@interface SuperClass ()
@property (nonatomic, strong) NSString *variableE1;
- (void)doPrivateStuff;
@end
```

Extensions are mainly used to extend public interface with private methods or properties and also to redeclare a readonly property as readwrite. If a property declared as readonly in the class interface is redeclared as readwrite in the extension, its set accessor can be used in the class implementation. However, if the property is also redeclared as readwrite in another extension in a separate .h file, then it becomes publicly readwrite as well. The only trick is that it should be declared as readwrite in the class implementation file as well as in a separate class extension interface file and then the class extension interface file should actually be imported in the source code.


#### Protocols

A protocol is used to declare methods and properties that are independent of any class. Any class can then decide to conform to it and provide its own definitions.

```
@protocol ProtocolName <NSObject>
@property (nonatomic, strong) NSString *variableP1;
- (void)doContractStuff;
@end
```

Protocols can also have optional methods which are declared under `@optional` directive.
If a method is marked as optional in a protocol and a class adopts to that protocol, then before sending a message for that optional method to an object of that class a check must be done using `respondsToSelector`: method for that optional method.

Protocols too inherit from other protocols. While creating protocols, it is advisable to adopt it from NSObject protocols.
```
@protocol ProtocolName <NSObject>
```

Following is the syntax to indicate that a class adopts a protocol.
```
@interface SuperClass : NSObject <Protocol1Name, Protocol2Name>
```
