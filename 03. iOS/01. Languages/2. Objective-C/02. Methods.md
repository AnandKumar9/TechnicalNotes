###### Methods

```
- (void)addObserver:(NSObject *)observer forKeyPath:(NSString *)keyPath options:(NSKeyValueObservingOptions)options context:(void *)context;
```
> In the above sample method `declaration`, there are 4 arguments and their types are specified. The method does not return anything as its return type is `void`.

Typically a method includes the parameters' names as a part of its name. The order of parameters in method call cannot be changed and should be just as per the declaration. Also, the convention is to name the methods in camel case, i.e. the first letter of method name as well as all parameter names should be in lower case.

Following is the above method's `signature`. The argument names are not included in it (though the parameter types of course are).

```
-(void)addObserver:(NSObject *)forKeyPath:(NSString *)options:(NSKeyValueObservingOptions)context:(void *)
```

Methods are `called` by sending messages as shown below.
```
[obj methodName];
```
 This entire statement is called a `message expression`. The object on the left side, which receives the message is called the `receiver`. If a method returns something, then it can be assigned to a variable.

 Objective-C also allows the returned value to be ignored by not assigning them to anything.

###### self, super and id

`self` is a pointer that refers to the object had that actually received the message.

`super` is a pointer that refers to the super class of the object that had actually received the message.


`id` is a special keyword which indicates pointer to an object. Its syntax does not have a `*`. However, using `id` does not allow to get compile-time information about the object and hence important errors may not be caught.

###### Object initialization

`+alloc` method is provided by `NSObject`. It makes sure that enough memory is allocated for properties defined by the object and also clears up the memory allocated for the properties by setting them to zero. It also sets the object's retain count as 1 and initializes the object's isa variable to point to the object's class.

`-init` method is also provided by `NSObject`. it returns `id`.
```
SuperClass *obj = [[SuperClass alloc] init];
```

It is possible for `init` to return a different object than was created by `alloc`. Hence, the call to `init` should always be nested during object creation. It should never be as below as then init might have returned a different object, but obj will not be assigned to it.
```
SuperClass *obj = [SuperClass alloc];
[obj init];
```

This may happen when for any reason a class should not be initialized again. One such case is a singleton instance where the object will be allocated when alloc: is called but then init: will only return an already existing singleton instance.

Whenever an object is initialized, it must be checked that it is not `nil` before proceeding. This is important as if for any reason nil is sent, it will not even throw an exception (as in Objective-C messages can be sent to nil) and will be very difficult to debug.

Also, the same object should never be reinitialized. Attempting to do often will throw an exception for most of the framework classes.

`+new` method is also provided by NSObject and is effectively same as calling alloc and init with no arguments.
```
SuperClass *obj = [SuperClass new];
```

An initialization method should do the below before doing the initialization of its instance variables.
```
self = [super init];
if (self) {
     //initialize instance variables here
}
```

`Designated initializer` is the initializer that is most recommended to be used among all the initializer methods that a class may have. It is not any keyword or anything like that. It is advised to even override init to call the designated initializer with suitable default values.

###### Literals

Some classes provide an alternative concise syntax to create instances. These are known as `literals`.

```
NSString - @"" - [NSString stringWithCString:"" encoding:NSUTF8StringEncoding]
NSNumber - @YES, 3.14f, 42, 42L
```

Scalar variables such as int, etc. must be initialized at the time of declaration as they may otherwise contain garbage values However, for object pointers it is not necessary as the compiler automatically sets them as nil if nothing else is specified.

nil is a safe way to initialize an object pointer. A message sent to nil does not do anything.

###### Class methods -

A class itself is actually an object of opaque type called Class. They can receive messages. The methods belonging to the class object are called class methods.

Class methods are denoted by a + sign which differentiates them from instance methods (which use a - sign).

The most common examples of class methods are factory methods. Factory methods are an alternative to object allocation and initialization procedure. However, the receiving client does not own this object and is hence not responsible for releasing it. Factory methods can also be used to implement singleton instances where needed (as in `NSWorkspace`).

Some examples of factory methods.
```
NSString - + (instancetype )stringWithString:(NSString *)aString;
NSDate - + (instancetype)dateWithTimeIntervalSinceNow:(NSTimeInterval)secs
```
