###### What are Blocks

To put it very simply, blocks are inline code that can be executed, assigned to variables and even passed around. (They are known as closures in some other languages.)

In addition to having executable code they can also maintain bindings to automatic (stack) or managed (heap) memory and hence can maintain set of state (data) that it can use to impact behavior when executed. It is a C level feature (hence works with Objective-C and C++ too) and is available in GCC and Clang(?) and is also always an Objective-C object when used in Objective-C.

^ is used to declare a block variable.


###### Blocks syntax

Blocks' syntax is quite similar to that of function pointers, except that ^ is used for blocks instead of *.

A block’s return type need not be explicitly declared if it can be inferred. Also, a block that takes no arguments must specify void in the arguments list, unless the return type can be inferred in which case even the void in arguments list can be left out.

Blocks even support variadic arguments (example?).

Typedefs can also be created for blocks.

Declaring blocks (cheat sheet) - (Link) http://fuckingblocksyntax.com/

As a local variable.
```
returnType (^blockName)(parameterTypes) = ^returnType(parameters) {...};
```

As a property.
```
@property (nonatomic, copy) returnType (^blockName)(parameterTypes);
```

As a method parameter.
```
- (void)someMethodThatTakesABlock:(returnType (^)(parameterTypes))blockName
```

As an argument to a method call.
```
[someObject someMethodThatTakesABlock: ^returnType (parameters) {...}];
```

As a typedef.
```
typedef returnType (^TypeName)(parameterTypes);
TypeName blockName = ^(parameters) {…}
typedef float (^MyBlockType)(float, float);
```

An array of blocks:
```
void (^arrayOfTenBlocksReturningVoidWithIntArgument[10])(int);
```

##### Remembering blocks syntax

There are 3 variants -
1. `returnType(^blockName)(parameterTypes)`

2. `^returnType(parameters){..}`

3. `(returnType(^)(parameterTypes))blockName`

1 is used when a block is declared, as a local variable or as a property. 2 is used when a block is being assigned, as the value of a block variable or as block argument in a method. 3 is used when a block is being declared in a method declaration.
Typedef declaration of blocks is similar to 1.

##### __block modifier

Blocks can access variables declared outside them in readonly scope, however if the variables are declared with `__block` modifier those variables van even be accessed in readwrite mode inside blocks. Technically, this is said as blocks can modify variables in same lexical scope.

`__block` cannot be used with C arrays of variable length and with structures that contain C99 variable-length arrays (what are these?).

##### Copying blocks

Usually there is no need to copy (or retain) blocks. If however a copy needs to be created, it can be done using these C functions. Copying a block moves it to heap.
`Block_copy();` <br>
`Block_release();` <br>
To avoid leak a `Block_copy()` must always be balanced with `Block_release()`. <br>

> Does a block_copy always need to be bridged to return type void as in below.
`Block_copy((__bridge void *)arrangedTeams);`

While using ARC, usually there is no need to use `Block_copy` and `Block_release`. If using MRC, then they needs to be used. When you have a STACK block and want to keep it as a HEAP block (e.g. when you have a block in a function and want it to live after you exited the function!), you need to block_copy it then. ##### Invoking blocks in a debug session

Blocks can be invoked during a GDB debug session.
```
$ invoke-block myBlock 10 20
```

For passing a string it must be enclosed in quotes.
```
$ invoke-block doSomethingWithString "\"this string\""
```

##### Misc.

A block can be copied and passed to other threads and all the variables referenced within the block are preserved for all the copies of the block.

Block variables can also be created within blocks.

A block reference can be casted to a pointer of arbitrary type, and vice-versa. However, a block reference cannot be dereferenced via the dereference operator (*) and a block’s size cannot be computed at runtime.

Within a method if an instance variable is directly accessed, a strong reference is created to self. However, if a reference is made to a copy of that instance variable (which can even happen if that instance variable is assigned to another local variable), then a strong reference is made to the local variable.

At a file level, a block can even be declared as a global literal.

#import <stdio.h>
int GlobalInt = 0;
int (^getGlobalInt)(void) = ^{ return GlobalInt; };
