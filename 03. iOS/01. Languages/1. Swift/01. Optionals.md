##### What is an optional?

An `Optional (i.e. ?)` denotes something which can have a value or can be `nil`. So for something to even possibly have `nil`, it must be declared as an `optional`.
```
let a: Int? = 4
let b: Int? = nil
```

##### Accessing the value of an optional

`Force unwrap operator (i.e. !)` - Can be used on an optional and forcibly gives its value. If however the optional was `nil`, this will cause a crash. This should be barely used.

```
print(a!)
```

`Optional binding` - Shorthand to force unwrap an optional if its not `nil` and assign the unwrapped value to another variable.

```
if let x = str {
    print("\(x)")
}
```
Its also possible to do `if var` (if the unwrapped thing may need to be changed in the following scope) or `if _` (if the unwrapped thing is not even needed, and just a check for it not being nil is needed).

Optional binding can also be done using while loop, i.e. `while let` and there too conditions can be combined.

```
while let line = readLine(), !line.isEmpty {
       print(line)
}
```

Keep in mind though that with optional binding, the unwrapped variable is accessible only in the immediately enclosed scope. (This limitation can be solved by using `guard`)

##### Optional chaining

`Optional chaining` is a way to easily access properties, methods and subscripts of a struct/class/enum, etc. that is an optional itself.  Or even to invoke a closure that was declared as an optional.

When used for querying, it always returns an optional, even though what is eventually being queried is not an optional. And if the thing being accessed is an optional itself, then all these optionals can be chained together.

Here team instance has an optional property called captain which itself has another property called name.

```
if let captain = team.captain?.name {
	print("\(captain)")
}
```

The `?.` is optional chaining which fetches the value on left side as an optional if its not nil.

It can be used with methods, properties as well as subscripts.

Optional chaining on a method.
```
if john.residence?.printNumberOfRooms() != nil {..
```

Optional chaining on a subscript.
```
if let firstRoomName = john.residence?[0].name {.. // Here residence is the optional
```

Can be used to set values too.
```
instance1.property1A?.propertyX = 5
```

In fact it can also be used to simply invoke closures that were declared as optionals.
```
public var torchModeChangeObserver: (() -> Void)?
torchModeChangeObserver?()
```

##### Switching over optional enums

In case of an optional enum, the switch already matches the unwrapped value with the specified cases. (This is allowed since Swift 5.1)

```
let status: BuildStatus? = .inProgress

switch status {
case .inProgress:    // This does not need to be Optional(.inProgress) anymore
    print("Build is starting…")
default:
    print("Some other build status")
}
```

##### map and flatMap

Think of them as ways of applying a transform/closure to an optional to get a new value from it. Lot like `map` in `Sequence` (such as arrays).

`map` - A method for optionals that unwraps the value if any and applies a transform on it. Just as in optional chaining, here too the returned value is an always an optional. And if the optional was nil then it simply returns a nil.

```
let a: Int? = 5
let b = a.map { $0*2 }  // Will give Int? with value 10.
```

`flatMap` - Another method for optionals and its distinguishing factor is that it flattens the optional level by one. So if the transform itself produces an Optional, then the resulting thing is not an optional on that optional. But just the same optional.
```
let a: Int? = 5
let b = a.map { ($0*2 as? Int) }      // Returns Int??
let c = a.flatMap { ($0*2 as? Int) }  // Returns Int?

let d = a.flatMap { $0*2 }  // Still returns Int?
```

##### Comparing optionals
Non-optional values are automatically upgraded to an optional for comparison wherever needed. Hence this works.
```
if regex.characters.first == "^" {
```

And the below is not needed (keep in mind that first method returns an optional).
```
if regex.characters.first == Optional("^") {
```

Optionals do not yet conform to `Equatable` protocol. But they do provide an implementation of `==` operator and hence `==` can be used on optionals.

##### Enums that have a case named `none`

Optionals themselves are implemented as an enum with one of the cases being `.none`. Coonsequently if there is an optional custom enum which itself has a case called `.none`, the compiler treats the instance with those cases as `nil` instead.

```
enum BorderStyle {
    case none
    case solid(thickness: Int)
}

let border2: BorderStyle? = .none    // This is treated like `nil`
```

Swift 5.1 onwards compiler gives a warning for this too.

##### Misc.

Optionals confirm to `ExpressibleByNil` protocol and that is why they can be expressed as nil. This protocol however should not be conformed to by custom types.

`Sentinel values` is the general software engineering term for magic values that actually indicate that there is no value. Kind of like, optionals.
