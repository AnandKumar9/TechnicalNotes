#### Attributes

##### dynamicMemberLookUp
(This was proposed in [SE-0195 User-defined Dynamic Member Lookup Types](https://github.com/apple/swift-evolution/blob/master/proposals/0195-dynamic-member-lookup.md) and implemented in Swift 4.2.)

If a type is declared with the attributed `@dynamicMemberLookUp`, then even if a property of does not exist for that type it can still be accessed using dot notation with the property just specified like a normal variable. The corresponding implementation is provided by a subscript.

```
@dynamicMemberLookup
struct Environment {
    subscript(dynamicMember name: String) -> String? {
      get {...}
      nonmutating set {...}
    }
}

let environment = Environment()
environment.USER
environment.MY_VAR = "Hi"
```


##### dynamicCallable

(This was proposed in [SE-0216 User Defined Dynamically Callable Type](https://github.com/apple/swift-evolution/blob/master/proposals/0216-dynamic-callable.md) and implementd in Swift 5.0.)

It allows a function to be called using the function name as String. Its useful for interoperability to dynamic languages like Python, JavaScript, Perl, Ruby.

```
a = someValue(keyword1: 42, "foo", keyword2: 19)
```
can instead be called as
```
a = someValue.dynamicallyCall(withKeywordArguments: [
    "keyword1": 42, "": "foo", "keyword2": 19
])
```

#### Directives

#### available

Its can be used for checking OS version.

```
if #available(iOS 10, macOS 10.12, *) {
    // This piece runs on iOS10, macOS 10.12 and above, and on minimum deployment target and above (on all other platforms, such as watchOS and tvOS)
} else {
    // Fall back to earlier iOS and macOS APIs
}
```

In fact in such code, the complier also automatically ensures that the included snippets are actually available in that platform.

However in case of declarations such things are better done using `@available` declaration attribute.

PS - In Objective-C, `@available` is a slightly different thing. It is pretty much same as Swift's `#available`. <br>
`if (@available(iOS 11, *)) {`

##### error and warning

`#error` and `#warning` directives can be used to generate errors and warnings.
```
func doSomethingImportant() {
    #warning("TODO: missing implementation")
}
```

##### canImport

`#if canImport()` can be used to check availability of modules.
```
#if canImport(UIKit)
    // ...
#else
    #error("This playground requires UIKit")
#endif
```

##### compilerFlag

```
#if COMPILER_FLAG
  ...
```

##### inlinable and usableFromInline

(This was proposed in [SE-0193 Cross-module inlining and specialization](https://github.com/apple/swift-evolution/blob/master/proposals/0193-cross-module-inlining-and-specialization.md.) and implemented in Swift 4.2.)

Library authors can annotate some public functions as `@inlinable`. This gives the compiler the option to optimize generic code across module boundaries.

It effectively makes the body of the function part of your library’s public interface. If you later change the implementation (e.g. to fix a bug), binaries compiled against the old version might continue to use the old (inlined) code, or even a mix of old and new (because `@inlinable` is only a hint; the optimizer decides for each call site whether to inline the code or not).

Because inlinable functions can be emitted into the client binary, they are not allowed to reference declarations that are not visible to the client binary. You can use the `@usableFromInline` annotation to make certain internal declarations in your library “ABI-public”, allowing their use in inlinable functions.

> Understand this better. Ole's 4.2 Swift playground. Has implications for ABI stability.

##### swift and compiler version

`#if swift` checks if the code is running on a certain Swift version or greater.
```
if swift(>=4.2)
```

`#if compiler` checks if the code is running on a certain compiler version or greater, regardless of which compatibility version the code may be running in (but what is compatibility version).
```
#if compiler(>=4.2)
```

##### targetEnvironment

`targetEnvironment` allows to check if code is running on simulator.
```
#if targetEnvironment(simulator)
```
