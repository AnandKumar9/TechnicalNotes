###### Argument label and parameter name -

Each function parameter has both an `argument label` and a `parameter name` (the variable that is actually used inside the function body) . The argument label is optional, but the parameter name is mandatory. 

In general the use of argument labels can allow a function to be called in an expressive, sentence-like manner, while still providing a function body that is readable and clear in intent.

All arguments having both argument label and parameter name.
```
westerosManager.publishGreeting(to: a, from: b)

func publishGreeting(to greetee: House, from greeeter: House) {
```

If an argument label is not specified, by default the parameter name is used as the argument label while calling the function. 
```
westerosManager.arrangeMeeting(hostHouse: a, house2: b)

func arrangeMeeting(hostHouse house1: House, house2: House) {
```
(Handy when there is no real need to have an argument label that reads differently from the parameter name.)

If an argument label has to be omitted all together while calling the function, then `_` must be specified as the argument label in the function declaration.
```
westerosManager.invite(a, delegateHouse: b)

func invite(_ house1: House, delegateHouse house2: House) {
```

###### Default value for parameter - 

Default value for any parameter can be specified by assigning a value to the parameter after that parameter’s type. If a default value is defined, that parameter can be omitted when calling the function.

While it is not mandatory, it is advised to place the parameters with default values at the end in the function declaration.

```
westerosManager.strengthen(house1: a, withSoldiers: 1000, sentFrom: b)
westerosManager.strengthen(house1: a, sentFrom: c)

func strengthen(house1: House, withSoldiers count: Int = 50, sentFrom house2: House) {
```

###### Variadic parameter - 

A variadic parameter is specified in the declaration by putting `3 dots` after the type and function receives them as an array.

The thing to keep in mind is that a function can have at most one variadic parameter. So its a single parameter that is variadic (and not multiple parameters), however that single variadic parameter can be made to accept multiple values of the specified type.



Also, while calling the variadic parameter the multiple values need to be separated using commas.

```
westerosManager.get(maesters: 1, forHouses: a, c)

func get(maesters count: Int, forHouses houses: House...) {
```

###### inout parameter - 

By default parameters are constants and cannot be changed. If for some reason, they do need to be changed then they need to be specified as `inout` parameters.

Doing so also makes the changed values persist after the function has returned. So in a way it achieves the effect of returning data from function (but is not the same as a function returning data, that is independent of `inout` parameters).

While calling `&` needs to be prefixed to the arguments.
```
westerosManager.swap(house1: &a, withHouse2: &b)

func swap(house1: inout House, withHouse2 house2: inout House) {
```

`inout` parameters cannot have default values and also `inout` parameters cannot be used with variadic parameters.

> `swap` function 👆 has now been replaced with swapAt(_:_:) which takes indices instead of element.

> When may inout parameters may actually be needed? <br>
May be in a situation such as this. A function needs to affect an argument and also return a value. Now one way could be to have the argument stored as a property instead (and then it need not even be passed as an argument), but then a property would need to be created just for this reason. Another way could be to return both the values in a tuple or enum, but then a tuple or enum type will need to be created just for this. So an inout parameter becomes lot cleaner in that case. No need to create a new type or property.

###### Misc. -

###### Every function has a type
And these types can be specified as argument types as well as return types for other functions.

For example,
`(Int) -> Int` denotes a function that takes an Int and returns an Int.
`func chooseStepFunction(backward: Bool) -> (Int) -> Int`  is a function that takes a Bool and returns a function which itself takes an Int and returns an
Int.

The return value of a function can be ignored when it is called.

###### Implicit return type for single-expression functions

This is possible since Swift 5.1.

```
func double(_ number: Int) -> Int {
    number * 2     // No need to specify `return` here.
}
```

###### Overloaded functions are resolved statically at compile time
What it means is that if there are multiple overloaded implementations of functions (i.e. function which differ only in their parameter types and not names), then the version that is chosen while running is decided during compile time itself.

Hence say there is an `overloadedMethod` function with different implementations for UIView and UILabel. Then for an array such as this, the UIView implementation gets invoked on the label as well. That is because at compile time, the type of array is [UIView]. This is however not necessarily true for methods (they work differently).

```
let views = [label, view]
view.forEach { $0.overloadMethod() }
```
