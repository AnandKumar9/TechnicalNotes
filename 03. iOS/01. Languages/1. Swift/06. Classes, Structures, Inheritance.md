##### Value and Reference types

Value types keep a unique copy of their data. That is, if one value type instance is assigned to another then a copy of the data is created. structs are value types and hence keep in mind that when assigning one struct instance to another they both do not actually point to the same data. [link](https://developer.apple.com/swift/blog/?id=10)

##### Difference between struct and class -

Classes and structures share most of the capabilities, and then classes have a few more.

###### Commonalities between classes and structures
1. Both can have properties and methods
2. Both support subscripts
3. Both define initializers
4. Both support extensions and protocols

###### Additional capabilities of classes
1. Classes support inheritance
2. Their instance type can be checked at runtime using typecasting (cannot be done for structs and enums?)
3. Can have deinitializers
4. Reference counting allows more than one reference to a class instance at a time

###### Value and Reference semantics

If a structure instance is created as a constant (i.e. let), then that instance's property cannot later be modified even if that property itself is a variable (i.e. var). This is because when an element of `value type` (which struct is) is marked as a constant, so are all its properties.

This is not however true for `reference types`, as in their case variable properties can be changed later on even if the instance is marked as a constant property.

##### Mutating methods for value types -

In case of a method belonging to reference type (i.e. class), the method can modify a property. However in case of a method belonging to a value type (i.e. structure or enum), by default the instance method cannot modify any property. 

To do so the method declaration must be prefixed with the `mutating` keyword. 

```
mutating func modifyRiver() {
  name = name! + " of Westeros"
}
```
And then a mutating instance method can even assign a completely new instance to self.
```
mutating func modifyRiver() {
  self = River(name: name! + " of Westeros", majorRiver: majorRiver, house: house)
}
```

In case of type properties there is no restriction though and they can be modified from any method without needing mutating declaration.

One more thing to note is that a value type instance initialized as a constant (i.e. using let), cannot have its mutating method invoked as its properties cannot be changed (because the instance itself is marked as constant).


Well another thing is that if a struct has a lazy property, then that lazy property would be initialized only when accessed. As the access will be done only after the struct instance is created, the struct instance should not be a constant (in case that lazy property is accessed) or any computed property that actually accesses that lazy property should declare itself as a mutable getter. ([link1](https://oleb.net/blog/2015/12/lazy-properties-in-structs-swift/) [link2](https://stackoverflow.com/questions/44164578/lazy-var-in-struct/44164693#44164693))

```
var labelText: String? {
    mutating get {
        let date = Date()
        return dateFormatter.string(from: date)
    }
}
```

##### Inheritance -

> Mainly refers to how properties, etc. behave in case of inheritance. So if needed read the properties note first.

Methods, properties, and subscripts can be overridden.

Properties can be overridden either to provide custom getter and setter (like a computed property) or to add property observers.
It is not however possible to provide both an overriding setter and an overriding observer for the same property. It is also not possible to add observers to constant stored properties or read-only computed properties.

Further a read-only computed property cannot be overridden as read-write property. It is however possible to override a read-write computed property as a read-only property.

The subclass does not know if an inherited property is of stored or computed nature. It only knows that the inherited property has a certain name and type.

While inheriting, it is possible to add observers even for computed properties or even if the inherited property itself has observers (both the observers get fired then).

```
var capital: String?
override var capital: String? {
  get {
       return super.capital?.uppercased()
  }
  set {
       super.capital = newValue
  }
}

var soldiers: Int = 500
override var soldiers: Int {
  willSet {
       print("Changing soldiers count for an Elaborate House.")
  }
}
```
Overriding methods and subscripts is comparatively lot simpler than overriding properties. Its just this much for methods (and don't think will be any different for subscripts either).

```
override func viewWillAppear(animated: Bool) {
  super.viewWillAppear(animated) 
```
`super` is used to access the implementation in the super class.

A method, property, or subscript can be prevented from being overridden by marking it as `final`.
```
final var sigil: HouseSigil?
```

##### Declaration attributes -

These are typically used while developing the API for libraries and frameworks.

`available` -
If any declaration has @available before it then that declartion is available (and complied) only when the mentioned condition is met. This condition is availability of mentioned OS platforms and versions(and 3.1 onwards even Swift versions).

`@available(iOS 10.0, macOS 10.12, *)` -
Class class1 {..

`@available`(swift 3.1)

There are quite many more variations of this attribute.
`introduced`, `deprecated`, `obsoleted`, `message`, `renamed`

For example introduced specifies the version from which the declaration is available.

`@available(swift, introduced: 3.0, obsoleted: 3.1)`

This attribute is actually particularly useful when making libraries.

It is also extremely useful to exclude certain declarations from extensions alone.
```
@available(iOSApplicationExtension, unavailable)
public func doSomething() {
    print("Do something")
    let abcd = UIApplication.shared
}
```

> This in fact worked very well. As the build system did not complain even if the framework with this file was imported in an extension. It was however different frameworks (podspecs) that I tried for the main app and the extension.

Here are the various things that can be used as an `@available` attribute.

```

iOSApplicationExtension
OSX
OSXApplicationExtension
tvOS
tvOSApplicationExtension
watchOS
watchOSApplicationExtension
```

`discardableResult` - This is used with function and method declarations and removes compiler warning if the returned value is not even assigned to something while calling the function or method.

##### Memberwise initializer for structs

All structures get a default memberwise initializer, i.e. an initializer need not be custom provided. Also (Swift 5.1 onwards), if any of the properties are already having a value assigned in their declaration, then that also becomes the default value for that property in the memeberwise initializer.

```
struct User {
    var name: String
    var loginCount: Int = 0
}

let piper = User(name: "Piper Chapman")
```
