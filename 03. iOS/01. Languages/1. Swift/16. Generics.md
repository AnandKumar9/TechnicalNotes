#### Generic function

The parameter and return types can be dynamic.

```
func amplify<ElementType>(_ element: ElementType) -> ElementType {
    if element is String {
        return (element as! String).uppercased() as! ElementType
    } else if element is Int {
        return (element as! Int)*2 as! ElementType
    } else {
        return element
    }
}

let amplified = amplify("Norway")
```

```
func modify<ElementType1, ElementType2>(newElement1: ElementType1?, newElement2: ElementType2?, newElement3: ElementType1?) -> ElementType2? {
```

Generics in functions become especially useful when there are multiple types involved and there needs to be some coupling in the types of various arguments (and return type if any).

Its a convention though to have single capitalized alphabets for the placeholder types. <br>
`func modify <T, U>  (newElement1: T?, newElement2: U?, newElement3: T?) -> U? {`

#### Generic type

Generic types are custom classes, structures or enums which have dynamic types associated with them. Something like this.

```
struct Stack<Element> {
    var items = [Element]()
    
    mutating func push(_ item: Element) {
        items.append(item)
    } ..
}

var stackOfHouses = Stack<House>()
var stackOfKings = Stack<String>()

stackOfHouses.push(westerosManager.houses[0])
```

If a generic type is extended (i.e. if it has an extension), there is no need to explicitly specify the type parameters again. They are already available in the extension.

A generic function can be overloaded by providing different constraints, requirements, or both on the type parameters.

#### Generic protocol with Associated types

The daynamic types are called `associated types`. And then while defining a conforming type, the associated type can be specified using `typealias` or can just be inferred.

```
protocol Container {
    associatedtype ItemType1
    associatedtype ItemType2
    
    mutating func appendToType1(_ item: ItemType1)
}

struct WesterosContainer: Container {    
    typealias ItemType1 = House
    typealias ItemType2 = String
    
    mutating func appendToType1(_ item: ItemType1) { .. }
}

struct EssosContainer: Container {    
    mutating func appendToType1(_ item: House) {
    ..
}
```

#### Generic subscript

With generic subscripts, the type returned by a subscript function is determined by the inferred type at the caller site.

```
struct ConformingType {
  subscript<Type2>(key: String) -> Type2? {
      return key as? Type2
  }
}

let b1: Int? = b["2"]
```

And the argument too can have a generic type.

```
extension Collection {
    subscript<Indices: Sequence>(indices indices: Indices) -> [Element] where Indices.Element == Index {
        var result: [Element] = []
        for index in indices {
            result.append(self[index])
        }
        return result
    }
}

let words = "Lorem ipsum dolor sit amet".split(separator: " ")
words[indices: [1,2]]
```

(This was proposed in [SE-0148 Generic subscripts](https://github.com/apple/swift-evolution/blob/master/proposals/0148-generic-subscripts.md), and implemented in Swift 4.)

#### Generic Parameter Clause

Applicable for generic functions and types. <br>
Its the thing between the angle brackets in the declaration, and has the type parameters along with the associated constraints (and requirements on those parameters) if any. The `constraint` can be class, protocol, or protocol composition. <br>

Each of the types are called `Type parameters`.

```
<TypeParameter: Constraint>

func func1<A: UIView, B: Equatable & Hashable>(_ arg: A) -> B? {
```

Note though that constraints can also be specified for generic protcols' associated types. Just that they do not have a generic parameter clause per se, in which the constraints go.

```
associatedtype Item: Equatable
```

#### Generic Where Clause

Applicable for type parameters in generic functions and types, as well as for associated types in generic protocols.

Allows to specify additional requirements that are too complex to be otherwhise specified in generic parameter clause. It consists of the `where` keyword, followed by a comma-separated list of one or more `requirements`.

The requirement specifies that a type parameter inherits from a class or conforms to a protocol or protocol composition. For simple cases, its like a syntactic alternative to constraints in generic where clause.

```
func allItemsMatch<C1: Container, C2: Container> (_ someContainer: C1, _anotherContainer: C2) -> Bool
	where C1.ItemType == C2.ItemType, C1.ItemType: Equatable {

func f1<S: Sequence>(_: S) where S.Iterator.Element: Equatable
```

It can also be spcified that two types need to be identical using `==` operator. In below example, both the types need to conform to Sequence protocol and their elements (Iterator.Element) should also be of same type.
```
<S1: Sequence, S2: Sequence> where S1.Iterator.Element == S2.Iterator.Element
```

#### Contextual Where Clause

Applicable for generic types. Even if a given function of a generic type does not specify any type parameters of its own, that function can still specify a where clause.

Here Container is a generic type, and its average() function is available only when the type argument specifies the mentioned where clause.
```
extension Container {
    func average() -> Double where Item == Int {
```


#### Generic Argument Clause

A term used for actual instances of generic types. It is the complete clause with the actual concreete type.

Here `Dictionary<String, Int>` is the generic argument clause for the mentioned instance of built-in generic type `struct Dictionary<Key: Hashable, Value>`.
```
let dict: Dictionary<String, Int> = ["key1": 1, "key2": 2]
```

#### Conditional Protocol Conformance

(This was proposed in [SE-0143 Conditional protocol conformances](https://github.com/apple/swift-evolution/blob/master/proposals/0143-conditional-conformances.md), and implemented in Swift 4.2.)

Generic types can even be made to conform to a protocol only when type arguments themselves meet certain requirements.

```
extension Array: Equatable where Element: Equatable {
  static func ==(lhs: Array<Element>, rhs: Array<Element>) -> Bool { ... }
}
```

#### Runtime dynamic cast for generic types that have conditional protocol conformance

(This was introduced in Swift 4.2).

Whether the instance of a generic type that declares conditional protocol conformance, really conforms to the protocol or not can even be checked at runtime using `is` operator, or dynamically casted using `as?` operator.

Here as each of the array's elements are encodable, the array is encodable and hence it succeeds. If all the elements of the array were not encodable, the array would not have been encodable. The fact that this can be checked at runtime for an instance of a generic type, is what this allows.

```
let encodableArray = [1, 2, 3]
isEncodable(encodableArray is Encodable)
```


#### Recursive constraints on associated types

(This was proposed in [SE-0157 Recursive protocol constraints](https://github.com/apple/swift-evolution/blob/master/proposals/0157-recursive-protocol-constraints.md) and implemented in Swift 4.1.)

It's also possible for a generic protocol's associatedType to have constraints that reference the enclosing protocol. This wasn't always possible.

```
protocol Sequence {
    associatedtype SubSequence: Sequence
        where Iterator.Element == SubSequence.Iterator.Element, SubSequence.SubSequence == SubSequence
    ....
}
```
