A journal of how to go about unit testing various aspects. Always think what part really needs a unit test and how best to achieve it.

##### Analytics -

Unit tests can be written not just for the metadata of various events but also for the fact that the view controllers are indeed dispatching the correct events. This is demonstrated partly in Swift talk Wrapping Analytics API (talk no. 83) and I have also implemented it in the Precustomer app codebase.

##### Service calls -

Unit tests can be written for actual web service calls being made and seeing if correct data is obtained but this has a dependency on the network. So tests can also independently be written for the fact that request objects have the correct header, body, etc. and that the response mapper maps the received payload correctly (this can be done by running it on mock response files).
