An attachment behavior allows to create an attachment between two dynamic items or between a dynamic item and an anchor point (i.e. one automatically moves if the other moves). Hence an attachment behavior (i.e. attachedBehaviorType property) can be of type UIAttachmentBehaviorTypeItems or UIAttachmentBehaviorTypeAnchor.

The exact kind of attachment depends upon the method used during initialization.

init(item:attachedToAnchor:) - Attaches a dynamic item with a point (termed as anchor point). The distance between the center of the dynamic item and the anchor point remains fixed. Consequently if the anchor point pretty much moves in a circle around the dynamic item, the dynamic item stays quite stationary. Whereas if it the anchor point moves in one direction, the dynamic item follows it. The attachedBehaviorType of the behavior created by this method os of course UIAttachmentBehaviorTypeAnchor.

This method is typically used to create tossing views, where the user can flick a UIView with his fingers. A pan gesture recognizer is created and the gesture’s point is used as the anchor point of the attachment behavior which in turn is tied to the view to be tossed. During the gesture, the anchor point is constantly updated to be that of the current pan gesture location. Hence the view’s center also moves accordingly so that the distance which was initially there remains.

Also, when the pan gesture starts any existing behavior should be removed before a new behavior is added.
([Here](https://www.raywenderlich.com/94719/uikit-dynamics-swift-tutorial-tossing-views) is a link for such code, have tried it too. Tossing views can even be implemented without UIKitDynamics, here are some links - [link1](https://reecon.wordpress.com/2014/03/29/using-uisnapbehavior-to-add-action-to-your-views/), [link2](https://reecon.wordpress.com/2014/04/15/cmmotionmanager-noise-reduction-ios/#more-1575))

Its important to keep in mind that anchorPoint of the attachment behavior can be changed anytime.

For the view rotation to happen too as the flick is done, `initWithItem:offsetFromCenter:attachedToAnchor:` method can be used.
`init(item:offsetFromCenter:attachedToAnchor:)` - What this does is that it creates an attachment between the anchorPoint and a point that is as far from the dynamic item’s center as specified by the offset. 

Hence if lets say the offset has no x dimension and has a y dimension that is half the height of the view, and then the anchorPoint is just at the bottom edge of the view (at center X), the dynamic item moves along with the anchorPoint. And if the anchorPoint and offset center do not coincide, the attachment causes some rotation to happen on the view when the anchorPoint moves. The exact rotation probably happens based on the Physics as determined by the system.
self.attachmentBehavior = UIAttachmentBehavior(item: self.view1, offsetFromCenter: UIOffsetMake(0, 39.0), attachedToAnchor: gesture.locationInView(self.view))

Similarly there are methods init(item:attachedToItem:), 
init(item:offsetFromCenter:attachedToItem:offsetFromCenter:) which create attachment behavior between dynamic items.

There is a `limitAttachmentWithItem(_:offsetFromCenter:attachedToItem:offsetFromCenter:)` method that imposes a maximum separation between two dynamic items (it can work with their center as well as offsets from center) and it hence appears as if there is a rope connecting the two dynamic items. The distance between the two dynamic items is not fixed and hence changes (what exact algorithm it follows though for the separation).

Pin attachment allows to create a kind of rotation of dynamic items about an anchor point.

Sliding attachment needs an axis of translation to be specified as well along with the anchor point. The items can move only along the specified axis. Even a range along the axis can be specified so that the items can move only a certain distance even along the specified translation axis.
