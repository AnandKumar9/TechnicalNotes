**UIKitDynamics** allows to have various physics related animations, i.e. things such as gravitational pull, collisions, field. etc. There are 7 different kinds of animations that are possible and they are known as behaviors.

#### Dynamic animator and behaviors

To add any dynamics first a dynamic animator (UIDynamicAnimator) needs to be created and then the required behaviors (UIDynamicBehavior) created and added to it.

The motion starts as soon as the behavior is added to the animator. While creating a dynamic animator a reference view needs to be specified which may or may not be the main view of the current view controller. All the views in the behaviors added to the animator henceforth should be subviews of this reference view. 

There are 7 different kinds of behaviors. All of them are subclasses of UIDynamicBehavior.

1. Gravity behavior - Views are gravitated downwards
2. Collision behavior - Reaction when views collide with themselves or boundaries
3. Dynamic Item behavior - Physical properties of views such as allowsRotation, charge, etc. changed
4. Push behavior - Views pushed in specified direction (vector)
5. Attachment behavior - Views move in sync with each other or with an anchor point
6. Snap behavior - A spring like motion of a view around a specified point
7. Field behavior - Views subjected to various physical fields such as magnetic field, vortex, etc.

Programmatically, behavior is added to any object that conforms to UIDynamicItem protocol and not instead to a UIView. Now actually UIView as well as UICollectionViewLayoutAttributes conform to this protocol. This even allows collection views to support some UIKitDynamics animations (need to understand this better.) There are tricks though, using which even things such as CALayer can be made to conform to UIDynamicItem and used to some extent ([link](https://www.invasivecode.com/weblog/uikit-dynamics-layer-constraint/)).

The properties in UIDynamicItem protocol are center, bounds and transform. bounds is a readonly property whereas others can be writeable too.

While working with collection view layout attributes, the dynamic animator probably needs to be initialized with init(collectionViewLayout:) method instead of init(referenceView:).

Multiple dynamic items can even be combined together in a single group (UIDynamicItemGroup) so that they together behave like a single item. It preserves the individual collision bounds of the items and the items added to the behavior should not be added to behaviors themselves. A group cannot be added to another group. While creating an array of dynamic items need to be added to it. Thereafter it works just as UIDynamicItem, i.e. behaviors can be added to dynamic item group and the dynamic item group can then be added to animator.

There is even a UIDynamicAnimator delegate that has callback methods for pausing and resumption of animation.

#### UIKitDynamics and Auto Layout

UIKitDynamics does not work very well with views that are using auto layout constraints. If they still need to be used together then probably the behavior should be added only once the constraints have been added and the layout done. Or else adding the behavior before that just removes the constraints. For example, its ok to add the behavior to a subview in viewDidAppear but not in viewWillLayoutSubviews. Also if anything needs to be done with auto layout after the UIKitDynamics animation has happened, it will not work well if the animation did not bring the views back to its original position.

Its possible though to let a view work as per dynamics and then its subviews have constraints. When using with auto layout, if for a particular view auto layout should not be used (i.e. it should act as told by UIKitDynamics), the translatesAutoResizingMasksIntoConstraints should be set as true.

There are tricks to make constraints automatically update with behaviors during the animation. This can be done having a custom object that conforms to dynamic item protocol, animating it and then by updating the constraints’ constants in the behaviors action method. Something like below, here dynamicHub is a custom object that conforms to UIDynamicItem protocol. [link](https://www.invasivecode.com/weblog/uikit-dynamics-layer-constraint/)

```
snapBehavior.action = ^{
    self.topConstraint.constant = [dynamicHub center].y;
};
```
