#### Animatable properties of UIView

frame, bounds, center, transform, alpha, backgroundColor, contentStretch (there aren’t too many).

#### Common UIView animation methods

At UIView level there are several animation methods. 

UIView - animate(withDuration:animations:) [Since iOS4]
UIView - animate(withDuration:animations:completion:) [Since iOS4]
UIView - animate(withDuration:delay:options:animations:completion:) [Since iOS4]
UIView - animateKeyframes(withDuration:delay:options:animations:completion:) [Since iOS7]
UIView - animate(withDuration:delay:usingSpringWithDamping:initialSpringVelocity:options:animations:completion:) [Since iOS7]

All the above methods are block based and were available only since iOS4. What actually happens in the animations block of these method is that the system automatically updates the corresponding layer properties of the specified view properties and then internally creates core animations for them.

Before iOS4, there were several more animation methods in UIView such as beginAnimations(_:context:), setAnimationStart(_:), etc. However the use of the methods is discouraged since i0S2 and the block based methods such as animate(withDuration:animations:), etc. should be used instead.

UIView - beginAnimations:context: 
UIView - commitAnimations (and many more of these)

There are also a few view transition methods that allow a view to have some special animation (known as transition) and also do some more things (i.e. add/remove views themselves or subviews, etc.) alongside. 

##### animateWithDuration

**animate(withDuration:animations:)** is pretty simple. The UIView properties to be animated go inside the block in second argument. Thats it.

```swift
UIView.animateWithDuration(5.0, animations: {
        self.view1.frame = CGRectMake(self.view1.frame.origin.x, self.view1.frame.origin.y, 100, 100)
})
```



**animate(withDuration:animations:completion:)** also has a completion block which executes once the animations have happened. However in this block the finished flag must be checked before the code executes and it should not just be assumed that the block will be called only once all the animations have completed.

```swift
UIView.animateWithDuration(5.0, animations: {
                self.view1.center = CGPointMake(150, 150)
                self.view1.bounds = CGRectMake(0, 0, 100, 100)
                },
                                       completion: {finished in if (finished) {
                                        self.view1.backgroundColor = UIColor.yellowColor()
                                        }})
```



**animate(withDuration:delay:options:animations:completion:)** has a completion block, but then also has a delay argument that can be specified before the animation starts and most importantly also has an options argument in which several options can be specified to fine tune the animation.

##### animateKeyframesWithDuration

**animateKeyframesWithDuration:delay:options:animations:completion**: is a UIView method for doing keyframe animations on animatable UIView properties. It has similar options (i.e. reverse, repeat, etc.) as the usual UIView animation methods. The properties to be changed are specified in the animations block and the keyframes (i.e. the subsequent properties to be animated) also go in the same block and are specified using addKeyframe(withRelativeStartTime:relativeDuration:animations:) method.

```swift
UIView.animateKeyframesWithDuration(10.0, delay: 0, options: [], animations: {
    UIView.addKeyframeWithRelativeStartTime(0.2, relativeDuration: 0.4, animations: {
                    self.view1.backgroundColor = UIColor.yellowColor()
    })
    UIView.addKeyframeWithRelativeStartTime(0.8, relativeDuration: 0.2, animations: {
                    self.view1.backgroundColor = UIColor.blueColor()
    })
                }, completion: {finished in
                    self.view1.backgroundColor = UIColor.greenColor()})
}
```

In addKeyframe(withRelativeStartTime:relativeDuration:animations:) method, the relative start time and relative duration are specified.

**********

**animate(withDuration:delay:usingSpringWithDamping:initialSpringVelocity:options:animations:completion:)** is a UIView method for animating its properties that is similar to the CASpringAnimation on layers. The initial spring velocity should not be set as 0 as then it just turns out to be a usual animation and a spring like effect does not take place.

#### Misc.

Completion block may trigger right away if frame is animated.

If a view’s frame is animated inside the animations block the animation happens all right but the completion block can execute right away instead of after the animations. Whats said in the documentation is that if the transform property contains a non-identity transform, the value of the frame property is undefined and should not be modified. 

A little difficult to understand but true. Its hence better to animate the view’s center and bounds instead ([link](http://stackoverflow.com/a/10560577/1135417)).
During an animation, user interactions are temporarily disabled for the views being animated. This can be configured though.

If any layer property animations are placed inside a UIView animation method block, its not that the layer property animations do not happen. They happen, but usually instantly and totally done by the system. It does not happen as per the duration specified in the view animation method. Apparently you can’t perform sublayer animations in an animateWithDuration: block.

Keep in mind that what goes inside the blocks is not just animatable properties of views, but even auto layout constraints. The constraints can be animated. In fact, they are used lot more often for animation than frame.
