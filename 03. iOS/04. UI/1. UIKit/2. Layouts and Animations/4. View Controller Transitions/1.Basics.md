##### Animator and Context objects

In case of a custom transition of view controllers, the transition is actually done by something called an animator object. This is the object that tells what animation to do, how long should it take, etc.

Now during this animation, the animator object needs to know about both the ‘from’ (i.e. the presenting) view controller as well as the ‘to’ (i.e. the presented) view controller, and several other things too. All this information is provided by the system in something called as a context object and is made available as arguments in several callback methods of the animator object.

Technically,
animator object is something that conforms `to UIViewControllerAnimatedTransitioning` protocol
context object is something that conforms `to UIViewControllerContextTransitioning` protocol

##### Animator object (`<UIViewControllerAnimatedTransitioning>`) -

There isn’t anything in the animator object's protocol that has anything to with interactiveness. The interactive part (if any) of custom transitions is done from methods of another protocol. 

It has just 3 methods.

`transitionDuration(using:)` tells the duration for the current animation transition. Has the transition context object in the argument. The value provided here should be the same value that is used when configuring the animations duration in your animateTransition: method.

`animateTransition(using:)` is the method that should actually perform the animation. Has the transition context object in the argument. This is where the container view should be fetched from the context object and then the required animation done on it.

`animationEnded(_:)` is an optional method and is called once the transition is over.

The animation is typically done using the usual animation methods such as addAnimation:forKey: method of `CALayer`. But then probably the `UIView` animation methods can also be used.

```
let maskLayerAnimation = CABasicAnimation(keyPath: "path")
maskLayerAnimation.fromValue = circleMaskPathInitial.CGPath
maskLayerAnimation.toValue = circleMaskPathFinal.CGPath
maskLayerAnimation.duration = self.transitionDuration(transitionContext)
maskLayerAnimation.delegate = self
maskLayer.addAnimation(maskLayerAnimation, forKey: "path")
```
If you want to draw to the screen directly without a view, use this method to configure a `CADisplayLink` object instead. (What does this mean?)

##### Context object (`<UIViewControllerContextTransitioning>`)

The context object is provided by the system itself and should not be created from the scratch. In other words what it means is that `UIViewControllerContextTransitioning` should not be directly adopted by any class. The system alone should adopt it and the exposed methods can then be used.
`viewController(forKey:)` method returns view controllers involved in transition. The relevant keys `are UITransitionContextFromViewControllerKey`,
`UITransitionContextToViewControllerKey`.

What exactly happens during the transition is not clear yet. But I can assume that there is some interim view controller which has got a root view that has all the animation happening in it. This root view is probably what is known as the containerView and it is exposed by the context object through the method `containerView()`. All the animation, view addition/removal, etc. should be done on this container view.

The animator object is responsible for adding the view of the presented view controller or else the destination (i.e. presented) view controller’s view will not even show up after the transition animation.

To begin with, by default it already seems to be having the from (i.e. presenting) view controller’s root view added to it.

The thing to realize is that the moment transition starts even the destination view controller is actually already ready and available for the animator object.

The `transitionWasCancelled()` method of context object indicates if the transition was cancelled. Calling the cancelInteractiveTransition method causes this method to return true.

The `completeTransition(_:)` method of context object must be called once the transition animation is done and it must correctly indicate if the animation completed successfully. In case of interactive transitions, it must be called in addition to finishInteractiveTransition or cancelInteractiveTransition methods.
A common place to call this method is in the animation’s callback method (such as CAAnimationDelegate callback method).
```
self.transitionContext?.completeTransition(!self.transitionContext!.transitionWasCancelled())
```
##### Interactive animation object (`<UIViewControllerInteractiveTransitioning>`) -

An interactive animation object should conform to the `UIViewControllerInteractiveTransitioning` protocol. This protocol has very few methods but defines the animation curve (which might mean animation pacing), etc.

`UIPercentDrivenInteractiveTransition` is a built-in class that already conforms to `UIViewControllerInteractiveTransitioning` protocol. Why is it called percent driven and how exactly it implements the protocol methods, I currently am not sure of but this object seems to suffice the usual needs and can be used.

It has a few properties such as `duration` (readonly), `percentCompleted`, `animationCurve`.

More importantly it has 3 methods that are used to actually let the interactive animation happen. `update(_:)`, `cancel()`, `finish()`.

If for example the interactive transition is being driven by user gestures, the update method can be used to regularly update the completion percentage which then internally calls the animateTransition and other methods of the animator object appropriately to actually perform the required animation. Similarly calling finish just goes ahead and completes the transition animation.

The `cancelInteractiveTransition()` method of context object notifies the interactive animator object that the transition should be cancelled. It must be followed by a `completeTransition(_:)` method call of the context object.

Now the catch is that the percent driven interactive transition object also has a `cancelInteractiveTransition()` or `cancel()` method which in turn just calls the `cancelInteractiveTransition()` method of the associated context object. And this percent driven interactive transition object method is the one that is used.

Similar is the case with `update(_:)` and `finish()` method of percent driven interactive transition object, they just call the `updateInteractiveTransition(_:)` and `finishInteractiveTransition()` methods of associated context object.

While cancelling an interactive animation,

From interactive animation object -
```
self.interactionController?.cancelInteractiveTransition()
```

In animator object, when animation stops - 
```
self.transitionContext?.completeTransition(!self.transitionContext!.transitionWasCancelled())
```

While updating or finishing an interactive animation,

From interactive animation object - 
```
self.interactionController?.updateInteractiveTransition(completionProgress)
self.interactionController?.finishInteractiveTransition()
```

##### How it works for a navigation controller -

For custom view controller transitions in navigation controller, a custom delegate needs to be assigned for the navigation controller.

Anytime a transition is about to happen, the system calls the delegate’s `navigationController(_:animationControllerFor:from:to:)` method. This method has the navigation controller, the kind of operation (push/pop) for current transition as well as from and to view controllers in its arguments. If the method returns nil, the standard transition happens. If it returns something else (i.e. the animator object, which conforms to `UIViewControllerAnimatedTransitioning` protocol) then that object is asked to perform the transition.

If the navigation controller delegate also implements `navigationController(_:interactionControllerFor:)` , then that method is also called by the system before animation. This method indicates if the view controller transition should be interactive. If nil is returned it is not an interactive transition but if an object conforming to `UIViewControllerInteractiveTransitioning` protocol is returned it is an interactive transition. This method is called after `navigationController(_:animationControllerFor:from:to:)` and contains the animator object in one of the arguments.

Its ok for the navigation controller delegate and the interactive animation object to be the same object.
