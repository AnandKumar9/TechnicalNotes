###### Update Cycle, Layout Pass, and Drawing Cycle

There are 3 passes.

1. Update cycle (in which constraints are calculated or updated)

2. Layout pass (in which layout is determined and the UI laid out, i.e. frames and bounds are calculated)

3. Drawing cycle (in which any necessary drawing is done, i.e. CoreGraphics, etc.)

`Update cycle` happens bottom-up (from subview to super view). `Layout pass` and `drawing cycle` happen top-down (from super view to subview).

Each step depends on the one before it. The display pass (i.e. drawing cycle) will trigger a layout pass if any layout changes are pending. Similarly, the layout pass will trigger updating the constraints if the constraint system has pending changes.

###### Update cycle related methods
 
`setNeedsUpdateConstraints` indicates that the constraints of the receiver view should be updated in next update cycle. The system then calls `updateConstraints` in the next layout pass and recalculates the constraints. Just like `setNeedsLayout` this too is good for performance as it allows multiple constraints to be calculated together in the next update cycle. This method causes the update cycle to happen even if there is nothing new to update.

`updateConstraintsIfNeeded` causes the constraints of the receiver view to be updated immediately if needed. If there is nothing new to update, this method does not cause the update cycle to happen.

`updateConstraints` is a UIView method that gets called when the constraints of a view are being updated (recalculated), i.e. when the update cycle happens. If any verification of constraints, etc. needs to be done it can be done in an overridden implementation of this method. It is also ok to add some constraints here if needed. No constraint should be invalidated or a layout or drawing triggered from this method though.

###### Layout pass related methods

`setNeedsLayout` invalidates the current layout of the receiver view and causes a layout update during next update cycle. It should always be called on the application’s main thread (this probably happens automatically if you just call it in the usual way). Also as it does not cause an immediate layout update, its good from a performance perspective as then more layout updates can be consolidated for one update cycle. This method causes the layout pass to happen even if there is nothing new to layout.

`layoutIfNeeded` causes the layout of the receiver view to be updated immediately. If there is nothing new to layout, this method does not cause the layout pass to happen.

`layoutSubviews` is a UIView method that gets called when a layout of its subviews is done, i.e. when the layout pass happens. This is the method in which system uses the constraints to determine the size and position of the subviews. If for any reason, the constraints are not sufficient for the intended UI then this method can be overridden and the constraints can be tweaked and if needed even the frame rectangles can be directly set here.

So `layoutIfNeeded` updates the layout immediately only if needed (i.e. if any constraint has changed). 

`setNeedsLayout` whereas does not do anything immediately but mandatorily updates the layout in next layout pass, i.e. even if nothing has changed in constraints.

###### Drawing cycle related methods

`setNeedsDisplay` indicates that the receiver view’s should mandatorily draw its contents again in the next drawing cycle.

`drawRect` is a UIView method that gets called when a view draws its contents, i.e. when the drawing cycle happens. This probably means CoreGraphics drawings. It is mandatorily called when the view appears and the call happens after `updateConstraints` and `layoutSubviews` have been called. If nothing is needed in this method, it should not be overridden.

###### Typical sequence in which methods are called when a view controller shows up

```
View Controller - loadView
View Controller - viewDidLoad
View Controller - viewWillAppear
Subviews - updateConstraints
View Controller - viewWillLayoutSubviews
View Controller - viewDidLayoutSubviews
Subviews - layoutSubviews
View Controller - viewWillLayoutSubviews
View Controller - viewDidLayoutSubviews
Subviews - drawRect
View Controller - viewDidAppear
```

Do not create new constraints in `viewWillLayoutSubviews` if not absolutely necessary, it might appear everything rendered well but a lot of duplicate constraints will end up getting created as `viewWillLayoutSubviews` can get called multiple times. Instead create constraints in `viewWillAppear`.

`viewWillLayoutSubviews` is better used for doing anything which can be done only after the bounds are known. Say, a constraint’s constant depends upon topLayoutGuide length then that can be updated here as by this time the layout guides lengths are known.

If the constraints still need to be created in `viewWillLayoutSubviews` for some reason, may be it will be better to first invalidate or remove all its existing constraints.

`viewWillLayoutSubviews` is called when the view controller is about to layout its subviews. It can be called every time a layout pass happens, which can happen automatically if the orientation, etc, change and also forcibly by calling a method such as setNeedsLayout.

`viewDidLayoutSubviews` is called when the view controller has readjusted its subviews, or to be more precise when it has started the layout pass on each of its subviews. It may happen that the subviews’ layoutSubviews method is called after this method.
