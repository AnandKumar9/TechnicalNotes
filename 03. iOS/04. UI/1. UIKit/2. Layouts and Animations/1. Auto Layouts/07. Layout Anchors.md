`trailingAnchor`###### Creating constraints using NSLayoutAnchor

`NSLayoutAnchor` exists to give an easier API for creating constraints. Start with a UIView or UILayoutGuide object you wish to constraint, and select one of that object’s anchor properties. These properties correspond to usual `NSLayoutAttribute` values and are subclasses of `NSLayoutAnchor`.

The amount of code when using `NSLayoutAnchor` is lesser and is also well readable. Also, it provides additional checking in terms of what kind of constraints is being attempted between what kinds of attributes. For example, constraint for horizontal anchors (`leadingAnchor or ``trailingAnchor`) can only be created only with other horizontal anchors. Similarly, multipliers can only be provided for size constraints. These rules are not enforced by the `NSLayoutConstraint` API.

The reason the API looks concise is that now there are different methods for specific kinds of constraints and they are hence simpler. Also properties such as `leadingAnchor`,  topAnchor, etc. have been introduced for UIView and `layoutMarginsGuide`.

```
NSLayoutAnchor > NSLayoutDimension, NSLayoutXAxisAnchor, NSLayoutYAxisAnchor
NSLayoutXAxisAnchor - Used for creating horizontal constraints
NSLayoutYAxisAnchor - Used for creating vertical constraints
NSLayoutDimension -  Used for creating size based constraints
```

UIView does not provide anchor properties for the layout margin attributes. Instead, the `layoutMarginsGuide` property provides a UILayoutGuide object that represents these margins.

Apart from making the code more concise, the layout anchor API can also tell certain errors at compile time instead of runtime.

###### Code snippet using anchors

```
NSLayoutConstraint *cn = [self.imageView.leadingAnchor constraintEqualToAnchor:self.view.layoutMarginsGuide.leadingAnchor constant:0];
cn.identifier = @"ID_6";
cn.active = YES;
```
###### Layout Anchor related methods

Just keep in mind that the moment you write something like self.imageView.leadingAnchor, the anchor type is known and then the appropriate methods show up. For example here, `leadingAnchor` is a `NSLayoutXAxisAnchor` object so `NSLayoutXAxisAnchor` methods will qualify for it (which in turn are nothing but NSLayoutAnchor methods). If however let's say self.imageView.heightAnchor was used, then it would have been of the type `NSLayoutDimension` and `NSLayoutDimension` methods (and there are several) would then have also qualified.

```
NSLayoutAnchor:
- constraintEqualToAnchor:
- constraintEqualToAnchor:constant:
- constraintGreaterThanOrEqualToAnchor:
- constraintGreaterThanOrEqualToAnchor:constant:
- constraintLessThanOrEqualToAnchor:
- constraintLessThanOrEqualToAnchor:constant:

NSLayoutDimension:
- constraintEqualToAnchor:multiplier:
- constraintEqualToAnchor:multiplier:constant:
- constraintEqualToConstant:
- constraintGreaterThanOrEqualToAnchor:multiplier:
- constraintGreaterThanOrEqualToAnchor:multiplier:constant:
- constraintGreaterThanOrEqualToConstant:
- constraintLessThanOrEqualToAnchor:multiplier:
- constraintLessThanOrEqualToAnchor:multiplier:constant:
- constraintLessThanOrEqualToConstant:

NSLayoutXAxisAnchor, NSLayoutYAxisAnchor:
No separate methods in NSLayoutXAxisAnchor and NSLayoutYAxisAnchor. But in each of these NSLayoutDimension methods the anchor type on both sides should be of the same type.
```
