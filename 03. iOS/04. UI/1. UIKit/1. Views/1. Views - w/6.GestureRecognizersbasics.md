Two ways to get touch inputs in a custom view object -
1. Getting the raw touch information, every finger moving, etc.

UIGestureRecognizer is the base class, which is also abstract, i.e. it is never directly used. It's inherited classes such as UIPinchRecognizer are used by the custom view object if required.

There are 2 steps to using a gesture recognizer -
1. Creating a gesture recognizer and adding it to the view. This is usually done by the controller object.
2. Providing implementation for a method to be invoked when the gesture is recognized. This is normally done by the view object, unless the gesture would modify the model or the data to be shown.

'1' is done using two methods together.

- (id)initWithTarget:(id)target action:(SEL)action;
It is declared in UIGestureRecognizer class and is available in classes like UIPanGestureRecognizer as they inherit UIGestureRecognizer. It is the default initializer of UIGestureRecognizer. First argument is the target, i.e. the object which will be sent a message when the gesture is recognized (usually the view object) and the 2nd argument is the selector which is invoked when the gesture is recognized.

- (void)addGestureRecognizer:(UIGestureRecognizer*)gestureRecognizer __OSX_AVAILABLE_STARTING(__MAC_NA,__IPHONE_3_2);
It is declared in UIView class. The argument is the gesture recognizer which is to be added to the view object. 

Here is an example of a controller object creating the gesture recognizer and adding it to the view object using the two above methods.
- (void)setPannableView:(UIView *)pannableView
{

    _pannableView = pannableView;
    UIPanGestureRecognizer *pangr = [[UIPanGestureRecognizer alloc] initWithTarget:pannableView action:@selector(pan:)];
    [pannableView addGestureRecognizer:pangr];

}

There can be a case where the gesture recognizer is added to a view object, but the gesture is handled by a different object. That is when the 1st argument in the 1st method is different from the object to which the 2nd method is messaged (pannableView object in the above example).

Gesture recognizers (UIGestureRecognizer) have a method called locationInView which returns a point indicating where the gesture’s location. Various gesture recognizers override this method as appropriate. In case of a tap gesture recognizer, its simply a matter of where the tap happened. For some other gestures its a point that is a centroid of various touch positions.

CGPoint tapLocation = [tapGestureRecognizer locationInView:self.bug.superview];

While adding gesture recognizer to an image view, the user interaction on the image view must first be enabled. Otherwise the gesture will not be detected. In fact the same might be true for other controls too when you see that gesture is not being detected. Just that in case of image view, the user interaction is already disabled by default.
[self.imageView setUserInteractionEnabled:YES];

Always remember a gesture recognizer once it is not needed. It is often better to remove a gesture recognizer in its action method, i.e. remove it as soon as it is detected. Else there can be issues. For example, when I added a tap gesture recognizer to an image view  I was performing a segue to another view controller from the action method. But sometimes the segue took a second or so before happening and in that time if another tap happened it was treated as two segues. So if I remove the gesture recognizer when the first is detected this problem goes away.

Also, care must be take to remove the gesture recognizer from the subview it was added to and not the view controller’s main view (i.e. the usual self.view).

If a view has several subviews, then the gesture recognizer added to the view also gets detected on the subviews. However care must be taken to have the user interaction set as enabled if any subview is an image view.
