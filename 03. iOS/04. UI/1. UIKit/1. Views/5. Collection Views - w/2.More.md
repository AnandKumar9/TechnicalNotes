Collection view cells provide inherent support for managing their own selection and highlight state. To actually apply a highlight to a cell, custom code needs to be written.

When items are inserted or removed from a collection view, the collection view automatically animates the views impacted by the change. If multiple changes need to be animated together, all the insert, delete and move calls must be made inside a block and that block passed to performBatchUpdates:completion: method. 

By default single item selections are supported in collection views. However, multiple items selection can be enabled and selection can be disabled altogether as well. If the cell’s selectedBackgroundView property contains a valid view it is shown when the cell is highlighted or selected.

The highlighted state and selected state of a cell are different things. The highlighted state is a transitional state that you can use to apply visible highlights to the cell while the user’s finger is still touching the device. This state is set to YES only while the collection view is tracking touch events over the cell. When touch events stop, the highlighted state returns to the value NO. By contrast, the selected state changes only after a series of touch events has ended. Whether the user is selecting or deselecting a cell, the cell’s selected state is always the last thing to change.

*************

If gesture recognizers are to be added, they must be added to the collection view itself (not the collection view controller or anything else). This can be used for various things, such as changing the spacing between the items in a custom layout based on the amount of pinch done with a pinch gesture.

The parameters of custom gesture recognizers can be modified when they may conflict with default gesture recognizers. For example, a custom tap gesture may conflict with the tap gesture that is present by default for selecting and highlighting. In such a case, a tap gesture can be configured with 2 taps needed for the gesture to be recognized.

*************

When any section or item needs to be added, removed or moved the datasource must be updated before notifying the collection view of the changes.

When the user performs a long-tap gesture on a cell, the collection view attempts to display an Edit menu for that cell. However the following delegate methods must be implemented and some conditions must be met for that.

-collectionView:shouldShowMenuForItemAtIndexPath: (must return YES)
-collectionView:canPerformAction:forItemAtIndexPath:withSender: (must return YES for at least one of the desired actions) 
-collectionView:performAction:forItemAtIndexPath:withSender:

cut:, copy:, paste: are the actions supported by a collection view cell.     

*************

If the spacing or size of items in a flow layout needs to be dynamic, it can be done using UICollectionViewDelegateFlowLayout protocol methods.

UICollectionView method visibleCells should never be called from the layoutAttributesForElementsInRect: method of a custom layout class.

When a collection view is scrolled, the scroll view automatically calculates the resting place depending upon the current speed and deceleration rate. This position can be received as well as modified using targetContentOffsetForProposedContentOffset:withScrollingVelocity: method.
