UIAppearance -

The idea behind UIAppearance is that it allows to configure some selected properties of all instance of certain views  and controls all throughout the app. Hence, I could have all the UIButtons across the app have the same titleColor without having to configure it separately for each and every button. Technically, it is a protocol (it had to be a protocol instead of a property or method in UIView directly as there are UI classes such as UIBarButtonItem which do not subclass from UIView) and has two methods.

+appearance - This returns the appearance proxy of the receiver, hence it can be used when the change has to be made to the instances of a UI class all across all the application. After this code has run, all the pageControls across the app will have these properties.

```
UIPageControl *pageControl = [UIPageControl appearance];
pageControl.pageIndicatorTintColor = [UIColor lightGrayColor];
pageControl.currentPageIndicatorTintColor = [UIColor blackColor];
pageControl.backgroundColor = [UIColor whiteColor];
```

+appearanceWhenContainedIn - This returns the appearance proxy of the receiver in a given containment hierarchy. Hence, this should be used when a UI class has to be made consistent only when it falls in the view hierarchy of another class.

[[UIBarButtonItem appearanceWhenContainedIn:[UINavigationBar class], nil] setTintColor:[UIColor lightGrayColor]];
[[UIBarButtonItem appearanceWhenContainedIn:[UINavigationBar class], [UIPopoverController class], nil]
     setTintColor:myPopoverNavBarColor];

The properties set in appearance proxy can still be overridden later if they are explicitly set for any specific class.

Not all methods and properties conform to UIAppearance. Here  is a link which mentions the conforming properties as of iOS 7. Normally, the properties that can be used with UIAppearance have the macro UI_APPEARANCE_SELECTOR in their signature in the header files. That is the only sure way to say whether a property can be customized using UIAppearance. Following is a sample signature.

- (void)setTitlePositionAdjustment:(UIOffset)adjustment forBarMetrics:(UIBarMetrics)barMetrics UI_APPEARANCE_SELECTOR;

UIAppearanceContainer is another protocol which just declares the UI_APPEARANCE_SELECTOR macro which indicates that a method which has it in its signature will respond to UIAppearance.

To make a custom UIView subclass use UIAppearance, some more things need to be done. Firstly of course the required properties should have UI_APPEARANCE_SELECTOR macro in their declaration. But their can be some more work needed if the class has custom initializers. (link)
@property (nonatomic, strong) UIColor *rectColor UI_APPEARANCE_SELECTOR;

UIAppearance also supports customization for trait collections (i.e. adaptive layouts) through the
appearanceForTraitCollection: method, which returns a new appearanceProxy for the passed traits collection alone.

UIResponder -

UIResponder class defines the interface for objects that respond to and handle events. Both UIApplication and UIView all of them are its subclasses. Instances of UIResponder are also referred to as responder objects or responders.

There are two kinds of events - touch events (i.e. finger touch, swipe, etc.) and motion events (i.e. shaking of device, etc.).

The primary event handling methods for touches are touchesBegan:withEvent:, touchesMoved:withEvent:, touchesEnded:withEvent: and touchesCancelled:withEvent:.
Anytime a finger touches the screen, is dragged on the screen, etc. touch events (i.e. UITouch objects) are generated. These responder methods are automatically called during these touch events.

Making the status bar same colored as its underlying view -

In app delegate, add this -
CGFloat height = [UIApplication sharedApplication].statusBarFrame.size.height; //Usually 320
CGFloat width = [UIApplication sharedApplication].statusBarFrame.size.width; //Usually 20

UIView *view = [[UIView alloc] initWithFrame:CGRectMake(0, 0, width, height)];
view.backgroundColor = [UIColor colorWithRed:190/255.0 green:0/255.0 blue:3/255.0 alpha:1.0];
[self.window.rootViewController.view addSubview:view];

The below are also mentioned as possible solutions, but they didn’t work.
In app delegate, add -
[UIApplication sharedApplication] setStatusBarStyle:UIStatusBarStyleLightContent];

Or in info.plist, add -
Status bar style - UIStatusBarStyleLightContent

Having the status bar font color as white (in iOS 8) -

Add these keys in info.plist -
View controller-based status bar appearance - NO
Status bar style - UIStatusBarStyleLightContent

Rather put this in the code instead of the having corresponding key in info.plist.
[[UIApplication sharedApplication] setStatusBarStyle:UIStatusBarStyleLightContent];

Setting the font color of items in navigation bar (at least iOS 7 onwards) -

Add this in app delegate -
[[UINavigationBar appearance] setTintColor:[UIColor redColor]];

Adding a right bar button item in a navigation bar -

UIBarButtonItem *rightBarButtonItem = [[UIBarButtonItem alloc] initWithImage:[UIImage imageNamed:@"menu"] style:UIBarButtonItemStylePlain target:self action:nil];
self.navigationItem.rightBarButtonItem = rightBarButtonItem;

There is no off the shelf way to do it globally for all the view controllers. Bar button items are associated with each of the view controllers separately and not to the navigation controller.

Assign a custom view controller to main window -

self.window = [[UIWindow alloc] initWithFrame:[[UIScreen mainScreen] bounds]];
self.window.rootViewController = [[SMViewController alloc] initWithNibName:@"SMViewController" bundle:nil];
[self.window makeKeyAndVisible];

So it is probably like this. A device can be connected to multiple displays (or screens), its main screen can be found through UIScreen +mainScreen. Then again a screen can have multiple windows (i.e. full screen windows) in it and the key window can be found through UIWindow -keyWindow. A window can be made key using UIWindow -makeKeyAndVisible. And then finally the root view controller of the window is set through the property rootViewController.

Locking screen orientation -

The API to lock a UI to be portrait-like is kind of distributed.
	1. There are UIViewController's supportedInterfaceOrientations and preferredInterfaceOrientationForPresentation.
	2. And yet all of this gets superseded by any applicable navigation controller's UINavigationControllerDelegate's navigationControllerSupportedInterfaceOrientations. If there are multiple nested navigation controllers, then the innermost's configuration takes precedence.

iPhone X changes -

Status bars no longer changes heights with background task (location tracking, phone call, etc.) on X (instead there are color indicators).

Keep in mind that by default swipes over home indicator are not accepted, but taps are. So even if a table view cell underlaps the home indicator, it can still be tapped.
