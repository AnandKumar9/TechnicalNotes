Layer properties are typically animated using Core Animation classes. 

CAAnimation -> CAPropertyAnimation, CAAnimationGroup, CATransition
CAPropertyAnimation -> CABasicAnimation, CAKeyframeAnimation
CABasicAnimation -> CASpringAnimation

`add(_:forKey:)` is the animation method at CALayer level. It is used for all 3 animations - basic, keyframe as well as spring.
frame is not an animatable property in layer. But bounds, anchorPoint and position are.

All animatable layer properties - [link](https://developer.apple.com/library/ios/documentation/Cocoa/Conceptual/CoreAnimation_guide/Key-ValueCodingExtensions/Key-ValueCodingExtensions.html)

**********

CABasicAnimation provides animation capability for a layer property (i.e. a property which is animatable).

The layer property to be animated is specified as a string in the keyPath property. The values it should animate from and to are specified in fromValue and toValue.

```
let animation1 = CABasicAnimation(keyPath: "contentsRect")
animation1.fromValue = value1
animation1.toValue = value2
animation1.duration = 1
animation1.repeatCount = Float(Int.max)
self.view.layer.addAnimation(animation1, forKey: "Animation 1") 
```

It should be kept in mind that once the animation is over, by default the initial value of the property is once again restored. 

CABasicAnimation inherits from CAPropertyAnimation. There is a boolean property in CAPropertyAnimation called additive which indicates if the value given by the animation (which values, fromValue or toValue?) should be added right away in the render tree. Usually this is not needed, but sometimes it can be useful (need to understand it better).

CAKeyframeAnimation allows the animation for the specified layer property to happen between multiple values and not just a single fromValue and toValue. The fraction of the entire duration when these values should be reached can also be specified. It is a subclass of CAPropertyAnimation.

```
let animation2 = CAKeyframeAnimation()
animation2.keyPath = "contentsRect"
animation2.values = [value1, value2, value3, value1]
animation2.keyTimes = [0, 0.7, 0.9, 1]
animation2.duration = 3
animation2.repeatCount = Float(Int.max)
self.l1.addAnimation(animation2, forKey: "Animation 2")
```

If the calculationMode property is kCAAnimationDiscrete, then no interpolation happens between the specified keyframes and the animation just jumps from one keyframe to another.

When animating a value that is a coordinate point, such as the layer’s position,  instead of individual values even the path to be followed for that point can be specified. In such a case anything specified in values property is ignored. calculationMode property determines how the animation proceeds. It has possible values such as kCAAnimationLinear, kCAAnimationDiscrete, kCAAnimationPaced, etc. kCAAnimationPaced or kCAAnimationCubicPaced give a smooth constant velocity along the
path. kCAAnimationLinear gives a simple interpolation along the path.

There is also a rotationMode property in case of path based keyframe animations that specifies if the animating object should also rotate itself as it animates along the path. By default its nil, but the possible values are kCAAnimationRotateAuto and kCAAnimationRotateAutoReverse.

**********

CASpringAnimation is a subclass of CABasicAnimation and it allows the animation for a layer property to happen between the specified fromValue and toValue using a spring like oscillating and damping animation. The duration cannot be directly assigned, instead the settlingDuration should be specified as the duration.
```
let animation4 = CASpringAnimation()
animation4.keyPath = "position.x"
animation4.damping = 5
animation4.fromValue = self.l1.position.x
animation4.toValue = self.l1.position.x + 100.0
animation4.duration = animation4.settlingDuration
animation4.repeatCount = Float(Int.max)
self.layer1.addAnimation(animation4, forKey: "Animation 2")
```

Pacing the animation -

The timingFunction method of CAAnimation can be used to set the pacing of the animation. By default its nil which indicates liner pacing. However a custom object of CAMediaTimingFunction type can be assigned to it to have custom pacing. 

There are also some already available standard pacings.

kCAMediaTimingFunctionLinear
kCAMediaTimingFunctionEaseIn
kCAMediaTimingFunctionEaseOut
kCAMediaTimingFunctionEaseInEaseOut
kCAMediaTimingFunctionDefault.
animation2.timingFunction = CAMediaTimingFunction(name: kCAMediaTimingFunctionEaseIn)
functionWithControlPoints can be used to create a custom pacing.

Keyframe animations can also have a timingFunctions property that can have different timing functions for different keyframe segments.

Starting the animation after a delay -

CAAnimation also conforms to CAMediaTiming protocol which has a beginTime property. This property can be used to alter the time scale of the animation when compared to the object to which it is added. And hence it can delay the basic animation.
let animation1 = CABasicAnimation(keyPath: "contentsRect")
....
animation1.beginTime = CACurrentMediaTime() + 2.0
self.layer1.addAnimation(animation1, forKey: "Animation 1”)

CAAnimation methods do not have any delay argument, so this property can be used to start the animation after a delay.


Not reverting back to previous state after animation - 

By default, a CAAnimation falls back to its model layer values (i.e. before animation values) once the animation completes. However, it is possible to not remove the presentation layer on completion using the below properties.

animation1.fillMode = kCAFillModeForwards
animation1.removedOnCompletion = false

However it is not advisable as it causes unnecessary overhead by keeping animation objects around. Besides its also advisable to keep model layer in sync with the UI. Instead to not let the UI go back to its pre-animation state, the model layer’s values should be updated directly after the animation gets over (but how as here is no completion block in these methods?). This should however be done before adding the animation object to the layer or else it will feel as if an additional animation is happening.

self.l1.contentsRect = // new value
.. create animation object ..
self.l1.addAnimation(animation1, forKey: "Animation 1")

Animation object is copied when added to a layer -

The thing to note though is that as soon as a core animation object is added to the layer, a copy of it gets attached to it. Hence modifying the animation object in anyway after that does not affect the animation already added to the layer. Hence, this will not have any effect on the begin time.
```
self.layer1.addAnimation(animation1, forKey: "Animation 1")
animation1.beginTime = CACurrentMediaTime() + 2.0
```
byValue - 

byValue property indicates the value by which the fromValue should be incremented.
No more than any two of fromValue, byValue and toValue should be non-nil for an animation object.
