Auto Layout is an alternative to hard coded layout. Frames are created automatically by the system using the specified constraints, i.e. the relationships between various views in the scene. It is not an app level setting and can be selectively turned on or off individual scenes or view controllers through `File Inspector -> Use Auto Layout`. With Auto Layout there is no more `setFrame:` that happens from the code.

Before auto layouts below 2 methods were bring used -

1. Frame for each view set programmatically and recalculated and set every time a change occurs. <br>

2. Autoresizing mask to automate some of the changes. However there isn't much they could do.


###### When does Auto Layout make things easier

External changes: (Size or shape of superview changes. Some happen at runtime, some like a different screen size don't.)
The user resizes the window (OS X).
The user enters or leaves Split View on an iPad (iOS).
The device rotates (iOS).
The active call and audio recording bars appear or disappear (iOS).
The user enters or leaves Slide Over on an iPad (iOS).
You want to support different size classes.
You want to support different screen sizes.

Internal changes: (size of view changes)
The content displayed by the app changes. (for example a view's size might depend upon its content)
The app supports internationalization. (takes care of changing label size, date and time conventions as well as left-to-right or right-to-left direction.)
The app supports Dynamic Type (iOS). (font size changes, this affects views' size).

###### What is a constraint

A constraint can be thought as following. 
```
(item1Attribute) = Multiplier*(item2Attribute) + Constant
```
In addition a constraint also has a priority which can be from 0 to 1000. Further, the relationship need not always be an ‘=‘ but can also be ‘<=‘ or ‘>=“.

Inequality relations can be used in constraints but by the end of it the view's position and size should still be uniquely determinable through the other constraints or else an error is shown in the document viewer. An inequality relation constraint by itself does not uniquely establishes the concerned view's size and position.

The thing with inequality constraints is that as long as they are satisfied, the system will not care for any more. It does not matter how close it was.

Constraints with a priority of 1000 are required. All other constraints are optional.

###### Items and attributes in a constraint equation

The items in a constraint equation can represent either views or layout guides.

Attributes can be the four edges (leading, trailing, top, and bottom), as well as the height, width, and vertical and horizontal centers. In case of text items they can even be one or more baseline attributes. <br>

Programmatically they are represented by the enum `NSLayoutAttribute`.

`NSLayoutAttributeBaseline`

`NSLayoutAttributeLastBaseline `(For objects with more than one line of text, it is the baseline for bottommost line of text.)

`NSLayoutAttributeFirstBaseline `(For objects with more than one line of text, it is the baseline for topmost line of text.)

There are also attributes for margins (left, top, right, bottom, leading, trailing and even center X, center Y).

`NSLayoutAttributeNotAnAttribute` can be used when the attribute of 2nd item doesn't matter, which might happen in a constraint such as item1.height >= 40. In such a case 2nd item in the equation can be nil and its attribute can have the enum value `NSLayoutAttributeNotAnAttribute`.
