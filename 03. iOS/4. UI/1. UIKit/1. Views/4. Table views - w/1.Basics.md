Section header and footer can display image too, and not just text.

Table view can have its own header and footer too, distinct from the section headers and footers.

Plain table view is an unbroken list and a grouped table view has visually distinct sections.

While creating the attributes of a table view in storyboard, two types of cell content can be specified - static cells which are used when no. of rows is fixed with each having its own layout; dynamic prototypes in which no. of rows, etc. can be dynamic and one cell can be designed and used as template for all cells.

When a table view entered editing mode, there are controls displayed for insertion, deletion and reordering of rows.

Table view cell styles and accessories -

Table view cells can have background views as well as accessory views. Usually a table view cell has 3 default content elements - main label, detail label, image. There are 4 standard cell styles (left detail, right detail, etc.) available by default and they place these default content elements in different positions. A custom cell can also be created to give a totally customized style to the table view cell.

Standard Table view cell styles -

1. Default (UITableViewCellStyleDefault). Single title and an optional image on the left.
2. Subtitle (UITableViewCellStyleSubtitle). A title with a gray subtitle under it, an optional image on the left.
3. Right Detail (UITableViewCellStyleValue1). Title on the left, subtitle on the right.
4. Left Detail (UITableViewCellStyleValue2). Title on the right, subtitle on the left.

Standard accessory views -

1. Disclosure indicator (UITableViewCellAccessoryDisclosureIndicator). 
2. Detail disclosure button (UITableViewCellAccessoryDetailDisclosureButton). 
3. Checkmark (UITableViewCellAccessoryCheckmark).  


Indexed lists and selection lists-

Plain table views can also have index associated with sections for quicker navigation. Such table views are also known as indexed lists. The rows in such table views should not have disclosure indicators or detail disclosure buttons as they interfere with the positioning of the index.

UILocalizedIndexedCollation is a convenience class that helps to organize the data in case of indexed lists.
Indexed lists can be implemented using sectionIndexTitlesForTableView: and tableView:sectionForSectionIndexTitle:atIndex: methods. The sectionForSectionIndexTitle:atIndex: method returns the section no. to be scrolled to when the user taps an index. It is not that every section needs to have a unique index for it, in fact there can be sections with no corresponding index. Hence, sectionIndexTitlesForTableView: and sectionForSectionIndexTitle:atIndex: are different methods. One just returns an independent array of strings for indexes and the other one actually says which section to go to when an index is tapped.

Table views that allow selection on rows and then show checkmarks for the selected rows are also known as selection lists.

DataSource, Delegate and some other tidbits - 

UITableView inherits from UIScrollView.It of course has the datasource and delegate property too which allow finer control on various data and visual appearance related tasks. However, actually UITableView too itself has methods for most of the methods that the datasource and delegate protocols provide. It has methods for all table view activities such as providing a cell, specifying the row height, moving rows, etc.

UITableViewDataSource protocol has just 2 required methods - tableView:numberOfRowsInSection: and tableView:cellForRowAtIndexPath:. UUITableViewDelegate protocol does not have any required methods.

UIKit declares a category on NSIndexPath that specify a section and row index for NSIndexPath and hence NSIndexPath is used easily with table views.

Scrolling a table view causes an invocation of tableView:cellForRowAtIndexPath: for each newly visible row.
tableView:willDisplayCell:forRowAtIndexPath: method is called just before a cell is drawn. This method should be used only to modify the display related properties of a cell, it should not be used to modify the content.


UITableViewController -

UITableViewController inherits from UIViewController. It manages a single table view and even though it has very few exposed methods of its own, it takes care of lot of boilerplate code .

Following are some of the things done by table view controller -

1. By default sets itself as the datasource and delegate for its table view.
2. When the table view is to appear for the first time, the table view controller sends reloadData to the table view  which allows it to reload the data from its data source. 
3. Clears selections when table view is about to be displayed. (isn’t the selection retained while coming back?)
4. Flashes the scroll indicators when the table view finishes displaying.
5. Responds properly when user taps on edit button by putting table view in editing mode and again when the user taps done.
6. Provides support for NSFetchedResultsController
7. Automatically scrolls to the row being edited if the row has a text field.
8. Automatically reacts to keyboard notifications.
9. Provides automatic support for 'pull to refresh'. Was the only way to implement the default 'pull to refresh' until iOS7. But may be more view controllers provide this support now.

If a table view in a storyboard is static, the custom subclass of UITableViewController should not implement the data source protocol. Instead, the table view’s data should be populated in viewDidLoad method. Typically, static table views have fixed controls that have separate outlets for each row to the view controller and they can be configured in viewDidLoad.

If the view to be managed consists of multiple subviews, only one of which is a table view then a UIViewController subclass should be used instead of a UITableViewController subclass. A UITableViewController is optimized to make its table view fill the screen between the navigation bar and the tab bar (if either are present).

And if a UIViewController is used to manage a table view, any selection in the table view should be cleared while displaying using the deselectRowAtIndexPath:animated: method and after the table view has been displayed the scroll view indicator should be flashed using flashScrollIndicators method.

If the screen needs to have more elements than a table view and you still want to have the convenience of table views, then the table view controller can be added as a  child view controller to that screen.
