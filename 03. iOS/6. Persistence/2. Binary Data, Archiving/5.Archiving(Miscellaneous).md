###### Making substitutions during coding

There are methods that allow the object being encoded or decoded to substitute a replacement class or instance for itself. This is especially used by class clusters. Such methods are generally known as substitution methods.

There are following substitution methods declared in `NSObject` protocol itself.

`classForCoder` (allows to specify a different class to be used during encoding. For example, a class cluster subclass specifying its public superclass) <br>
`replacementObjectForCoder:` (allows to specify a different object to be used during encoding)
awakeAfterUsingCoder: (allows to specify a different object to be used during decoding)

There are more methods. <br>
`classForArchiver` (NSArchiver) <br>
`replacementObjectForPortCoder:` (NSPortCoder) <br>

###### Restricting coder support

In methods such as `encodeWithCoder:`, etc. it is always possible to stop the archiving if needed by throwing a `NSInvalidArchiveOperationException`. For example, a coder may chose to encode only if the coder is of type `NSKeyedArchiver` and use this method top achieve that.

```
- (void)encodeWithCoder:(NSCoder *)coder {
      if ([coder isKindOfClass:[NSKeyedArchiver class]])
          // encode object
      else
          [NSException raise:NSInvalidArchiveOperationException format:@"Only supports NSKeyedArchiver coders”];
}
```

###### Encoding and decoding other data types

There are special methods (such as `encodeInt:forKey:`, `encodeDouble:forKey:`) in `NSKeyedArchiver` and `NSKeyedUnarchiver` for working with non object data types.<br><br> These non object data types even include booleans, byte arrays, NSPoint, NSSize, NSRect. However, there are no methods for aggregate types such as structures, arrays and bit fields.

Pointers cannot be encoded and decoded back to something useful. Instead, the information which the pointer is pointing to must be encoded.

###### Forward and backward compatibility

Keyed encoding supports forward and backward compatibility. What it means is that a class can be made to work with an archive that was created using a previous version of the class and also a class can deal with an archive which was created using a newer version of the class. However, all possibilities need to be accounted for in the methods and all keys that can come up during the process need to be considered. `containsValueForKey:` is one method that often needs to be used for checking if a key is there in the archive.

###### Subclassing NSCoder

While defining a subclass of `NSCoder`, if the custom class does not need to support keyed coding, at least the following NSCoder methods must be overridden.
```
encodeValueOfObjCType:at:
decodeValueOfObjCType:at:
encodeDataObject:
decodeDataObject
versionForClassName:
```

If however, it should support keyed coding then `allowsKeyedCoding` (should return YES) and all the keyed coding methods of NSCoder must also be implemented.

> NSArchiver and NSUnarchiver have been replaced by NSKeyedArchiver and NSKeyedUnarchiver respectively OS X 10.2 onwards.

> Is archiving and unarchiving available only in OS X and not in iOS? No its available in iOS as well.

###### Performance considerations

It is better to decode the value for a key than to check if it exists and then decode it. `containsValueForKey:` should be used only when it needs to be distinguished if the returned value is a default value or the real value.
