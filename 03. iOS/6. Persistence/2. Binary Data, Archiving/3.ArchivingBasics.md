###### What is archiving

Archiving allows to store an arbitrarily complex object graph as binary data in files. It retains the identity of every object and while unarchiving, with a few exceptions can be used to create an exact copy of the original object graph.
> In general, encoding and decoding is not something very fast. Its forte is simplicity.

###### What can be archived

An object must conform to `NSCoding` protocol to be be archivable. Most of the classes support it.<br>
> Archives cannot hold types whose implementations vary across platforms, such as `void *`, function pointers and long chains of pointers.

###### Coder Classes

`NSCoder` is an abstract class that provides the API for transferring objects and data items between memory and some other format.<br>The concrete subclasses of `NSCoder` are `NSArchiver`, `NSUnarchiver`, `NSKeyedArchiver`, `NSKeyedUnarchiver`, and `NSPortCoder`.<br><br>
They are referred to in general as coder classes, and instances of these classes as coder objects.

Keyed archives are created by `NSKeyedArchiver` objects and decoded by `NSKeyedUnarchiver` objects. They differ from sequential archives in the sense that every value encoded in a keyed archive is given a name or key. Key names should not use $ as prefix as it is used internally by the archiver classes.

Both `NSKeyedArchiver` and `NSKeyedUnarchiver` have delegates that are notified during various steps of archiving and unarchiving. They can be used to do anything that the code may wish to do in those stages.

###### Creating an archive

Usual `NSKeyedArchiver` methods for creating an archive are following.
```
archiveRootObject:toFile: (Creates an archive in a file)
archivedDataWithRootObject: (Creates the archive and has it in an NSData)
```

It can however also be done by creating a `NSKeyedArchiver` object and separately sending encoding methods (such as `encodeObject:forKey:`) to all the properties. However in such a case once done, `finishEncoding` method must be called. This method instructs the archiver object to construct the final data stream.

###### Decoding an archive

Usual `NSKeyedUnarchiver` methods for decoding are following.
```
unarchiveObjectWithFile:
unarchiveObjectWithData:
```

It can also be done by creating a `NSKeyedUnarchiver` object and separately decoding various keys in the archive using `decodeObjectForKey:`, etc. methods.

###### Missing Keys, Type Coercion

When decoding, if the requested keyed value does not exist the unarchiver returns a default value based on the return type of the decode method invoked. It can be `0`, `nil`, `0.0`, `NSZeroSize`, etc.<br>

Whether a keyed value exists or not can be checked using `NSKeyedUnarchiver` method `containsValueForKey:`. (However, it is better to just use the default value check wherever possible as this method has some performance constraints.)

`NSKeyedUnarchiver` does do some level of type coercion, i.e. float to double, etc. However, there are some constraints such as some precision being lost when doing double to float. Also, if the encoded value is too large to fit into the coerced decoded type a `NSRangeException` is thrown. And if an invalid coercion is attempted (such as int to float), a `NSInvalidUnarchiveOperationException` is thrown.

###### Root objects and Conditional objects

Root object is the starting point of an object graph. To encode an object graph, `encodeRootObject:` is called and the first object to be encoded is passed to it. This method though simply invokes encodes the object using `encodeWithCoder:`. It is the concrete subclasses’ job to keep track of multiple references.

A conditional object is an object that should be encoded only if it is being encoded unconditionally elsewhere in the object graph. This is done using `encodeConditionalObject:forKey:`. Typically conditional objects are used to encode weak references to objects. However, once again it is the concrete subclasses’ job to keep track of conditional object and to not encode objects unless they are needed.

A coder does not allow conditional objects to be decoded unless all the other objects have been encoded first.
