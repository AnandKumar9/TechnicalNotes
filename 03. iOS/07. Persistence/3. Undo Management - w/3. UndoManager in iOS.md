In iOS, by default an undo operation is triggered by shaking the device. This can be turned off though using the below UIApplication property. It is usually set in an application launch method such as application:didFinishLaunchingWithOptions:.

application.applicationSupportsShakeToEdit = NO;

UIResponder provides an undoManager property which then becomes available to all the objects (which is pretty much every UIView) that inherit from it. When the application (appdelegate?) receives an undo event, UIResponder goes up the the responder chain (starting with the first responder) looking for a responder that returns an NSUndoManager object from undoManager. The first undo manager that is found is used for the undo or redo operation. (Not very clear.)

The undoManager property of UIResponder is readonly, hence in any subclass that inherits from UIResponder it should be redeclared as readwrite and synthesized to be used.
