Registering a new undo operation clears the redo stack.

Undo manager automatically takes care of not registering a new undo operation when the setter is used during an undo. Instead the concerned operation is put in the redo stack.

There is likely no way to check no. of operations in the undo and redo stack at any moment. Just canUndo and canRedo methods be used to check if the stack is empty or not.

Use setLevelsOfUndo: to set no. of items (undo groups) that should be stored in the undo stack.

While setLevelsOfUndo: still works if undo groups are not being created explicitly, groupingLevel obviously does not return a value if undo groups have not been created explicitly.

There appears to be no method which can be used to check if there is an unclosed undo group, before performing an undo (canUndo returns YES if there are any undo operations in the undo stack, it does not check for unclosed undo groups). So undo groups should be closed manually and the code somehow needs to keep track of it.
