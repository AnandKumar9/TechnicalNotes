Regular expressions are used extensively throughout Foundation. While `NSRegularExpression` needs to be used for doing intricate operations (working with matched groups, reporting progress, etc.), a lot of simple things can also be done using various `String` and `NSPredicate` methods.

##### Using String methods -

###### Checking for a regex in a string

The String method `range(of:options:)` can be used to search for a substring that matches the regex satisfied in 1st argument in the receiver string. Its just that the second argument should have the the `.regularExpression` option specified. [link](https://developer.apple.com/documentation/foundation/nsstring/1416849-range)
```
let testString = "For NSSet and NSDictionary, the ..."
let regex = "[A-Z]{3,}[0-z]+"    // Matches anything that looks like a Cocoa type

if let typeRange = testString4.range(of: regex, options: .regularExpression) {
    print("First type: \(testString[typeRange])")     // Prints NSSet
}
```

Note though that this method only returns the range of the first matching substring. It does not report any more matching substrings that may be present.


###### Replacing regex matching patterns in a string

The string method `replacingOccurrences(of:with:options:range:)` can be used to look for occurrences of a substring that complies to the regex specified in argument 1 and replacing them with the string specified in argument 2. In this second argument, $0 can be used to refer to the matched substring and $1, $2, etc. can be used to specify any captured groups.

```
let replacedText = testString4.replacingOccurrences(of: regex, with: "`$0`", options: .regularExpression) // Puts back-tick across matched substring
```

> Make a note that in both the methods the option `.regularExpression` does need to be specified. It belongs to the enum `NSString.CompareOptions` ([link](https://developer.apple.com/documentation/foundation/nsstring/compareoptions)) and it has many more options (`caseInsensitive`, `backwards`, etc.)


In fact simple regex checks can also be done using `NSPredicate`. I think `NSPredicate`'s `MATCHES` clause by default does a regex pattern matching too.

```
let regex1 = "ABC.*"
let result1 = NSPredicate(format: "SELF MATCHES %@", regex1).evaluate(with: "ABCD")
```

##### NSRegularExpression and NSTextCheckingResult -

To do more intricate things `NSRegularExpression` needs to be used.

###### Creating a NSRegularExpression:

The initializer used is `init(pattern:options:)` and its a throwing function. A bunch of options can be passed ([link](https://developer.apple.com/documentation/foundation/nsregularexpression/options)). `caseInsensitive` for instance is nothing but same as `(?i)` modifier of regular expressions. So that modifier need not be specified in the pattern. (I think though that its rather better specified in the pattern.)
```
let pattern = "<a\\s+[^>]*href=\"([^\"]*)\"[^>]*>"
let regexObject = try! NSRegularExpression(pattern: pattern, options: .caseInsensitive)
```

###### Matching a `NSRegularExpression` in a string:

Methods such as `matches(in:options:range:)`, `firstMatch(in:options:range:)` can be used.
The results are given as `NSTextCheckingResult` instances

```
let matches = regexObject5.matches(in: testString,
                                range: NSMakeRange(0, testString.utf16.count))

let result = matches.map { result -> String in
    print(result)
    let hrefRange = result.range(at: 1)
    let start = String.UTF16Index.init(encodedOffset: hrefRange.location)
    let end = String.UTF16Index.init(encodedOffset: hrefRange.location + hrefRange.length)
    return String(testString.utf16[start..<end])!
}
print(result)
```

`NSTextCheckingResult` has various methods, etc. for accessing the matched substring's location. This location/range then needs to be accessed to extract the substring (quite convoluted, but that's how it is.)

`range(at:)` - Gives the range for specified index. Index 0 is always the full match. Subsequent indexes are the capture groups. So 1 may be the 1st captured group, 2 may be the 2nd captured group and so on.
> `NSTextCheckingResult` is in fact also returned by some other things like data detectors.

Also, keep in mind that the `UTF16Index` view is needed to access indexes in String (understand this better, ObjcIO article on regexp does describe a little).

There are similar methods for replacing matched substrings as well. `stringByReplacingMatches(in:options:range:)`, etc.

Then there is a `enumerateMatches(in:options:range:using:)` method too which calls a closure every time a match happens and at any point this traversal can be stopped. Pretty efficient when there is a very long string and you don't necessarily want to scan it fully. There is a good example in NSHipster article.

##### Escape ", don't escape meta-chars like >

While writing patterns in Swift, remember to properly escape any necessary `"`.
Also, know that the regexp metachars need not be escaped in a regexp fashion when put in a Swift string.

A pattern - `<a\s+[^>]*href="([^\"]*)"[^>]*>`
Same pattern when put in a Swift string - `<a\\s+[^>]*href=\"([^\"]*)\"[^>]*>`      (Notice how the first `\` has been escaped.)

Another pattern - `(?<=href=)("https:\/\/.*?")(?=\>)`      (Notice how the metacharacters have been escaped)
Same pattern when put in a Swift string - `let pattern = "(?<=href=)(\"https://.*?\")(?=>)"`  (Notice how regex meta-characters have not been escaped, but `"` has been escaped with `\`)
