NSObject -> UIResponder -> UIApplication

NSObject -> UIResponder -> UIView -> UIWindow, UIControl
NSObject -> UIScreen

UIApplication receives events from the system and dispatches them to the app code for handling. It often works in tandem with the app delegate object, which contains custom code.

AppDelegate is a custom object created at app launch, usually by UIApplicationMain() function. It mainly handles state transitions in the app. It is usually a subclass of UIResponder and if UIApplication does not handle an event, it sends the the event to app delegate for processing.

UIWindow object coordinates the presence of one or more views on screen. Most apps have only one window, which presents content on the main screen. However apps may have additional window for displaying content on an external display. UIWindow object also work with UIApplication object to deliver events to views and view controllers.

An app can have a main storyboard file or a main nib file, but it cannot have both. The main files for them are specified by UIMainStoryboardFile and NSMainNibFile keys respectively. For apps that use nib files, UIApplicationMain() loads the nib file contents into memory but does not install them in app’s window. It must be done programmatically in app delegate.
