Checking for multitasking support -

For apps built for iOS4 and later, whether multi tasking is available in the device or not can be checked through the multitaskingSupported property of UIDevice. For earlier iOS versions, it can just be checked if the property even exists or not through the respondsToSelector method.

Background execution -

Most apps are moved to suspended state soon after entering the background state. Only apps that provide important service to the user are allowed to continue running for a longer length of time. It can be done in 3 ways.

1. Finite length background tasks -

If the app needs to perform a short task, it can request for a little extra time to finish any important task through beginBackgroundTaskWithExpirationHandler: or beginBackgroundTaskWithName:expirationHandler: method. These methods are usually called when the app is still in foreground and subsequently cause their suspension to be delayed by a short time.

Every call to these methods must be balanced by a corresponding call to the endBackgroundTask: method to mark the end of the task.  Each time the start of a task is declared with the beginBackgroundTaskWithExpirationHandler: method, it returns a unique identifier which is then passed while ending the task through endBackgroundTask: method (a sample implementation). Here is another way to implement it -

```
__block UIBackgroundTaskIdentifier backgroundTaskIdentifier = UIBackgroundTaskInvalid;
backgroundTaskIdentifier = [[UIApplication sharedApplication] beginBackgroundTaskWithExpirationHandler:^(){
     if (backgroundTaskIdentifier != UIBackgroundTaskInvalid) {
          [application endBackgroundTask:backgroundTaskIdentifier];
     }
     backgroundTaskIdentifier = UIBackgroundTaskInvalid;
}];
```
And end it yourself as well once the work is done, so that to does not run unnecessarily anymore.

An app can have any number of tasks running at any time.

2. Downloading contents in the background -

NSURLSession (available from iOS7) can be used to start downloads so that the system takes control of the download process even if the app is suspended or terminated. It can even launch the app when the transfer finishes. NSURLSessionConfiguration class is used to configure NSURLSession. If configured to relaunch, app delegate’s application:handleEventsForBackgroundURLSession:completionHandler: method is called. The system may relaunch the app even to handle authentication challenge or other task related events that require the app’s attention.

However it is important to keep in mind that all this works only when the system itself suspends or terminates the app and not when the user force quits the app (apart from when the apps have location background key).

3. Long running background tasks -

For some specific tasks mentioned below, iOS allows apps to be run in background for lot longer durations if they declare their support for these services appropriately in Info.plist.
UIBackgroundModes key should be added and the appropriate tasks must be added as an array. Further some of these keys even allow the system to continue the task itself even if the app is terminated and then wake up the app again when done.

The key names for the tasks are audio, location, voip, newsstand-content, external-accessory, bluetooth-central, bluetooth-peripheral, fetch, remote-notification. (link)

1. Playing audible content or recording audio content (audio)

2. Keeping user informed of the location (navigation apps)

3. Supporting VoIP (voip)

4. Newsstand apps that download new contents (newsstand-content)

This key allows the system to launch the app even if it is not running, so that it can initiate the downloading of new issue. With this key, the system handles the download process itself and continues the download even if the app is suspended or terminated. When the download is completed, the system transfers the file to app sandbox and notifies the app. Even if there is an error in download, the app is woken up to handle it.

5. Apps that respond to external accessories (external-accessory)

This key indicates that the system can wake up the app when an external accessory delivers an update. Upon being woken up the app usually gets 10 seconds to process the data. External accessory can be something like a health monitor. (But if its a bluetooth monitor, then can’t the same also be done with the bluetooth accessories key?).

Such apps are also required to provide an interface that allows the user to start and stop delivery of accessory update events. The interface should then open or close the accessory session as appropriate.

6. Apps that work with or as bluetooth accessories (bluetooth-central, bluetooth-peripheral)

These keys allow Core Bluetooth to wake up the app when any important peripheral or central related event occurs. (Can they also launch the app from terminated state?)

Just as with the external-accessory key, here too the apps are required to provide an interface that allows the user to start and stop delivery of the bluetooth events. The interface should then open or close the session as appropriate.

7. Regular scheduled fetch (fetch)

fetch indicates that the app requires new content from network on a regular basis and the system launches the app in background for a limited time at regular basis, thereby giving it a chance to regularly update its content. The method called when the app is launched is application:performFetchWithCompletionHandler:. It is recommended to do any downloads using NSURLSession.

This background key should be used responsibly as the system may not launch the app if the app has a bad history, such as not initiating any download very often or taking long for downloads.

8. Remote notifications triggered launch (remote-notification)

In remote-notification the app is launched in background or resumed by the system when remote notification arrives. However for this background mode, probably 30 min is provided to complete the task instead of a lesser 5 min or 10 min. This is what is known as ‘background app refresh’.

The push notification payload must include content-available key with its value set to 1. This is probably also termed as silent notification. It is also recommended to use NSURLSession to initiate and manage the download.

Responsible background apps -

An app running in background should take care to do the following while in background-
1. Not make any OpenGL ES calls from the code
2. Any bonjour related services should be cancelled before moving to suspended state
3. Be prepared for connection failures in network based sockets
4. App state should be saved before moving to background
5. Strong references to unneeded objects must be removed before moving to background
6. Use of shared system resources such as address book and calendar should be stopped before entering suspended state
7. Avoid updating windows and views
8. Any external accessory session must be closed (then what is the purpose of that external-accessory background mode?)
9. Any action sheets or alert views displayed on app UI must be removed.
10. Remove sensitive information from views as the system automatically takes a snapshot of app’s main window.
