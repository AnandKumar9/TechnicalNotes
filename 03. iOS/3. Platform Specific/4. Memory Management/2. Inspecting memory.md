#### MemoryLayout<T>

The size, stride and alignment for any type can be found using the generic type `MemoryLayout<T>`. All the values are given in bytes.

`MemoryLayout<Int>.size` - Gives 8, i.e. 8 bytes
`MemoryLayout<Int>.stride` - Gives 8, i.e. 8 bytes
`MemoryLayout<Int>.alignment` - Gives 1, i.e. 1 byte

Similarly there are also methods such as .size(ofValue: T), however I am currently not sure as to what purpose does it serve. The same information is also given by methods such as .size.

MemoryLayout<Int>.size(ofValue: 3) - This too gives 8

`offset(of:)` method can be used to get a type property's byte offset. (Introduced in Swift 4.2 via [SE-0210](https://github.com/apple/swift-evolution/blob/master/proposals/0210-key-path-offset.md)).
```
struct Point {
    var x: Float
    var y: Float
    var z: Float
}

MemoryLayout<Point>.offset(of: \Point.z)
```

#### Size of various types

Int - Gets 8 bytes.
Int8 - Gets only 8 bits, i.e. a byte and hence the max it can store is 127.
Bool - Gets a byte (and not not just a bit, even though a bit alone should be enough for it. This is because usually byte is the basic addressable unit. link)
Float - Gets 4 bytes.
Double - Gets 8 bytes.

struct - The sum of all its instance variable types. Functions do not take any extra space.

struct StructA {
    let count: UInt32
} - Takes 4 bytes (as 32 bits equates to 4 bytes)

struct StructA {
    let count: UInt32
    let flag: Bool
} - Takes 5 bytes (as 32 bits equates to 4 bytes and a Bool takes 1 byte)

struct StructA {
} - Takes 0 bytes (the struct does not have anything. However in case of an empty struct, the stride is still 1 byte.)


Reference types such as class - Needs 8 bytes. That is because they need to be size of an address and addresses are usually 8 bytes long in 64 bit systems (thats why they are called ’64-bit’ systems).

For types such as Int, the max value that can be stored in a type such as Int can be found using <Type>.max (for example Int.max).
