###### JSONSerialization could only convert to or from a JSON object

`JSONSerialization` class that has existed since iOS 6 did not do enough. It can take a JSON object `Data` and convert it into array/dictionary, but not to a custom type straight away. In below example `obj1` is actually an array, nothing more than that.

```
let jsonData1: Data = ... Some Data generated from a JSON String
if let obj1 = try? JSONSerialization.jsonObject(with: jsonData1, options: []) {
```

#### Codable protocol

`Codable` protocol whereas is very powerful. You just need to specify the type as being conformant to that protocol and then `JSONDecoder` class does the rest for convert a JSON Data to custom types.

```
struct UserA: Codable {
    var name: String
    var age: Int
}

if let decodedEntity = try? JSONDecoder().decode([UserA].self, from: jsonData1) {
    print("Person 1 name: \(decodedEntity[0].name), Person 2 age: \(decodedEntity[1].age)")
}
```

The protocol itself is a combination of `Decodable` and `Encodable` protocols.

```
typealias Codable = Decodable & Encodable
```

Further, there are also protocols named `Decoder` and `Encoder`. `JSONDecoder` is a `Decoder` compliant class that provides capabilities for decoding JSON object. Similarly, `JSONEncoder` is a `Encoder` compliant class that can encode types into JSON objects.

#### JSONDecoder
###### keyDecodingStrategy

If the case style is different across json and the variable names in the type, the `JSONDecoder` property `keyDecodingStrategy` can be used to specify how to treat differences in case style.

It is an enum of type `JSONDecoder.KeyDecodingStrategy` whose possible values are `useDefaultKeys` (the default), `convertFromSnakeCase`, `custom(closure)`

```
let json = """
[
    {
        "first_name": "Paul",
        "last_name": "Hudson"
    },
    {
        "first_name": "Andrew",
        "last_name": "Carnegie"
    }
]
"""

struct UserB: Codable {
    var firstName: String
    var lastName: String
}

let decoderSnakeCase = JSONDecoder()
decoderSnakeCase.keyDecodingStrategy = .convertFromSnakeCase
```

###### custom(closure) as keyDecodingStrategy

```
case custom(([CodingKey]) -> CodingKey)
```

`custom(closure)` allows to specify a closure that can be used to provide mapping for every individual key in the json.

During decoding, the closure is called once for each key in the `Decodable` value being decoded. The closure is called along with an array of `CodingKey` instances representing the sequence of keys needed to reach the value being decoded. This may sound convoluted, but that is how it is.

```
{
    "a.value": 1,
    "b": {
        "a.b.value": 2,
        "c": {
            "a.b.c.value": 3
        }
    }
}
"""
```
For above json, the closure will be called 5 times for every key in isolation. Notice how for each iteration a complete chain of parent keys is passed. The eventual key is passed as a `_JSONKey`, but the parent keys are returned as `CodingKeys`
```
[_JSONKey(stringValue: "b", intValue: nil)]
[_JSONKey(stringValue: "a.value", intValue: nil)]
[CodingKeys(stringValue: "b", intValue: nil), _JSONKey(stringValue: "c", intValue: nil)]
[CodingKeys(stringValue: "b", intValue: nil), _JSONKey(stringValue: "a.b.value", intValue: nil)]
[CodingKeys(stringValue: "b", intValue: nil), CodingKeys(stringValue: "c", intValue: nil), _JSONKey(stringValue: "a.b.c.value", intValue: nil)]
````



###### dateDecodingStrategy

The `JSONDecoder` property `dateDecodingStrategy` can be used for specifying how to convert date strings in JSON to `Date` objects. It's possible values are `deferredToDate`, `millisecondsSince1970`, etc. In fact it can also have `.formatted(DateFormatter)` and `.custom(closure)` for converting custom dates.

```
let json = """
[
    {
        "firstName": "Theo",
        "graduationDay": "31-08-2001"
    }
]
"""

let dateFormatter = DateFormatter()
dateFormatter.dateFormat = "dd-MM-yyyy"

let decoder = JSONDecoder()
decoder.dateDecodingStrategy = .formatted(dateFormatter)
```

###### CodingKey

The custom type itself can also have a nested enum called `CodingKeys` which conforms to `CodingKey` protocol and provides the name to use for each.

```
struct UserB: Codable {
    enum CodingKeys: String, CodingKey {
        case firstName = "first_name"
        case lastName = "last_name"
    }

    var firstName: String
    var lastName: String
}
```

> This way a `keyDecodingStrategy` need not be specified.

#### Parsing hierarchical data in a flattened way

Say the JSON has a nested structure, but you want the object to have a flat structure.

```
let json = """
[
{
    "name": {
        "first_name": "Taylor",
        "last_name": "Swift"
    },
    "age": 26
}
]
"""

struct UserC: Codable {
    var firstName: String
    var lastName: String
    var age: Int
}
```

Then we actually need to provide custom implementations for the `Codable` functions `init(from: Decoder)` (actually a `Decodable` function) and `encode(to: Encoder)` (actually a `Encodable` function). This way those custom implementations are invoked for every key instead of the default implementations.

```
init(from decoder: Decoder) throws { ..

func encode(to encoder: Encoder) throws { ..  
```
