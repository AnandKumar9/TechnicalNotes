`#define` directive can have a constant, expression and can also define a macro.

```
#define OVERS 50
#define LIMITED_OVERS 10 + 10
```

A `variadic macro` is one which can have variable no. of arguments. They are declared with ellipsis (three dots) to indicate the argument position from where the no. of arguments can be variable.
```
#define DLog(…)
#define ZAssert(condition, …)
```

All the preprocessor directives in C - [link](http://gcc.gnu.org/onlinedocs/cpp/)

`__OBJC__` - It is a standard pre-defined macro with value 1, when the Objective-C complier is in use. Hence, it can be used to test whether a header is complied by a C complier or an Objective-C compiler.

`#ifdef` -
It is a conditional. The text in it is executed if the conditional succeeds. In the below examples, the macro __OBJC__ is checked if it is defined and if so the included lines are executed.

```
#ifdef __OBJC__
    #import <UIKit/UIKit.h>
    #import <Foundation/Foundation.h>
#endif
```

`#ifndef` - The opposite of #ifdef. It executes if the macros mentioned next to it is not defined. Hence, it is commonly used to execute code which needs to be done only the first time a header file is included. Headers included this way are called once-only headers (http://gcc.gnu.org/onlinedocs/cpp/Once_002dOnly-Headers.html#Once_002dOnly-Headers).

`#undef` - It undoes a previously-made definition.

`__FILE__` - A special variable in GCC which holds the name of the current file as a C string. It is the path from which the preprocessor opened the file and not just the file name which might have been specified along with #include.

`__LINE__` - A special variable in GCC which holds the current line number, as a decimal integer constant.

`__PRETTY_FUNCTION__` - A special variable inGCC which holds the name of the current method as a C string.

`__VA_ARGS__` - Used to access all the arguments (comma-separated?) passed in a variadic macro. A variadic macro is one which can have variable no. of arguments.


`NS_BLOCK_ASSERTIONS` - A special macro which if defined, causes the assertions to be disabled, i.e. if this macro is defined then even if an assertion is encountered the app will not quit.

Configurations which are present by default - Debug, Release (they can be seen in Project Settings -> Info -> Configurations)

Schemes which are present by default - Build, Run .app, Test, Profile, Analyze, Archive. By default, only Profile and Archive schemes have the build configuration as Release. All other schemes have the build configuration as Debug.

If you go to Edit Scheme, the build configuration, debugger, etc. can be changed for various schemes.

There are some handy macros that have been introduced in iOS6. (A nice write-up explaining these macros.)
`NS_ENUM` is a macro which stands for a typedef for an enum. The NS_ENUM macro helps define both the name and type of the enumeration.

```
typedef NS_ENUM(NSInteger, UITableViewCellStyle) {        
     UITableViewCellStyleDefault,
     UITableViewCellStyleValue1,
     UITableViewCellStyleValue2,
     UITableViewCellStyleValueSubtitle
};
```

It is possible to know the target OS of a code by using some of the macros definedinTargetConditionals.h.
`TARGET_OS_IPHONE` indicates the target is iOS, TARGET_OS_MAC indicates the target is Mac OS. However, TARGET_OS_MAC is also defined when building for iOS, hence if any piece of code needs to be included only for Mac OS and the code may also have iOS as target, it is better to check for a target of Mac OS with the condition 'if !TARGET_OS_IPHONE'. There is also a pre-defined macro TARGET_IPHONE_SIMULATOR for iOS Simulator. Hence, !TARGET_IPHONE_SIMULATOR indicates the iOS app is running on mobile device. (Write-up)

To determine whether the app is running on iPhone or iPad, `UI_USER_INTERFACE_IDIOM()` function can be used.

```
if(UI_USER_INTERFACE_IDIOM() == UIUserInterfaceIdiomPad) {
    //iPad
}
elseif(UI_USER_INTERFACE_IDIOM() == UIUserInterfaceIdiomPhone) {
    //iPhone
}

```
