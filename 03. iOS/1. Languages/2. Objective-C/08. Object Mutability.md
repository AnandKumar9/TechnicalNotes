The primary reason Foundation often has mutable and immutable variants of some of its classes is that there is a chance that if an object is not immutable, it can be changed unknowingly from a different thread (this must have been a very real problem) and that for some classes only having mutable copies can have harsh implications on the performance.

Although an immutable object is not supposed to change, it should not always be assumed so. A method may be returning an immutable variant of an actually mutable object and then may later change it. Further, serializing a property list does not preserve the mutability of its objects, but just the general type (array, dictionary, etc.). Hence, while deserializing the previous mutability nature will not be known.

A mutable object such as NSMutableArray can always be created using the alloc init pair of methods. However, a factory method such as below which allows to specify the probable capacity enables more efficient storage.
NSMutableArray *mutableArray = [NSMutableArray arrayWithCapacity:[timeZones count]];


Each immutable class also offers a mutableCopy method which returns a mutable copy of the object.

All classes offers a copy method which returns an immutable copy of the object. However, even though the doc says so actually it may not always be this way. Even a mutable object may be returned if copy is called on a immutable object. (Link) http://stackoverflow.com/questions/7212268/when-does-copy-return-a-mutable-object?rq=1

Besides, many classes themselves give methods for converting between variants. Following are some of them. +arrayWithArray can be used to create NSArray from a NSMutableArray. 

If a method intends to expose an mutable object but does not want it to be changed by others, it should return an immutable copy in such a case (by typecasting on copy message if necessary).

For reasons related to internal implementation, it is not advisable to use isKindOfClass: method to check if a class is of the mutable variant. Instead while using an api, what the api says should be trusted.


Storing mutable objects in collection can cause unpredictable problems. Sometimes they can even become corrupt if a constituent object mutates as this mutation can change the outcome of the hash method.
