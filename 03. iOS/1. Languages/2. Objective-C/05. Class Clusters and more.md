`Class clusters` are a group of a number of private concrete subclasses under a public abstract superclass (even though an object is created in source code for a class cluster NSNumber, actually an object of one of its private concrete subclasses gets created behind the scenes). The grouping of classes in this way simplifies the publicly visible architecture of an object-orieneted framework without reducing its functional richness.

The abstract superclass in a class cluster usually declares methods for creating instances of its private subclasses. The objects though can be considered as of superclass's type in the source code, for convenience.

`NSNumber`, `NSString`, `NSArray`, `NSDictionary`, `NSData` are all examples of class clusters.

There are sometimes multiple public classes that declare the interface for a class cluster. Usually these are the classes which have a mutable-immutable pair, i.e. NSArray and `NSMutableArray`, `NSString` and `NSMutableString`, etc.

`Liskov principle` states that if S is a subtype of T, then objects of T may be replaced with objects of type S. This holds true in Objective-C too. If class B is a subtype of class A, then an object of type B can be assigned to an object declared as being of type A. And probably this is why class clusters work. Objects are ultimately created in one of the subclasses and finally returned as if the object being returned is an instance of the superclass.


##### Subclassing Class clusters

A class cluster does not contain any instance variables in the public abstract superclass. They are actually there only in the private subclass.

Creating a subclass of a class cluster requires some additional things to be taken care of. One of them is that it must override all the primitive methods of the class cluster.

Primitive methods are those methods that directly access an object's instance variables. Essentially, all other methods can provide their implementation using the primitive methods alone. The primitive methods of NSArray are `-count` and `-objectAtIndex:`.
One way to find the primitive methods of a class is to check the reference. However, the public header of the class can also be checked. Usually the primitive methods are present in the `@interface` block, the other methods are present in categories.

There are multiple ways to subclass class cluster.

1. True subclass. Here an appropriate instance variable is declared in the subclass for storage and the primitive methods implemented. It should also be tested that the other methods continue to work without having to override them.

2. Have a composite object, i.e. the subclass itself should have an instance variable of the type class cluster. In this way, the primitive methods can simply have the instance variable methods called in their implementation.

Usually subclassing a class cluster is not even needed, just adding appropriate categories suffice the need.
