[WKNavigationProtocol]() is the protocol that declares methods for accepting or rejecting navigation changes, and for tracking the progress of navigation requests. ([Reference](https://developer.apple.com/documentation/webkit/wknavigationdelegate))

##### Allowing or denying navigation requests

###### Decide before receiving initial response (`decidePolicyForNavigationAction`)

The below two functions are called to get a decision i.e. `WKNavigationActionPolicy` (possible values being allow/deny/download) once some initial interaction has happened but before any content has been loaded. 

>  If the second method is implemented the first method is not called.

`webView(_: WKWebView, decidePolicyFor: WKNavigationAction, decisionHandler: {(WKNavigationActionPolicy)}`

 `webView(_: WKWebView, decidePolicyFor: WKNavigationAction, preferences: WKWebpagePreferences, decisionHandler: {(WKNavigationActionPolicy, WKWebpagePreferences)})`

The `WKNavigationAction` that is received in the argument is something that represents the navigation that is about to occur. It has a property of enum type `WKNavigationType` which has values that indicate whether it is a new link being tapped, back/fwd happening, page refresh, form submission, etc. The navigation action also has information about the source and target frames.

###### Decide after receiving initial response (`decidePolicyForNavigationResponse`)

This is called after some initial response has been received (HTTP headers, etc.) but before any content has been loaded.

`webView(_: WKWebView, decidePolicyFor: WKNavigationResponse, decisionHandler: {(WKNavigationActionPolicy)}`

##### Tracking the load progress of a request

###### Navigation started (`didStart`)

`webView(_: WKWebView, didStartProvisionalNavigation: WKNavigation!)` - Called when the navigation from main frame has started. 

###### Server redirect happens (`didReceiveServerRedirect`)

` webView(_: WKWebView, didReceiveServerRedirectForProvisionalNavigation: WKNavigation!)` - Called when the webpage gets an automatic server redirect to a different URL.

###### Main frame starts to receive content (`didCommit`)

`webView(_: WKWebView, didCommit: WKNavigation!)` - Called immediately before the webview starts updating the main frame. Is called only after  `webView(_:decidePolicyFor:decisionHandler:)` has approved the navigation response.

###### Navigation complete (`didFinish`)

`webView(_:didFinish:)` - Called when the webview has done a navigation, for example when the webview has loaded with a new URL.

##### Responding to authentication challenges (`didReceiveChallenge`)

`webView(_: WKWebView, didReceive: URLAuthenticationChallenge, completionHandler: (URLSession.AuthChallengeDisposition, URLCredential?) -> Void)` - Called when cert information is received, the method can decide whether to continue or not. The certs information is in the second argument, the decision goes in first argument of the completion handler. It should give the decision (`AuthChallengeDisposition`) by passing it as an argument to the received completion handler.

Sample code in its implementation (same as in Cert Pinning example).

```swift
func urlSession(_ session: URLSession, didReceive challenge: URLAuthenticationChallenge, completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void) {
    if let trust = challenge.protectionSpace.serverTrust, SecTrustGetCertificateCount(trust) > 0 {
        if let certificate = SecTrustGetCertificateAtIndex(trust, 0) {
            let data = SecCertificateCopyData(certificate) as Data
            if certificates.contains(data) {
                completionHandler(.useCredential, URLCredential(trust: trust))
                return
            }
        }
    }
    completionHandler(.cancelAuthenticationChallenge, nil)
}
```

###### `URLAuthenticationChallenge`

`URLAuthenticationChallenge` has all the details about the challenge (i.e. cert information) received from the server. It has properties like `protectionSpace` that represent the server that issued the cert. The cert is actually accessible using `challenge.protectionSpace.serverTrust`.

###### Possible values of `AuthChallengeDisposition` 

`useCredential` - Proceed with the credential (`URLCredential`) specified in the second argument of the completion handler. Can simply be the credential retrieved from `challenge.protectionSpace.serverTrust` too.

`performDefaultHandling` - Let the OS peform its own default handling of the received cert.

`cancelAuthenticationChallenge` - Cancel the entire request.

`rejectProtectionSpace` - Reject this challenge, and call the authentication delegate method again with the next authentication protection space. The provided credential parameter is ignored.
