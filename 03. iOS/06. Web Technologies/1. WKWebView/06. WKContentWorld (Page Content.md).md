##### Separating JS injected by app from JS in webpage's code (`WKContentWorld`) 

`WKWebView` has functions such as `evaluateJavaScript` and `callAsyncJavaScript` to inject JS in the webapage. However while doing this namespace conflicts can happen as the webview may not exactly know what variable names are already being used in the rendered JS. This is where `WKContentWorld` helps, it provides an isolated place for the webpage's JS to run separate from the application JS, rather the page's own global object

From reference,

>  `WKContentWorld` can be used as a namespace to separate the app’s web environment from the environment of individual webpages or scripts they execute. Content worlds help prevent issues that occur when two scripts modify environment variables in conflicting ways. Executing a script in its own content world effectively gives it a separate copy of the environment variables to modify.
>
>  Note though that the content world doesn’t apply to the current document or DOM of a webpage. Changes you make to the DOM are visible to all script code, regardless of content world. The content world affects only references to other JavaScript variables.

It's like having your own separate window object for the same page content. There is a page world representing the web content itself, and then there are client worlds representing one or more homes for your application's JavaScript. Your application's JavaScript run in a client world can still do things like call built-in DOM APIs on the page or change the DOM itself, but it will never see the 'application state' set up by the page's JavaScript. Likewise, the page's JavaScript will never see yours.

> Over here a webpage was having scrolling issues because of conflicting JS symbols. The fix is to use the `defaultClient` world for all of the `evaluateJavaScript` calls. <br> <br>![image-20230709183652985](assets/image-20230709183652985.png)

The default content world is accessible using `WKContentWorld.defaultClient`, and a new custom content world can be created using `WKContentWorld(name: "custom-world-name")`. The webpage's content world is accessible using `WKContentWorld.page`, and it should be used only when really necessary (such as when posting a message from the webpage's JS and wanting to intercept that from client code.)
