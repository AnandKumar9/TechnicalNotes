###### Staging area and Git directory
<br>
`Working directory` <br>
`Staging area` <br>
`Git directory` <br>

`Modified` means that you have changed the file but have not committed it to your database yet or not staged it yet.<br>
`Staged` means that you have marked a particular version of a file to go into your next commit snapshot.<br>
`Committed` means that the data is safely stored in your local database.

`Tracked files` are files that were in the last snapshot.

A modified file needs to be added to the staging area once again for its latest changes to be taken in the next commit. Or else, its previous version is taken when a commit is done.

###### Branches

Git keeps track of current branch the user is on through a special pointer called `HEAD`.

> Note that remote serves too have a `HEAD` (which is its default branch), and if something like `git pull [remote_name] HEAD` is done it is referring to the HEAD branch of the remote and not the local.

When a commit is done, it happens on the current branch of git and not on the other branches. 

There should not be any uncommitted changes in the working directory or staging area before switching to a different branch.

A `3 way merge` is when one of the two branches being merged is not a direct ancestor of the other branch being merged. Instead they have a common ancestor.

A `tracking branch` in git is a local branch that is connected to a remote branch. When a push and pull is done on that branch, it automatically pushes and pulls to the remote branch that it is connected with.

###### Tags

Tags are just a way of bookmarking certain commits. They are usually used for commits corresponding to releases or release candidates.

The same tag name cannot be added to multiple commits.

Also, tags are of two types. Lightweight and annotated. Annotated tags also contain some meta information such as author's name, email, custom message, etc.

```
git tag (Get a list of all tags)
git tag 0.0.1 <commit-ref> (Tag any commit)
git tag -a 0.0.2 -m "Message" (Annotated tag)
git tag -d 0.0.2 (Delete the specified tag)
git tag -f v1.4 <commit-ref> (Forcefully use an existing tag name)
```

By default, tags are not pushed to remote. They must either be specified individually or the push should be done with a `--tags` option.
```
git push origin 0.0.1 (Push the tag 0.0.1)
git push origin :refs/tags/12345 (Update the deleted tag 12345 to remote)
git push origin --tags (Push all tags, try)
```

Tags are shown as Releases in Github.

###### Undoing changes (reset, revert)

`git revert` just looks at the specified commit and creates a new commit which undoes those changes. That's it. It does not undo all the changes done in the commits since the specified commit, but just the changes in the specified commit. `no-edit` below means that a custom commit message is not needed. `no-commit` means that the undo changes should only be brought to staging area and not committed automatically.

```
git revert [commit hash] --no-edit
git revert [commit hash] --no-commit
```
